## 一、UDP 协议

<div id="section-2" class="note-anchor"></div>

### 核心特征

| 特性 | 说明 |
|------|------|
| **连接** | 无连接——直接发送，无需握手 |
| **可靠性** | 不可靠——不确认、不重传 |
| **有序性** | 不保证顺序 |
| **首部开销** | **8 字节**（TCP 是 20 字节） |
| **校验和** | 有，但可选（IPv4 中可选，IPv6 中必选） |

<div id="section-3" class="note-anchor"></div>

### UDP 首部格式

```
 0      7 8     15 16    23 24    31
┌────────┬────────┬────────┬────────┐
│  源端口号  │ 目的端口号 │  长度   │ 校验和  │
│ (2字节)  │ (2字节)  │(2字节) │(2字节) │
└────────┴────────┴────────┴────────┘
```

> 共 8 字节。**长度字段** = 首部 + 数据的总字节数。

<div id="section-4" class="note-anchor"></div>

### UDP 伪首部（计算校验和时用）

> **考点**
> UDP 计算校验和时，会加上一个 **12 字节的伪首部**（包含源IP、目的IP、协议号、UDP长度），仅用于校验和计算，不实际传输。

<div id="section-5" class="note-anchor"></div>

### 适用场景

| 场景 | 原因 |
|------|------|
| DNS 查询 | 单次请求-响应，数据量小 |
| 视频直播/语音 | 允许少量丢包，实时性优先 |
| RIP 路由协议 | 周期性广播路由信息 |
| DHCP | 获取IP地址时的广播通信 |

> **记忆口诀**
> UDP = "You Don't need to Prepare" — 不准备，直接发
> TCP = "To Care People" — 操心，各种确认重传

## 二、DNS 域名系统

<div id="section-7" class="note-anchor"></div>

### 基本概念

- **全称**：Domain Name System
- **功能**：域名 ↔ IP 地址 的映射
- **端口**：**53**（UDP 为主，大响应时用 TCP）
- **层次结构**：根域名服务器 → 顶级域名服务器（.com/.cn） → 权威域名服务器 → 本地域名服务器

<div id="section-8" class="note-anchor"></div>

### 两种查询方式

| 方式 | 过程 | 特点 |
|------|------|------|
| **递归查询** | 客户端 → 本地DNS → 根DNS → 顶级DNS → 权威DNS，结果逐级返回 | 被请求方承担全部查询工作 |
| **迭代查询** | 客户端 → 本地DNS，本地DNS依次问根→顶级→权威，每次得到的都是"你去问XXX" | 请求方自己一步步查 |

> **常见考点**
> - 主机向**本地域名服务器**的查询通常是**递归查询**
> - 本地域名服务器向**根域名服务器**的查询通常是**迭代查询**
> - DNS 缓存：每条记录有 TTL（生存时间），过期后重新查询

<div id="section-9" class="note-anchor"></div>

### 域名空间

```
                   根 (.)
         ┌─────────┼─────────┐
        com       cn       org
      ┌──┴──┐   ┌──┴──┐
   baidu   google  edu  gov
```

## 三、HTTP 协议

<div id="section-11" class="note-anchor"></div>

### HTTP 方法

| 方法 | 含义 | 幂等性 |
|:----:|------|:------:|
| **GET** | 获取资源 | ✅ |
| **POST** | 提交数据（创建资源） | ❌ |
| **PUT** | 更新资源（完整替换） | ✅ |
| **DELETE** | 删除资源 | ✅ |
| **HEAD** | 只获取响应头（不返回body） | ✅ |

<div id="section-12" class="note-anchor"></div>

### 常见状态码

| 状态码 | 含义 |
|:------:|------|
| **200** | OK，请求成功 |
| **301** | 永久重定向 |
| **302** | 临时重定向 |
| **304** | Not Modified（缓存有效，使用本地缓存） |
| **400** | Bad Request（请求有语法错误） |
| **403** | Forbidden（拒绝访问） |
| **404** | Not Found（资源不存在） |
| **500** | Internal Server Error（服务器内部错误） |
| **502** | Bad Gateway（网关错误） |
| **503** | Service Unavailable（服务不可用） |

> 记忆：2xx成功，3xx重定向，4xx客户端错，5xx服务器错

<div id="section-13" class="note-anchor"></div>

### HTTP/1.1 vs HTTP/2

| 特性 | HTTP/1.1 | HTTP/2 |
|------|----------|--------|
| 连接复用 | 持久连接（Keep-Alive），但请求串行 | **多路复用**（一个连接并行多个请求） |
| 头部压缩 | 无 | HPACK 压缩 |
| 服务器推送 | 无 | 支持 Server Push |
| 格式 | 文本 | 二进制帧 |

<div id="section-14" class="note-anchor"></div>

### Cookie

- 服务器通过 `Set-Cookie` 响应头设置
- 客户端在后续请求中通过 `Cookie` 请求头带上
- 用于保持 HTTP 无状态协议下的**会话状态**

## 四、路由协议

<div id="section-16" class="note-anchor"></div>

### 分类

| 类型 | 协议 | 算法 | 范围 |
|------|------|------|------|
| **IGP（内部网关协议）** | RIP | 距离向量（Bellman-Ford） | AS 内部 |
| | OSPF | 链路状态（Dijkstra/SPF） | AS 内部 |
| **EGP（外部网关协议）** | BGP | 路径向量 | AS 之间 |

<div id="section-17" class="note-anchor"></div>

### RIP（Routing Information Protocol）

| 特性 | 说明 |
|------|------|
| 度量 | **跳数**（hop count） |
| 最大跳数 | **15**（16 = 不可达） |
| 更新方式 | 周期性广播（每 30s）整个路由表 |
| 协议 | 使用 **UDP**（端口 520） |
| 收敛速度 | **慢**（好消息传得快，坏消息传得慢——计数到无穷） |

<div id="section-18" class="note-anchor"></div>

### OSPF（Open Shortest Path First）

| 特性 | 说明 |
|------|------|
| 度量 | **链路代价**（带宽相关） |
| 算法 | **Dijkstra 最短路径优先** |
| 更新方式 | 仅当拓扑变化时，洪泛 LSA（链路状态通告） |
| 协议 | 直接封装在 **IP** 数据报中（协议号 89） |
| 收敛速度 | **快** |

> **RIP vs OSPF 必背对比**
> | | RIP | OSPF |
> |------|:---:|:---:|
> | 算法 | 距离向量 | 链路状态（Dijkstra） |
> | 度量 | 跳数 | 代价（带宽） |
> | 传谁 | 整个路由表 | 仅链路状态变化 |
> | 给谁传 | 邻居 | 全网路由器（洪泛） |
> | 用什么传 | UDP | IP 直接封装 |
> | 收敛 | 慢 | 快 |

<div id="section-19" class="note-anchor"></div>

### BGP（Border Gateway Protocol）

- 在不同 **AS（自治系统）** 之间交换路由信息
- 使用 **TCP**（端口 179）
- 路径向量协议——携带完整的 AS 路径
- 策略路由：不只是找最短路径，还要考虑商业策略

## 五、TCP 流量控制与拥塞控制

<div id="section-21" class="note-anchor"></div>

### 流量控制：滑动窗口

- **目的**：防止发送方发送太快导致接收方缓冲区溢出
- 接收方通过 TCP 首部的**窗口字段**（window）告知剩余缓冲区大小
- 发送窗口 = min（拥塞窗口, 接收窗口）

<div id="section-22" class="note-anchor"></div>

### 拥塞控制（四个算法）

| 阶段 | 算法 | 机制 |
|------|------|------|
| ① | **慢启动** | cwnd 从 1 开始，每收到一个 ACK，cwnd **指数增长**（×2 每 RTT） |
| ② | **拥塞避免** | 达到 ssthresh 阈值后，cwnd **线性增长**（+1 每 RTT） |
| ③ | **快重传** | 收到 **3 个重复 ACK** 时，立即重传丢失报文（不等超时） |
| ④ | **快恢复** | 快重传后不进入慢启动，而是 ssthresh = cwnd/2，cwnd = ssthresh，然后线性增长 |

> **必背参数**
> - **ssthresh**（慢启动阈值）：cwnd 指数增长的上限
> - **cwnd**（拥塞窗口）：发送方根据网络拥塞状况动态调整
> - 超时 → ssthresh = cwnd/2，cwnd = 1，重新慢启动
> - 3个重复ACK → ssthresh = cwnd/2，cwnd = ssthresh，进入快恢复

<div id="section-23" class="note-anchor"></div>

### TCP 拥塞控制 vs 流量控制

| | 拥塞控制 | 流量控制 |
|------|----------|----------|
| 目的 | 防止网络过载 | 防止接收方溢出 |
| 调节依据 | 网络拥塞状况（丢包、延迟） | 接收方缓冲区剩余空间 |
| 核心变量 | 拥塞窗口 cwnd | 接收窗口 rwnd |

## 六、物理层两个定理

<div id="section-25" class="note-anchor"></div>

### 奈奎斯特定理（无噪声信道）

> 
$$
\text{最大数据率} = 2W \log_2 V \quad \text{(bps)}
$$

> - $W$：信道带宽（Hz）
> - $V$：信号离散等级数（如二进制 V=2）

<div id="section-26" class="note-anchor"></div>

### 香农定理（有噪声信道）

> 
$$
\text{最大数据率} = W \log_2(1 + \frac{S}{N}) \quad \text{(bps)}
$$

> - $S/N$：信噪比（线性值）
> - 常用分贝值：$\text{SNR}_{\text{dB}} = 10 \log_{10}(S/N)$
> - 例如：30dB → $S/N = 1000$

> **联合使用**
> 奈奎斯特给出符号速率上限（码元），香农给出信息速率上限（考虑噪声）。**实际最大速率取两者中较小的**。

## 七、NAT 网络地址转换

<div id="section-28" class="note-anchor"></div>

### 基本概念

- **功能**：将**私有 IP 地址**转换为**公网 IP 地址**
- **目的**：解决 IPv4 地址枯竭问题
- 通常部署在**路由器**上

<div id="section-29" class="note-anchor"></div>

### 私有地址段（必背）

| 类别 | 地址段 | CIDR |
|:----:|------|:----:|
| A | 10.0.0.0 ~ 10.255.255.255 | 10.0.0.0/8 |
| B | 172.16.0.0 ~ 172.31.255.255 | 172.16.0.0/12 |
| C | 192.168.0.0 ~ 192.168.255.255 | 192.168.0.0/16 |

<div id="section-30" class="note-anchor"></div>

### NAT 类型

| 类型 | 说明 |
|------|------|
| **静态 NAT** | 一对一映射（一个私有IP ↔ 一个公网IP） |
| **动态 NAT** | 多对多映射（从公网IP池中分配） |
| **NAPT/PAT** | 多对一映射（多个私有IP 共享一个公网IP，用端口号区分）——最常见 |

## 八、DHCP 动态主机配置协议

<div id="section-32" class="note-anchor"></div>

### 基本概念

- **全称**：Dynamic Host Configuration Protocol
- **功能**：自动给主机分配 IP 地址、子网掩码、默认网关、DNS 服务器
- **端口**：服务端 **67**，客户端 **68**（UDP）
- **临时使用**：0.0.0.0（源地址）→ 255.255.255.255（目的地址）

<div id="section-33" class="note-anchor"></div>

### 四步流程（DORA）

```
客户端                                     DHCP服务器
  │                                           │
  │── DHCP DISCOVER（广播）────────────────→│  ① 发现："谁给我IP？"
  │                                           │
  │←── DHCP OFFER（单播/广播）──────────────│  ② 提供："这个IP给你"
  │                                           │
  │── DHCP REQUEST（广播）─────────────────→│  ③ 请求："我要用这个IP"
  │                                           │
  │←── DHCP ACK（单播/广播）───────────────│  ④ 确认："好的，给你"
  │                                           │
```

> **记忆方法：D-O-R-A（Discover → Offer → Request → ACK）**

<div id="section-34" class="note-anchor"></div>

### 租约

- DHCP 分配的 IP 有**租约期**（lease time）
- 到期前需续租（发送 DHCP REQUEST）
- 50% 租约时尝试续租，87.5% 时广播续租

## 九、IPv6

<div id="section-36" class="note-anchor"></div>

### 与 IPv4 的对比

| 特性 | IPv4 | IPv6 |
|------|------|------|
| 地址长度 | 32 位 | **128 位** |
| 表示方式 | 点分十进制 192.168.1.1 | 冒号十六进制 2001:db8::1 |
| 首部长度 | 可变（20~60 字节） | 固定 **40 字节** |
| 校验和 | 有（首部校验和） | **无**（由上层协议负责） |
| 分片 | 路由器可分片 | **仅源节点可分片** |
| ARP | 有 | 被 ICMPv6 邻居发现替代 |
| NAT | 需要（地址不够） | 原则上不需要（地址充足） |

<div id="section-37" class="note-anchor"></div>

### IPv6 地址简化规则

1. 前导零省略：`00ab` → `ab`
2. 连续的全零段用 `::` 代替（**仅一次**）
3. 例：`2001:0db8:0000:0000:0000:ff00:0042:8329` → `2001:db8::ff00:42:8329`

## 十、网络安全基础

<div id="section-39" class="note-anchor"></div>

### 加密类型

| 类型 | 密钥 | 算法 | 特点 |

## 十一、VLAN 基本概念

- **VLAN**（虚拟局域网）：将一个物理局域网逻辑划分为多个独立的广播域
- 同一 VLAN 内的主机可以**直接通信**（不需要路由器）
- 不同 VLAN 之间的通信需要**路由器**或**三层交换机**
- VLAN 间通过 **802.1Q 标签**（Trunk 链路）识别
- 优点：隔离广播域、提高安全性、灵活管理

## 十二、其他易考概念

| 概念 | 一句话解释 |
|------|-----------|
| **MTU** | 最大传输单元，以太网通常 1500 字节 |
| **MSS** | TCP 最大报文段大小 = MTU - IP 首部 - TCP 首部 |
| **TTL** | IP 首部中的生存时间，每跳减 1，为 0 时丢弃（防循环） |
| **ICMP** | 网际控制报文协议，用于 ping/traceroute |
| **端口号范围** | 知名端口 0~1023，注册端口 1024~49151，动态端口 49152~65535 |
| **常见端口** | HTTP:80, HTTPS:443, DNS:53, SMTP:25, POP3:110, FTP:21/20, SSH:22, Telnet:23, DHCP:67/68 |
| **全双工/半双工** | 全双工=同时收发（交换机），半双工=轮流收发（集线器） |
| **虚电路 vs 数据报** | 虚电路面向连接（类似电话），数据报无连接（类似邮政） |
| **分组交换 vs 电路交换** | 分组交换共享链路（互联网），电路交换独占链路（传统电话） |

> **易混淆概念**
> - **带宽**（bps）vs **吞吐量**（实际传输速率）vs **时延**（发送时延 + 传播时延 + 处理时延 + 排队时延）
> - **冲突域**：Hub 的所有端口在同一冲突域，交换机的每个端口独立冲突域
> - **广播域**：交换机所有端口在同一广播域（默认），路由器的每个接口独立广播域

## 十三、复用技术（FDM / TDM / WDM / CDM）

<div id="section-45" class="note-anchor"></div>

### 四大复用技术

| 复用技术 | 中文 | 原理 | 典型应用 |
|----------|------|------|----------|
| **FDM** | 频分复用 | 不同信号分配**不同频段**，同时传输 | 广播电台、ADSL、有线电视 |
| **TDM** | 时分复用 | 不同信号占用**不同时隙**，轮流使用信道 | 传统电话（T1/E1） |
| **STDM** | 统计时分复用 | TDM 改进版——按需分配时隙，**不固定** | 分组交换 |
| **WDM** | 波分复用 | 光的 FDM——不同波长在同一光纤 | 光纤通信 |
| **CDM/CDMA** | 码分复用 | 不同用户用**不同码片序列**，同时同频传输 | 3G 移动通信 |

<div id="section-46" class="note-anchor"></div>

### TDM vs STDM

| | TDM | STDM |
|------|------|------|
| 时隙 | **固定分配** | **按需分配** |
| 空闲时隙 | 浪费 | 分配给其他用户 |
| 效率 | 低（有空闲） | 高 |

> **CDM 核心**
> - 每个站分配唯一**码片序列**（chip sequence）
> - 不同码片**正交**（互不干扰）
> - **扩频**：1 bit → m bit 码片，带宽扩展 m 倍

## 十四、电路交换 vs 报文交换 vs 分组交换

<div id="section-48" class="note-anchor"></div>

### 三种交换方式

| 特性 | 电路交换 | 报文交换 | 分组交换 |
|------|:------:|:------:|:------:|
| **连接建立** | 需要 | 不需要 | 不需要 |
| **传输单位** | 比特流 | 整个报文 | 分组（包） |
| **存储转发** | ❌ | ✅ | ✅ |
| **每跳时延** | 忽略（直通） | 收完整个报文 | 收完一个分组 |
| **资源分配** | 独占（静） | 共享 | 共享 |
| **典型例子** | 传统电话 | 电报 | 互联网 |

<div id="section-49" class="note-anchor"></div>

### 关键对比

```
电路交换：A ──────→ B  独占链路，传完才释放
报文交换：A → R1 (存) → R2 (存) → B  整个消息逐跳传
分组交换：A → R1 (分包) → R2 (分包) → B  拆成小包流水线
```

> **必考点**
> - 电路交换适合**实时/连续**流量（如语音），分组交换适合**突发**流量（如上网）
> - **虚电路** = 分组交换 + 面向连接（结合两者优点，如 ATM/FR）
> - 分组交换的**存储转发**使总时延 = $n \times$ 发送时延（不是 1 次）

<div id="section-50" class="note-anchor"></div>

### 虚电路 vs 数据报

| | 虚电路（面向连接） | 数据报（无连接） |
|------|:------:|:------:|
| 连接建立 | 需要 | 不需要 |
| 路由决定 | 建立时一次性决定 | 每个包独立决定 |
| 顺序 | 保证有序 | 可能乱序 |
| 协议 | X.25, ATM, FR | IP |

## 十五、TCP 首部字段详解

> **高频考点：TCP 首部共 20~60 字节，固定部分 20 字节。**

```
 0      3 4      7 8     15 16    23 24    31
┌────────┬────────┬────────┬────────┐
│    源端口号 (2B)     │   目的端口号 (2B)    │
├────────┴────────┼────────┴────────┤
│           序号 (Sequence Number, 4B)      │
├─────────────────┼─────────────────┤
│         确认号 (Acknowledgment, 4B)       │
├──┬──┬──┬──┬──┬──┼──┬──┬──┬──┬──┬──┤
│DO│Re│U│A│P│R│S│F│   窗口大小 (2B)    │
│  │  │R│C│S│S│Y│I│                    │
│  │  │G│K│H│T│N│N│                    │
├──┴──┴──┴──┴──┴──┴──┴──┴──┴──┴──┴──┤
│    校验和 (2B)      │   紧急指针 (2B)    │
└─────────────────────┴────────────────────┘
```

<div id="section-52" class="note-anchor"></div>

### 标志位（6 位，必背）

| 标志 | 全称 | 含义 |
|:----:|------|------|
| **URG** | Urgent | =1 时紧急指针有效 |
| **ACK** | Acknowledgment | =1 时确认号有效（建连后始终为 1） |
| **PSH** | Push | =1 时立即交付应用层，不缓存 |
| **RST** | Reset | =1 时强制复位连接 |
| **SYN** | Synchronize | =1 时请求建立连接 |
| **FIN** | Finish | =1 时请求释放连接 |

> 记忆：URGent ACKnowledge Push ReSeT SYN FIN

<div id="section-53" class="note-anchor"></div>

### 关键字段

| 字段 | 大小 | 说明 |
|------|:---:|------|
| 数据偏移 (DO) | 4 bit | TCP 首部长度（以 4 字节为单位），最小 5（20B） |
| 窗口大小 | 2B | 接收方剩余**接收缓冲区**大小（流量控制） |
| 校验和 | 2B | 加 TCP 伪首部后计算 |
| 紧急指针 | 2B | 仅在 URG=1 时有效 |
| 选项 | 可变 | MSS、窗口扩大因子、时间戳等 |

> **常见考点**
> - TCP 首部**最小 20 字节** vs UDP 首部 **8 字节** vs IP 首部**最小 20 字节**
> - 伪首部（12B）用于计算校验和：源IP(4) + 目的IP(4) + 0 + 协议号(1) + TCP/UDP长度(2)

> | TCP | 6 |

## 十七、TCP 状态转换图

> 11 种状态：选择填空中常考状态名称和转换条件。

```
客户端状态:                          服务器状态:
                                     LISTEN (监听)
     CLOSED                              │
       │ SYN=1, seq=x                    │
       ▼                                 ▼
    SYN_SENT ──────────────────────→ SYN_RCVD
       │   ←── SYN=1, ACK=1 ──────    │
       │         seq=y, ack=x+1         │
       │ ACK=1, ack=y+1                 │
       ▼                                 ▼
    ESTABLISHED ←────────────────── ESTABLISHED
       │            (数据传输)            │
       │ FIN=1                           │
       ▼                                 ▼
   FIN_WAIT_1 ────────────────────── CLOSE_WAIT
       │   ←── ACK ────────────────    │
       ▼                               │ FIN=1
   FIN_WAIT_2                         ▼
       │   ←── FIN ──────────────── LAST_ACK
       │ ACK                              │
       ▼                                 ▼
   TIME_WAIT ──────────────────────── CLOSED
   (等 2MSL)
       ▼
     CLOSED
```

<div id="section-57" class="note-anchor"></div>

### 全部 11 个状态

| 状态 | 含义 | 谁 |
|------|------|:--:|
| **CLOSED** | 连接未建立 | 双方 |
| **LISTEN** | 服务器等待连接请求 | 服务端 |
| **SYN_SENT** | 发送 SYN 后等待 SYN+ACK | 客户端 |
| **SYN_RCVD** | 收到 SYN 后发送 SYN+ACK，等待 ACK | 服务端 |
| **ESTABLISHED** | 连接建立，传数据 | 双方 |
| **FIN_WAIT_1** | 主动关闭方发送 FIN 后 | 主动方 |
| **FIN_WAIT_2** | 收到 ACK，等待对方 FIN | 主动方 |
| **CLOSE_WAIT** | 收到 FIN，发送 ACK，等待应用层关闭 | 被动方 |
| **LAST_ACK** | 被动方发送 FIN，等待 ACK | 被动方 |
| **TIME_WAIT** | 发送最后 ACK 后等 **2MSL** | 主动方 |
| **CLOSING** | 双方同时关闭（少见） | 双方 |

> **必背**
> - 主动关闭方经过：FIN_WAIT_1 → FIN_WAIT_2 → TIME_WAIT → CLOSED
> - 被动关闭方经过：CLOSE_WAIT → LAST_ACK → CLOSED
> - TIME_WAIT = **2MSL**（最长报文段寿命 × 2，通常 2×2min = 4min）

## 十九、ICMP 协议

<div id="section-62" class="note-anchor"></div>

### 基本概念

- **全称**：Internet Control Message Protocol（网际控制报文协议）
- **封装**：直接封装在 IP 数据报中（协议号 = 1）
- **功能**：报告网络层差错 + 测试网络连通性
- **不是**：ICMP 不纠正错误，只报告

<div id="section-63" class="note-anchor"></div>

### ICMP 消息类型（必背）

| 类型 | 含义 | 触发场景 |
|:----:|------|------|
| **0** | Echo Reply（回显应答） | ping 的回复 |
| **3** | Destination Unreachable | 目的不可达（含细分码：网络/主机/协议/端口不可达） |
| **5** | Redirect | 重定向（有更优路由） |
| **8** | Echo Request（回显请求） | ping 的请求 |
| **11** | Time Exceeded | TTL 超时（traceroute 依赖此报文） |

<div id="section-64" class="note-anchor"></div>

### 两个重要应用

| 工具 | 原理 |
|------|------|
| **ping** | 发 ICMP Echo Request (type 8) → 收到 Echo Reply (type 0) → 算 RTT |
| **traceroute** | 逐跳增加 TTL=1,2,3...→ 每跳返回 ICMP Time Exceeded (type 11) → 逐跳发现路径 |

> **traceroute 原理**
> 源发 UDP 包，TTL 从 1 递增。中间路由器 TTL=0 返回 ICMP type 11。到达目的后返回 ICMP type 3（端口不可达，因为 UDP 用了不可达端口）。

## 二十、PPP 协议 & 透明传输

<div id="section-66" class="note-anchor"></div>

### PPP（Point-to-Point Protocol）—— 数据链路层

| 特性 | 说明 |
|------|------|
| **组成** | ① 封装成帧 ② LCP（链路控制） ③ NCP（网络控制，支持多种网络层协议） |
| **帧定界** | 标志字段 `01111110` (0x7E) |
| **协议** | LCP = 0xC021, NCP(IPCP) = 0x8021, IP = 0x0021 |

<div id="section-67" class="note-anchor"></div>

### 透明传输（超高频考点）

> **问题**：数据中出现了和帧定界符 `01111110` 相同的比特串怎么办？

**字节填充（异步/面向字符传输）**：
- 转义字符 = `0x7D`
- 出现 `0x7E` → 替换为 `0x7D 0x5E`
- 出现 `0x7D` → 替换为 `0x7D 0x5D`
- ASCII 控制字符（<0x20）→ 加 `0x7D` 前缀 + 变换

**比特填充 / 零比特填充（同步/面向比特传输）**：
> 发送方：在**连续 5 个 1 后插入一个 0**（标志字段 `01111110` 除外）
> 接收方：收到 `011111` 后看下一位：是 `0` 则删除（填充位），是 `10` 则是帧结束标志

> **例题**：原始数据 `0110111111111100`，比特填充后是什么？

**解答**：在连续 5 个 1 后插 0：
- `0110111111` → 5个1后插入0 → `01101111101`
- 接着 `111100` → 又一个5个1 → `1111010`
- 结果：`01101111101_1110100`

> **记忆**
> - 字节填充：异步传输（8位为单位），PPP+MODEM
> - 比特填充：同步传输（HDLC/PPP），5连1插0

## 二十一、CSMA/CA 与 Wi-Fi（802.11）

> CSMA/CD 用于**有线以太网**（检测冲突），CSMA/CA 用于**无线局域网**（避免冲突——因为无线很难检测冲突）。

<div id="section-69" class="note-anchor"></div>

### CSMA/CA vs CSMA/CD

| | CSMA/CD | CSMA/CA |
|------|:------:|:------:|
| 网络类型 | 有线以太网 | 无线 802.11 |
| 策略 | 检测冲突（Collision Detection） | 避免冲突（Collision Avoidance） |
| 能否同时收发 | ✅ 全双工 | ❌ 半双工（无法同时收发） |
| 遇到冲突 | 停止 + 退避 | 发送前先等 + 随机退避 |

<div id="section-70" class="note-anchor"></div>

### 为什么无线不能用 CSMA/CD？

1. **隐藏终端问题**：A 和 B 都能听到 AP，但 A 和 C 互相听不到 → 同时发 → 冲突
2. 无线信号衰减快，接收端信噪比低，无法边发边检测
3. 发送功率远大于接收灵敏度 → 发送时无法听到其他信号

<div id="section-71" class="note-anchor"></div>

### CSMA/CA 核心机制（四个步骤）

```
① 先听后发：空闲且持续 DIFS（分布式帧间间隔）→ 发送
② 否则退避：随机选取退避计数器，信道空闲则递减，忙则冻结
③ 接收确认：收到 ACK → 成功；没收到 → 重传（退避窗口加倍）
④ RTS/CTS（可选）：请求发送 / 允许发送（解决隐藏终端）
```

<div id="section-72" class="note-anchor"></div>

### 隐藏终端 与 RTS/CTS

```
        隐藏终端问题          RTS/CTS 解决
       A       C                A → AP：RTS（我要发）
        ↘     ↙                 AP → 所有人：CTS（让A发，其他静默）
          AP                    A → AP：DATA
                                AP → A：ACK
  (A和C互相听不到，同时发给AP→冲突)
```

> **必背概念**
> - CSMA/CD：有线，检测冲突，"边说边听"
> - CSMA/CA：无线，避免冲突，"先预约再发"（RTS/CTS）
> - DCF（分布式协调）→ CSMA/CA；PCF（点协调）→ 轮询

## 二十四、Go-Back-N vs Selective Repeat

> 属于数据链路层和传输层的滑动窗口协议对比（填空中常考区别）。

| 特性 | GBN（回退N帧） | SR（选择重传） |
|------|:------:|:------:|
| 接收窗口 | **1**（只能顺序接收） | **>1**（可缓存乱序帧） |
| 出错行为 | 丢弃该帧及之后所有帧 | **仅丢弃出错帧** |
| 重传 | 从丢失序号开始重传**所有** | **仅重传出错帧** |
| 发送窗口大小 | ≤ $2^n - 1$ | ≤ $2^{n-1}$ |
| 缓存 | 发送方需缓存 | 收发双方都需缓存 |
| 实现复杂度 | 简单 | 复杂 |
| 适合场景 | 差错率低 | 差错率高/大 BDP |

> **窗口大小限制是高频考点**
> - 用 $n$ 位序号 → GBN 窗口最大 $2^n - 1$，SR 窗口最大 $2^{n-1}$
> - 例：n=3 位序号 → GBN 窗口 ≤ 7, SR 窗口 ≤ 4

## 二十五、其他易混概念速记
