## 一、考点概述

TCP是传输层最重要的协议。必考：**三次握手建立连接**、**四次挥手释放连接**。考察形式：简答 / 画时序图 / 分析某一步的意义。

## 二、TCP vs UDP

| 特性 | TCP | UDP |
|------|:---:|:---:|
| **连接** | 面向连接（需建立连接） | 无连接 |
| **可靠** | 可靠（确认、重传） | 不可靠（尽力而为） |
| **顺序** | 保证有序 | 不保证 |
| **开销** | 大（20字节首部） | 小（8字节首部） |
| **适用场景** | HTTP、FTP、邮件 | DNS、视频直播、语音 |

## 三、三次握手（建立连接）🌟

<div id="section-4" class="note-anchor"></div>

### 时序图

```
客户端                                   服务器
  │                                        │
  │──── SYN=1, seq=x ────────────────────→│  ① 客户端请求建立连接
  │                                        │
  │←── SYN=1, ACK=1, seq=y, ack=x+1 ────│  ② 服务器确认 + 请求
  │                                        │
  │──── ACK=1, seq=x+1, ack=y+1 ────────→│  ③ 客户端确认
  │                                        │
  │         连接建立，开始传数据             │
```

<div id="section-5" class="note-anchor"></div>

### 每一步的意义

| 步骤 | 方向 | 标志位 | 作用 |
|:----:|------|--------|------|
| **第一次** | C → S | SYN=1 | 客户端请求建立连接，发送初始序号 x |
| **第二次** | S → C | SYN=1, ACK=1 | 服务器同意连接 + 确认收到请求（ack=x+1），发送自己的初始序号 y |
| **第三次** | C → S | ACK=1 | 客户端确认收到服务器的同意（防止已失效的连接请求到达服务器） |

> **为什么是三次而不是两次？**
> 防止**已失效的连接请求报文**突然到达服务器，导致服务器误开连接浪费资源。
> 
> 如果只有两次握手：客户端发了一个旧SYN后掉线，服务器收到后回复SYN+ACK并分配资源——但客户端不会用这个连接。三次握手让客户端必须再确认一次。

## 四、四次挥手（释放连接）

<div id="section-7" class="note-anchor"></div>

### 时序图

```
客户端                                   服务器
  │                                        │
  │──── FIN=1, seq=u ──────────────────→│  ① 客户端："我说完了"
  │                                        │
  │←── ACK=1, seq=v, ack=u+1 ────────│  ② 服务器："知道了"
  │                                        │
  │      （服务器可能还在发剩余数据）        │
  │                                        │
  │←── FIN=1, ACK=1, seq=w, ack=u+1 ──│  ③ 服务器："我也说完了"
  │                                        │
  │──── ACK=1, seq=u+1, ack=w+1 ──────→│  ④ 客户端："知道了"
  │                                        │
  │  客户端等待 2MSL 后关闭                 │  服务器收到ACK后立即关闭
```

<div id="section-8" class="note-anchor"></div>

### 每一步的意义

| 步骤 | 方向 | 作用 |
|:----:|------|------|
| **第一次** | C → S (FIN) | 客户端关闭数据发送方向 |
| **第二次** | S → C (ACK) | 服务器确认收到，但可能还有数据要发 |
| **第三次** | S → C (FIN) | 服务器数据发完了，关闭发送方向 |
| **第四次** | C → S (ACK) | 客户端确认收到，进入 TIME-WAIT |

> **为什么是四次不是三次？**
> TCP是全双工的，每个方向需单独关闭。第二次挥手的ACK和第三次挥手的FIN**不能合并**，因为服务器收到FIN后可能还有数据没发完。

<div id="section-9" class="note-anchor"></div>

### TIME-WAIT 状态

- 客户端发完第四次挥手 ACK 后，**等待 2MSL**（Maximum Segment Lifetime，最长报文段寿命）才彻底关闭
- **目的**：确保最后的 ACK 能被服务器收到（若丢失，服务器会重发 FIN）

## 五、同类练习题

> **题目**：简述TCP第三次握手的作用。如果不进行第三次握手会有什么问题？

**解析**：
- **第三次握手的作用**：客户端对服务器的SYN进行确认，防止已失效的连接请求到达服务器导致服务器单方面建立连接
- **没有第三次握手的后果**：假设客户端发出的第一个SYN在网络中滞留很久，客户端已放弃该连接。该SYN后来到达服务器，服务器回复SYN+ACK并分配资源——但因没有第三次握手确认，服务器无法知道客户端已不需要这个连接，**资源被白白占用**

---

> **记忆口诀**
> - **三次握手**：SYN → SYN+ACK → ACK（"请求→确认请求→确认确认"）
> - **四次挥手**：FIN → ACK → FIN → ACK（"我关了→知道了→我也关了→知道了"）
> - 建立连接3次，释放连接4次（因为全双工，两个方向分别关）
