## 一、操作系统概述

<div id="section-2" class="note-anchor"></div>

### 操作系统定义

- 控制和管理计算机硬件与软件资源的**系统软件**
- 是用户与计算机硬件之间的**接口**
- 从用户角度看是**虚拟机**，从管理角度看是**资源管理者**

<div id="section-3" class="note-anchor"></div>

### 四大特征

| 特征 | 含义 |
| --- | --- |
| **并发** | 多个程序在同一时间间隔内（宏观同时、微观交替）运行 |
| **共享** | 多个进程共享系统资源（互斥共享 / 同时共享） |
| **虚拟** | 一个物理实体映射为多个逻辑实体（虚拟CPU、虚拟内存） |
| **异步性** | 进程以不可预知的速度向前推进 |

> ⭐ **并发和共享**是操作系统最基本的两个特征，**两者互为存在条件**。
> 
> 历年填空题原题！必背！

<div id="section-4" class="note-anchor"></div>

### 并发 vs 并行

|  | 并发 | 并行 |
| --- | --- | --- |
| 含义 | 多个事件在同一**时间间隔**内发生 | 多个事件在同一**时刻**发生 |
| 实现 | 单 CPU 上交替执行 | 多 CPU 上同时执行 |

> ⭐ 判断题高频：并发和并行是完全相同的概念（×）

<div id="section-5" class="note-anchor"></div>

### 操作系统五大管理功能

1. 进程管理
2. 存储管理
3. 设备管理
4. 文件管理
5. 作业管理（用户接口）

> 不属于五大管理功能的是"**网络管理**"。选择题考过。

<div id="section-6" class="note-anchor"></div>

### 操作系统分类

| 类型 | 主要目标 | 特点 |
| --- | --- | --- |
| **批处理系统** | 提高吞吐量 | 无交互，一批处理 |
| **分时系统** | 缩短响应时间 | 交互性，时间片轮转 |
| **实时系统** | 响应及时性 + 可靠性 | 必须在截止时间前完成 |
| **嵌入式系统** | 实时性 + 可靠性 | 资源受限，专用 |

> 选择题：分时系统最重要指标是**响应时间**；实时系统是**可靠性和实时性**。

<div id="section-7" class="note-anchor"></div>

### 单道 vs 多道

- **单道程序系统**：内存只有一道程序，CPU 在 I/O 时空闲 → CPU 利用率低
- **多道程序设计**：内存可同时放多道程序，宏观并行微观串行，提高资源利用率

> 多道程序设计让多个进程**并发**运行，不是**同一时刻同时**使用 CPU。（判断题：×）

<div id="section-8" class="note-anchor"></div>

### 原语

- 不可中断执行的原子操作
- 特点：**不可分割性**（原子性）
- 例如 P/V 操作原语

<div id="section-9" class="note-anchor"></div>

### 内核态 vs 用户态

- 区分目的：**提高 OS 安全性**（不是提高运行速度）
- 用户程序在**用户态**运行，不能在内核态运行
- OS 内核在**核心态**运行

## 二、进程管理

<div id="section-11" class="note-anchor"></div>

### 进程定义

- 进程 = **程序的一次执行**
- 是系统进行**资源分配**和**调度**的一个独立单位
- 组成 = 程序段 + 数据段 + **PCB**

<div id="section-12" class="note-anchor"></div>

### 进程 vs 程序

|  | 进程 | 程序 |
| --- | --- | --- |
| 本质 | **动态** | **静态** |
| 生命周期 | 有创建、撤销 | 永久存储 |
| 并发 | 有 | 无 |
| 对应关系 | 一对多（一个程序可对应多个进程） | |
| 存在位置 | 内存 | 外存 |

<div id="section-13" class="note-anchor"></div>

### 进程五大特征

动态性、**并发性**、独立性、**异步性**、结构性

<div id="section-14" class="note-anchor"></div>

### PCB（进程控制块）

- 进程存在的**唯一标志**
- 创建进程 = 申请空白 PCB
- PCB 包含：
  - 进程标识符（PID）
  - **处理机状态信息**（程序计数器、寄存器）→ 进程调度用
  - 进程调度信息（状态、优先级）
  - 进程控制信息

<div id="section-15" class="note-anchor"></div>

### 进程三态转换

<div id="section-16" class="note-anchor"></div>

## 进程五状态转换图

| 起始状态 | 触发条件 | 目标状态 |
| --- | --- | --- |
| 创建 | 创建进程 | 就绪 |
| 就绪 | 调度 | 运行 |
| 运行 | 时间片到 | 就绪 |
| 运行 | 等待事件，如 I/O 请求 | 阻塞 |
| 阻塞 | I/O 结束或等待的事件发生 | 就绪 |
| 运行 | 进程结束 | 终止 |
P(S):  S = S - 1;  if (S < 0) 阻塞
V(S):  S = S + 1;  if (S <= 0) 唤醒一个等待进程

- **P 操作** = 申请资源（信号量减 1）
- **V 操作** = 释放资源（信号量加 1）

> P/V 操作是**低级进程通信原语**，必须成对出现，但不能被中断。

<div id="section-17" class="note-anchor"></div>

#### 信号量的值与含义

| S 的值 | 含义 |
| --- | --- |
| S > 0 | 可用资源数 = S |
| S = 0 | 无可用资源，无等待进程 |
| S < 0 | 无可用资源，等待进程数 = |S| |

> ⭐ 信号量的值**可以为负数**！判断题"信号量的值只能 ≥ 0"是**错误**的。

<div id="section-18" class="note-anchor"></div>

#### 信号量取值范围

**公式**：互斥信号量初值为 K，n 个进程竞争 → S ∈ **[K−n, K]**

例：初值 3，5 个进程 → S ∈ [−2, 3]

**等待队列最多几个进程？** = |最小值| = n − K

<div id="section-19" class="note-anchor"></div>

#### 互斥信号量 vs 同步信号量

| 类型 | 初值 | 作用 |
| --- | --- | --- |
| 互斥信号量 | 1（或 N） | 控制访问临界区 |
| 同步信号量 | 0 | 控制执行顺序 |

## 四、死锁

<div id="section-21" class="note-anchor"></div>

### 死锁产生原因

- 资源竞争 + **进程推进顺序非法**
- 根本原因：资源不足 + 请求和释放的顺序不当

<div id="section-22" class="note-anchor"></div>

### 死锁四个必要条件

| 条件 | 含义 | 破坏方法 |
| --- | --- | --- |
| **互斥条件** | 资源只能互斥使用 | 不可破坏（硬件决定） |
| **请求与保持** | 已持有资源的进程再请求新资源 | 一次性分配所有资源 |
| **不可剥夺** | 已分配的资源不能被强行夺走 | 可强行剥夺资源 |
| **环路等待** | 存在进程-资源的循环等待链 | **资源有序分配**（按编号申请） |

> ⭐ "一个进程占有资源后不主动释放"指的是**请求与保持**条件（不是不可剥夺！注意区分）

<div id="section-23" class="note-anchor"></div>

### 死锁处理四种方法

| 方法 | 时机 | 手段 |
| --- | --- | --- |
| **预防** | 死锁发生前 | 破坏四个必要条件之一 |
| **避免** | 死锁发生前 | **银行家算法**（动态判断） |
| **检测** | 死锁发生后 | 资源分配图 |
| **解除** | 死锁发生后 | 撤销进程（最简单）、剥夺资源、回退 |

<div id="section-24" class="note-anchor"></div>

### 银行家算法要点

- 属于**避免**死锁（不是预防，不是检测）
- **不能百分百杜绝死锁**，只能避免进入不安全状态
- 安全状态 → 一定无死锁；不安全状态 → **不一定**有死锁
- 安全序列：存在一种执行顺序使所有进程都能完成

<div id="section-25" class="note-anchor"></div>

### 死锁与资源数量计算

**公式**：n 个进程，每个最多需要 m 个同类资源，不发生死锁的最小资源数：


$$
总资源数 \geq n \times (m-1) + 1
$$


**反之**：系统有 R 个资源，每个进程最多需要 m 个，最多允许多少进程不发生死锁？


$$
n \leq \frac{R-1}{m-1}
$$


> 例：11 台打印机，每个进程要 3 台，最多 5 个进程不会死锁（(11-1)/(3-1) = 5）

## 五、进程调度

<div id="section-27" class="note-anchor"></div>

### 调度算法总结

| 算法 | 抢占？ | 特点 | 适合场景 |
| --- | --- | --- | --- |
| **FCFS** | 非抢占 | 简单，对短作业不利 | 批处理 |
| **SJF / SPF** | 可抢占 | 平均等待最短，长作业可能饥饿 | 批处理 |
| **优先级** | 可抢占 | 紧迫作业优先 | 实时系统 |
| **高响应比** | 非抢占 | 兼顾长短，**不会饥饿** | 批处理 |
| **时间片轮转** | 抢占 | 公平，响应快 | **分时系统** |
| **多级队列** | 抢占 | 多种策略结合 | 通用 |

<div id="section-28" class="note-anchor"></div>

### 高响应比公式


$$
响应比 = \frac{等待时间 + 要求服务时间}{要求服务时间} = 1 + \frac{等待时间}{要求服务时间}
$$


<div id="section-29" class="note-anchor"></div>

### 调度算法选择题考点

- 时间片过大 → 退化为 **FCFS**，响应时间变长
- 可抢占调度方式：FCFS **不能**抢占
- 最适合分时系统：**时间片轮转**
- 兼顾长短作业、避免饥饿：**高响应比优先**
- 抢占式优先级调度，当前运行进程总是优先级最高的

<div id="section-30" class="note-anchor"></div>

### 进程调度 vs 作业调度

|  | 进程调度 | 作业调度 |
| --- | --- | --- |
| 频率 | 高 | 低 |
| 作用 | 从就绪队列选进程上 CPU | 从外存选作业进内存 |
| 又称 | 低级调度 | 高级调度 |

## 六、存储管理

<div id="section-32" class="note-anchor"></div>

### 地址概念

| 术语 | 含义 |
| --- | --- |
| **逻辑地址** | 程序员看到的地址（相对地址） |
| **物理地址** | 内存中的实际地址（绝对地址） |
| **地址重定位** | 逻辑地址→物理地址的转换 |

<div id="section-33" class="note-anchor"></div>

### 重定位类型

| 类型 | 时机 | 特点 |
| --- | --- | --- |
| **静态重定位** | 程序装入时 | 装入后不能移动 |
| **动态重定位** | 程序运行时 | 可在内存中移动（支持紧凑） |

<div id="section-34" class="note-anchor"></div>

### 连续分配方式

| 方式 | 内零头 | 外零头 |
| --- | --- | --- |
| 单一连续分配 | 有 | 无 |
| 固定分区 | **有** | 无 |
| 动态分区 | 无 | **有** |
| 分页 | **有**（最后一页） | 无 |
| 分段 | 无 | **有** |
| 段页式 | 有 | 无 |

> ⭐ 简答题高频："内零头"和"外零头"各指什么，各存在于哪种管理方式？

<div id="section-35" class="note-anchor"></div>

### 可变分区分配算法

| 算法 | 规则 | 缺点 |
| --- | --- | --- |
| **首次适应** | 第一个够用的分区 | 低地址小碎片多 |
| **循环首次适应** | 从上次位置开始找 | 大分区被分割 |
| **最佳适应** | 大小最匹配的分区 | 碎片多，查找慢 |
| **最差适应** | 最大的分区 | 大作业不利 |

> ⭐ 有利于大作业的是**最差适应**。首次适应低地址小碎片多。

<div id="section-36" class="note-anchor"></div>

### 紧凑技术

目的：合并空闲分区（需要**动态重定位**支持）

<div id="section-37" class="note-anchor"></div>

### 分页存储管理

- 逻辑地址 = **页号** + **页内偏移**
- 页面大小固定（常为 4KB，页内偏移 12 bit）
- **页表**：页号 → 物理块号的映射
- 每个进程**一张页表**，运行进程页表驻留内存
- 分页系统必须设置页表实现**逻辑页号到物理块号**的映射（或逻辑地址→物理地址）

<div id="section-38" class="note-anchor"></div>

#### 地址位数关系

- 页面大小 P：P = $2^{页内偏移位数}$
- 页号位数 + 页内偏移位数 = 逻辑地址位数
- 物理块号位数 + 页内偏移位数 = 物理地址位数

例：逻辑地址 16 位，页内偏移 10 位 → 一页 $2^{10}=1024$B，最多 $2^6=64$ 页

<div id="section-39" class="note-anchor"></div>

### 分段存储管理

- 逻辑地址 = **段号** + **段内偏移**
- 段表：段号 → 段基址 + 段长
- 段长可变
- 优点：段可独立**共享、保护、动态增长**
- 地址越界判断：段内偏移 > 段长 → 越界

<div id="section-40" class="note-anchor"></div>

### 段页式

每取一个数据要访问 **3 次**内存（段表→页表→数据）

<div id="section-41" class="note-anchor"></div>

### 虚拟存储器

- 理论基础：**程序局部性原理**（时间局部性 + 空间局部性）
- 特征：**多次性、对换性、虚拟性**
- 最大容量取决于：CPU 地址结构（逻辑空间）+ 外存容量
  
> ⭐ 虚拟存储器不能扩大物理内存的实际容量！（判断题）
> 虚拟存储只能基于**非连续分配**技术。

## 七、页面置换 & 虚拟存储器

<div id="section-43" class="note-anchor"></div>

### 缺页中断

- 一条指令可能产生**多次**缺页中断（指令跨页 + 操作数跨页）
- 缺页中断属于**程序性中断**（内中断）

<div id="section-44" class="note-anchor"></div>

### 页面置换算法对比

| 算法 | 淘汰规则 | Belady异常 | 可实现 |
| --- | --- | --- | --- |
| **OPT** | 将来最久不用 | 无 | 否（理论最优） |
| **LRU** | 最近最久未用 | 无 | 是 |
| **FIFO** | 最早进入 | **有** | 是 |
| **LFU** | 使用频率最低 | — | 是 |
| **Clock/NRU** | 访问位=0 | — | 是 |

> ⭐ Belady 异常：FIFO 特有，增加物理块反而缺页增多

<div id="section-45" class="note-anchor"></div>

### 抖动（Thrashing）

- 频繁缺页，CPU 大部分时间用于页面置换而非进程执行
- 原因：分配物理块太少 / 置换算法不合适
- 解决办法：增加物理块、减少并发进程数

## 八、设备管理

<div id="section-47" class="note-anchor"></div>

### I/O 设备分类

| 按传输单位 | 例子 | 按共享属性 | 例子 |
| --- | --- | --- | --- |
| **块设备** | 磁盘 | **独占设备** | 打印机 |
| **字符设备** | 键盘、鼠标 | **共享设备** | 磁盘 |
| | | **虚拟设备** | SPOOLing 改造后的打印机 |

<div id="section-48" class="note-anchor"></div>

### I/O 控制方式（CPU 干预由多到少）

| 方式 | CPU 参与 | 特点 |
| --- | --- | --- |
| **程序查询** | 全程查询 | 效率最低，"忙等" |
| **中断驱动** | 数据准备完通知 CPU | CPU 被中断处理打断 |
| **DMA** | 开始 + 结束 | CPU 和 I/O 可并行 |
| **通道** | 极少 | 专门 I/O 处理机，CPU 干预**最少** |

> ⭐ 需要 CPU 干预最少的是**通道**（其次是 DMA）

<div id="section-49" class="note-anchor"></div>

### 缓冲区

- 目的：**缓解 CPU 与 I/O 设备速度不匹配**
- 单缓冲：一个缓冲区
- 双缓冲：两个缓冲区，读取和传送可并行
- 环形缓冲：多个缓冲区循环使用

<div id="section-50" class="note-anchor"></div>

### SPOOLing 技术（假脱机）

- 作用：独占设备 → **共享设备**（虚拟设备）
- 组成：输入井/输出井 + 输入缓冲/输出缓冲 + 输入进程/输出进程
- 典型应用：**共享打印机**
- 虚拟设备通过 **SPOOLing** 技术实现

> ⭐ 打印机物理上仍是独占设备，逻辑上可被多个用户共享

<div id="section-51" class="note-anchor"></div>

### 磁盘

<div id="section-52" class="note-anchor"></div>

#### 访问时间组成


$$
T_{access} = T_{seek} + T_{rotation} + T_{transfer}
$$


寻道时间 + 旋转延迟 + 传输时间

- **磁盘调度**主要优化的是**寻道时间**（也叫柱面定位时间）
- 寻道时间 = 移动柱面数 × 每柱面移动时间

<div id="section-53" class="note-anchor"></div>

#### 磁盘调度算法

| 算法 | 特点 |
| --- | --- |
| **FCFS** | 按请求顺序 |
| **SSTF** | 最短寻道优先，**边缘磁道可能饥饿** |
| **SCAN（电梯）** | 来回扫描，解决饥饿 |
| **CSCAN** | 单向扫描，更均匀 |
| **LOOK** | SCAN 的改进，不到端点就反向 |

> ⭐ SCAN 电梯算法主要解决 SSTF 的**边缘磁道饥饿现象**
> 磁盘调度算法中 FCFS、SSTF、SCAN 属于**移臂调度**（寻道调度）

## 九、文件管理

<div id="section-55" class="note-anchor"></div>

### 基本概念

| 术语 | 含义 |
| --- | --- |
| **文件** | 信息的集合，按名存取 |
| **FCB** | 文件控制块，存储文件属性（不是进程控制块） |
| **目录** | 文件的组织方式 |

> ⭐ 从用户角度看，引入文件系统主要目的是**按名存取**
> FCB 是**文件控制块**，不是进程控制块（PCB）

<div id="section-56" class="note-anchor"></div>

### 文件物理结构

| 结构 | 存储方式 | 存取方式 |
| --- | --- | --- |
| **顺序文件** | 连续存储 | 顺序存取，**最快** |
| **链接文件** | 盘块链 | 顺序存取 |
| **索引文件** | 索引表 | **随机存取** |

> ⭐ 存取最快的是**顺序文件**（连续结构）
> 适合随机存取的是**索引文件**
> 不适合直接存取（随机存取）的是**链接分配**

<div id="section-57" class="note-anchor"></div>

### 文件逻辑结构

- 有结构文件（记录式文件）
- 无结构文件（流式文件）

<div id="section-58" class="note-anchor"></div>

### 目录结构

| 结构 | 特点 |
| --- | --- |
| 单级目录 | 不能重名 |
| 二级目录 | 用户目录 + 文件目录 |
| **多级目录** | 树形，可重名，按路径访问 |

> ⭐ 不同用户文件名相同 → **多级目录结构**来解决

<div id="section-59" class="note-anchor"></div>

### 位示图

用途：**磁盘空间管理**（不是磁盘驱动调度、不是文件目录查找）

<div id="section-60" class="note-anchor"></div>

### 磁盘索引分配文件最大长度

单级索引：块大小 / 块号大小（一个索引块能存的块号数） × 块大小
二级索引：(块大小 / 块号大小)² × 块大小

已知索引块 = 物理块。

例：块大小 1KB，块号 4B
- 一个块可容纳 1024/4 = 256 个块号
- 单级索引最大文件 = 256 × 1KB = 256KB
- 二级索引最大文件 = 256² × 1KB = 64MB
- 三级索引最大文件 = 256³ × 1KB = 16GB

## 高频简答题参考答案

<div id="section-62" class="note-anchor"></div>

### 1. 操作系统四大特征及其关系

并发、共享、虚拟、异步。**并发和共享**是最基本的两个特征，互为存在条件。

<div id="section-63" class="note-anchor"></div>

### 2. 死锁四必要条件

互斥条件、请求与保持条件、不可剥夺条件、环路等待条件。

<div id="section-64" class="note-anchor"></div>

### 3. 进程与程序的区别

| 进程 | 程序 |
| --- | --- |
| 动态，有生命周期 | 静态，永久存储 |
| 并发执行 | 顺序执行 |
| 包含 PCB | 只有代码 |
| 资源分配单位 | 不是 |

<div id="section-65" class="note-anchor"></div>

### 4. 进程的五大特征

动态性、并发性、独立性、异步性、结构性。

<div id="section-66" class="note-anchor"></div>

### 5. PCB 的组成与作用

- 组成：进程标识符、处理机状态信息、进程调度信息、进程控制信息
- 作用：进程存在的**唯一标志**，OS 通过 PCB 管理和控制进程

<div id="section-67" class="note-anchor"></div>

### 6. 引入线程的原因，线程与进程区别

- 原因：减少进程创建和切换开销
- 区别：线程是调度和执行的基本单位，进程是资源分配的基本单位；线程共享进程地址空间

<div id="section-68" class="note-anchor"></div>

### 7. 进程同步与互斥含义

- 互斥：多个进程不能**同时**进入临界区
- 同步：多个进程按**一定顺序**协调执行

<div id="section-69" class="note-anchor"></div>

### 8. 静态重定位与动态重定位区别

| 静态 | 动态 |
| --- | --- |
| 装入时转换 | 运行时转换 |
| 不能移动 | 可移动（支持紧凑） |

<div id="section-70" class="note-anchor"></div>

### 9. SPOOLing 系统的组成与工作过程

- 组成：输入井/输出井、输入缓冲/输出缓冲、输入进程/输出进程
- 以共享打印机为例：用户输出先写入输出井 → 挂入打印请求队列 → 输出进程从输出井取数据打印

<div id="section-71" class="note-anchor"></div>

### 10. 引起进程调度的因素

- 运行进程时间片用完
- 运行进程等待事件（执行 P 操作、请求 I/O）
- 更高优先级进程到达（抢占式）
- 运行进程完成/终止

<div id="section-72" class="note-anchor"></div>

### 11. 一条指令可能产生多次缺页中断的原因

指令本身可能跨页存放，操作数可能跨页存放，因此一条指令执行可能访问多个页面，产生多次缺页中断。

<div id="section-73" class="note-anchor"></div>

### 12. 内零头和外零头

- 内零头：已分配给作业的空间中未被利用的部分（分页、固定分区）
- 外零头：系统中太小的、无法利用的空闲块（动态分区、分段）

<div id="section-74" class="note-anchor"></div>

### 13. 虚拟存储器的三个特征

多次性、对换性、虚拟性

<div id="section-75" class="note-anchor"></div>

### 14. 处理死锁的四种方法

预防、避免（银行家算法）、检测（资源分配图）、解除（撤销进程）

<div id="section-76" class="note-anchor"></div>

### 15. I/O 控制方式的演进

程序查询 → 中断 → DMA → 通道（CPU 干预从多到少）

<div id="section-77" class="note-anchor"></div>

### 16. 引入缓冲的目的

缓解 CPU 与 I/O 设备速度不匹配，提高系统吞吐量和设备利用率

## 选择题/填空题高频考点补充

<div id="section-79" class="note-anchor"></div>

### 易混淆概念对照

| 概念 | 易混概念 | 区别 |
| --- | --- | --- |
| PCB | FCB | PCB=进程控制块，FCB=**文件**控制块 |
| 进程调度 | 作业调度 | 进程调度=选进程上 CPU（低级），作业调度=选作业进内存（高级） |
| 互斥 | 同步 | 互斥=不能同时进，同步=按顺序进 |
| 死锁预防 | 死锁避免 | 预防=破坏条件，避免=银行家判断 |
| 段表 | 页表 | 段表存基址+段长，页表存块号 |
| 寻道时间 | 旋转延迟 | 寻道=磁头移动，旋转=等扇区转过来 |
| 逻辑地址 | 物理地址 | 逻辑=程序的，物理=实际的 |
| 块设备 | 字符设备 | 块=按块传输（磁盘），字符=按字符（键盘） |
| 并发 | 并行 | 并发=宏观同时微观交替，并行=同时 |
| 虚拟存储器 | 物理内存 | 虚拟=逻辑扩充，不等同于增加物理内存 |

<div id="section-80" class="note-anchor"></div>

### 信号量/PV 选择填空题

- P 操作的主要作用：**申请资源**（不是释放）
- 信号量 S 初值为 2，当前为 −1，等待进程 = **1** 个（|−1| = 1）
- 信号量初值 2，3 进程共享 → S ∈ **[−1, 2]**
- 信号量初值 1，n 进程竞争互斥 → S ∈ **[1−n, 1]**
- 多个进程共享互斥段，最多允许 2 个进入 → 信号量初值 = **2**

<div id="section-81" class="note-anchor"></div>

### 死锁选择填空题

- 银行家算法属于**避免死锁**，不是预防
- 一次性分配所有资源破坏**请求与保持**条件
- 资源有序分配破坏**环路等待**条件
- 强行剥夺资源破坏**不可剥夺**条件
- 最简单解除死锁方式：**撤销进程**
- 死锁一定伴随**循环等待**，但循环等待不一定死锁

<div id="section-82" class="note-anchor"></div>

### 调度选择填空题

- 时间片过大会退化为 **FCFS**
- 时间片轮转主要用于**分时系统**
- 高响应比优先不会产生**饥饿**
- FCFS 对短作业不利
- 抢占式调度：新到达进程优先级更高时抢占 CPU

<div id="section-83" class="note-anchor"></div>

### 存储管理选择填空题

- 对换(Swapping)和覆盖(Overlay)：节省主存空间
- 分页地址=页号+页内偏移，分段地址=段号+段内偏移
- 4KB 页面 → 页内偏移 **12 位**
- 逻辑地址 16 位，高 6 位页号 → 64 页，每页 1KB
- 页面越大，内零头越大
- 页面越小，页表越大

<div id="section-84" class="note-anchor"></div>

### 设备管理选择填空题

- 通道是专门 I/O 控制的硬件，独立于 CPU 工作 ✅
- SPOOLing 将独享设备改造为共享设备
- 磁盘属于**块设备**
- 位示图用于**磁盘空间管理**
- 设备分配需考虑：**安全性**和**设备无关性**

<div id="section-85" class="note-anchor"></div>

### 文件管理选择填空题

- 存取最快：**顺序文件**
- 适合随机存取：**索引文件**
- 磁盘是**块设备**
- SPOOLing 系统中打印机物理上仍是独占设备 ✅

## 判断题高频考点

| 判断 | 正误 |
| --- | --- |
| 多道程序设计可以让多个进程同时使用 CPU | ❌（宏观同时，微观交替） |
| 并发和并行是完全相同的概念 | ❌ |
| 进程是资源分配单位，线程是调度和执行单位 | ✅ |
| 临界区可以多个进程同时进入 | ❌ |
| 信号量的值只能 ≥ 0 | ❌（可以为负） |
| P/V 操作必须成对出现且不能被中断 | ✅ |
| 死锁一定伴随循环等待条件 | ✅ |
| 银行家算法可以百分百杜绝死锁 | ❌ |
| 动态分区产生外碎片，分页产生内碎片 | ✅ |
| 虚拟存储器可以扩大物理内存实际容量 | ❌ |
| 页面越大内存利用率越高 | ❌（内零头更大） |
| FIFO 可能出现 Belady 异常 | ✅ |
| 段式存储中段大小不固定 | ✅ |
| SPOOLing 系统中打印机依然是独占物理设备 | ✅ |
| 通道是独立于 CPU 工作的硬件 | ✅ |
| 程序查询方式下 CPU 大部分时间空闲 | ❌（忙等） |
| 索引文件适合随机存取 | ✅ |
| 时间片越小系统切换开销越小 | ❌（越大） |
| 就绪队列进程都已获得除 CPU 外所有资源 | ✅ |
| 进程结束后 PCB 被系统回收 | ✅ |
| 进程从阻塞态可直接到运行态 | ❌（必须经过就绪态） |
