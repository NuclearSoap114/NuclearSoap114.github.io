## 补充大题① 分段地址转换

<div id="section-3" class="note-anchor"></div>

### 分页 vs 分段对比

| | 分页 | 分段 |
| --- | --- | --- |
| 地址结构 | 页号 + 页内偏移 | **段号 + 段内偏移** |
| 大小 | 页面固定大小 | **段长可变** |
| 表结构 | 页表（页号→物理块号） | **段表（基址 + 段长）** |
| 越界判断 | 页号 ≥ 页表长度 | **段内偏移 ≥ 段长** |
| 缺页/缺段 | 缺页（有效位=0） | **缺段（段不在内存）** |

<div id="section-4" class="note-anchor"></div>

### 分段做题步骤

1. 逻辑地址 (段号, 段内偏移)
2. 查段表：段号合法？段内偏移 < 段长？
3. 物理地址 = **段基址 + 段内偏移**

<div id="section-5" class="note-anchor"></div>

### 例题（来自五套卷 第4套）

段表如下：

| 段号 | 基地址 | 段长 |
| --- | --- | --- |
| 0 | 219 | 600 |
| 1 | 2300 | 14 |
| 2 | 90 | 100 |
| 3 | 1327 | 5800 |
| 4 | 1952 | 96 |

**(2, 88)**：
- 段号 2 → 基址 90，段长 100
- 88 < 100 ✅
- 物理地址 = 90 + 88 = **178**

**(4, 100)**：
- 段号 4 → 段长 96
- 100 ≥ 96 ❌ → **越界中断！**

## 补充大题② 多道程序 CPU+I/O 并行调度

<div id="section-7" class="note-anchor"></div>

### 核心规则

- **CPU 可抢占**（按优先级），**I/O 设备不可抢占**
- 进程在 I/O 时释放 CPU
- 画 Gantt 图：CPU 和设备各一行

<div id="section-8" class="note-anchor"></div>

### 例题（测试题 综合题4）

1 个 CPU、两台独占 I/O 设备。优先级 A > B > C，0ms 同时到达。

```
A: CPU(30) → I/O1(50) → CPU(20)
B: CPU(20) → I/O2(40) → CPU(30)
C: CPU(40) → I/O1(30) → CPU(20)
```

**时间线**：

| 时间段 | CPU | I/O1 | I/O2 |
| --- | --- | --- | --- |
| 0-30 | **A** CPU1 | | |
| 30-50 | **B** CPU1 | A | |
| 50-80 | **C** CPU1 | A | B |
| 80-100 | **A** CPU2（抢占 C） | | B |
| 100-130 | **B** CPU2 | C | |
| 130-140 | **C** CPU1续 | C | |
| 140-170 | | C | |
| 170-190 | **C** CPU2 | | |

| 作业 | 完成 | 周转 |
| --- | --- | --- |
| A | 100 | 100 |
| B | 130 | 130 |
| C | 190 | 190 |

CPU 利用率 = 160/190 ≈ **84.2%**

## 选填补充考点

> 以下不展开为大题，但选择、填空、简答会考。

<div id="section-10" class="note-anchor"></div>

### 进程互斥访问四条件（≠ 死锁四条件！极易混淆！）

| 条件 | 含义 |
| --- | --- |
| **空闲让进** | 临界区空闲，允许进入 |
| **忙则等待** | 已有进程在里面，其他等待 |
| **有限等待** | 不能无限等（防饥饿） |
| **让权等待** | 不能进时释放 CPU（不忙等） |

<div id="section-11" class="note-anchor"></div>

### 覆盖与交换

| 技术 | 目的 | 特点 |
| --- | --- | --- |
| **覆盖** | 节省主存空间 | 程序员手动管理 |
| **交换** | 扩充主存 | OS 管理，进程整体换入换出 |

> 选择题：采用覆盖与交换技术的目的是**节省主存空间**（不是物理扩充）

<div id="section-12" class="note-anchor"></div>

### 缓冲区

| 类型 | 特点 |
| --- | --- |
| **单缓冲** | 读写串行 |
| **双缓冲** | 读写可并行 |
| **环形缓冲** | 多个缓冲区循环 |

<div id="section-13" class="note-anchor"></div>

### Belady 异常

- 仅 **FIFO** 有。增加物理块，缺页不减反增
- 典型序列：1,2,3,4,1,2,5,1,2,3,4,5 → 3块缺页 9 次，4块反而 **10 次**

<div id="section-14" class="note-anchor"></div>

### 磁盘访问时间


$$
T = T_{seek} + T_{rotation}/2 + T_{transfer}
$$


- 磁盘调度优化的是**寻道时间**（柱面定位时间）
- 磁盘访问时间**不包括**调度时间（选择题考点）

<div id="section-15" class="note-anchor"></div>

### 文件多级索引最大长度

块大小 B，块号大小 A → 一个块可存 $N = B/A$ 个块号
- 二级索引 = $N^2 \times B$
- 三级索引 = $N^3 \times B$

例：块 1KB，块号 4B → N=256，二级索引 = 256²×1KB = **64MB**

<div id="section-16" class="note-anchor"></div>

### 操作系统接口

| 接口 | 面向 |
| --- | --- |
| **系统调用** | 编程人员（引起用户态→核心态切换） |
| **命令接口 / GUI** | 普通用户 |

> "面对编程人员通过**系统调用**使用 OS，面对一般用户通过**命令形式**"——填空题考点

<div id="section-17" class="note-anchor"></div>

### 通道

- 又称 **I/O 处理机**，独立于 CPU 工作的硬件
- 用于**主存与外设**间的信息传输
- CPU 干预**最少**的 I/O 方式

<div id="section-18" class="note-anchor"></div>

### 系统调用 vs 库函数 vs 原语

| 概念 | 说明 |
| --- | --- |
| **系统调用** | 请求 OS 服务，用户态→核心态 |
| **库函数** | 封装系统调用，不一定切换态 |
| **原语** | 内核原子操作，不可中断 |

<div id="section-19" class="note-anchor"></div>

### 补充判断题

| 判断 | 正误 |
| --- | --- |
| 死锁与进程推进速度无关 | ❌（与推进顺序有关，是时间错误） |
| 出现死锁则所有进程都不能运行 | ❌（只有死锁进程，$2 \leq k \leq m$） |
| PV 操作可以完全防止死锁 | ❌（使用不当也会死锁） |
| 进程前趋图结点间存在互斥关系 | ❌（只有同步关系） |
| 临界区是实现互斥的那段代码 | ❌（是访问临界资源的代码） |
| 多道程序道数越多效率越高 | ❌（超一定数量下降） |
| 时间片越小系统效率越高 | ❌（切换开销增大） |

## 易错陷阱汇总

<div id="section-21" class="note-anchor"></div>

### 死锁条件混淆

| 描述 | 对应条件 |
| --- | --- |
| "占有资源后不主动释放" | **请求与保持**（不是不可剥夺） |
| 强行夺走资源 → 破坏 | **不可剥夺** |
| 资源编号按序申请 → 破坏 | **环路等待** |
| 一次性分配所有资源 → 破坏 | **请求与保持** |

<div id="section-22" class="note-anchor"></div>

### 调度算法别搞混

- 进程调度：FCFS、SJF、优先级、高响应比、RR
- 页面置换：FIFO、LRU、OPT（不是调度算法！）
- 磁盘调度：FCFS、SSTF、SCAN/CSCAN（也是 FCFS 但不同场景！）

<div id="section-23" class="note-anchor"></div>

### 常见伪装选项（看到就警惕）

- "线程是资源分配基本单位" → ❌
- "信号量值只能 ≥ 0" → ❌
- "虚拟存储扩大物理内存" → ❌
- "阻塞态可直接到运行态" → ❌
- "就绪 → 阻塞" → ❌（不可能！）
- "银行家算法百分百杜绝死锁" → ❌
- "并发 = 并行" → ❌
