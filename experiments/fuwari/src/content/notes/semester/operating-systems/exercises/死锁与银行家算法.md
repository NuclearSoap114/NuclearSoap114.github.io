## 一、死锁四必要条件

| 条件 | 含义 |
|------|------|
| **互斥** | 资源一次只能被一个进程独占 |
| **请求保持** | 进程持有资源的同时请求新资源 |
| **不可剥夺** | 已分配的资源不能被强制夺走 |
| **环路等待** | 进程间形成循环等待链 |

> **破坏任一条件即可预防死锁**
> - 破坏互斥 → 不太可能（很多资源本质是互斥的）
> - 破坏请求保持 → **一次性分配全部资源**
> - 破坏不可剥夺 → 允许抢占
> - 破坏环路等待 → **资源有序分配**（按编号顺序申请）

## 二、银行家算法 🌟必考大题

<div id="section-3" class="note-anchor"></div>

### 考点

考试给一个**资源分配状态**，要求：
1. 判断当前系统是否**安全**
2. 若安全，找一个**安全序列**
3. 判断某个进程的**资源请求能否满足**

<div id="section-4" class="note-anchor"></div>

### 数据结构

| 符号 | 含义 |
|:----:|------|
| **Max** | 每个进程**最大**需求矩阵 |
| **Allocation** | 每个进程**已分配**矩阵 |
| **Need** | 每个进程**还需要** = Max − Allocation |
| **Available** | 系统当前**可用**资源向量 |

<div id="section-5" class="note-anchor"></div>

### 安全性检查算法（必背步骤）

```
Step 1: 令 Work = Available
        Finish[i] = false (对所有进程 i)

Step 2: 寻找满足以下条件的进程 i：
        ① Finish[i] == false
        ② Need[i] ≤ Work（每个资源维度都不超过）
        若找到 → 执行 Step 3
        若找不到 → 跳到 Step 4

Step 3: Work = Work + Allocation[i]  // 释放 i 的资源
        Finish[i] = true
        回到 Step 2

Step 4: 若所有 Finish[i] == true → 系统安全
        否则 → 系统不安全
```

<div id="section-6" class="note-anchor"></div>

### 典型例题

> **例题**：系统有资源 A(10), B(5), C(7)。5个进程状态如下。问（1）系统安全吗？找安全序列。（2）P1请求(1,0,2)能否分配？

| 进程 | Max A B C | Allocation A B C | Need A B C |
|:----:|:---------:|:----------------:|:----------:|
| P0 | 7 5 3 | 0 1 0 | 7 4 3 |
| P1 | 3 2 2 | 2 0 0 | 1 2 2 |
| P2 | 9 0 2 | 3 0 2 | 6 0 0 |
| P3 | 2 2 2 | 2 1 1 | 0 1 1 |
| P4 | 4 3 3 | 0 0 2 | 4 3 1 |

**（1）安全性检查**：

Available = 总量 − 已分配
- A: 10 − (0+2+3+2+0) = 3
- B: 5 − (1+0+0+1+0) = 3
- C: 7 − (0+0+2+1+2) = 2
- **Available = (3, 3, 2)**

```
迭代安全性检查:

初始: Work = (3, 3, 2), Finish = [F,F,F,F,F]

第1轮: 
  P0: Need(7,4,3) > Work(3,3,2) ✗
  P1: Need(1,2,2) ≤ Work(3,3,2) ✓ → 选P1
  Work = (3,3,2) + (2,0,0) = (5, 3, 2), Finish = [F,T,F,F,F]

第2轮:
  P3: Need(0,1,1) ≤ Work(5,3,2) ✓ → 选P3
  Work = (5,3,2) + (2,1,1) = (7, 4, 3), Finish = [F,T,F,T,F]

第3轮:
  P0: Need(7,4,3) ≤ Work(7,4,3) ✓ → 选P0
  Work = (7,4,3) + (0,1,0) = (7, 5, 3), Finish = [T,T,F,T,F]

第4轮:
  P2: Need(6,0,0) ≤ Work(7,5,3) ✓ → 选P2
  Work = (7,5,3) + (3,0,2) = (10, 5, 5), Finish = [T,T,T,T,F]

第5轮:
  P4: Need(4,3,1) ≤ Work(10,5,5) ✓ → 选P4
  Finish = [T,T,T,T,T] 全部完成!
```

- ✅ **系统安全**
- 安全序列：**P1 → P3 → P0 → P2 → P4**（不唯一）

**（2）P1请求 (1, 0, 2)**：

```
判断:
  Request(1,0,2) ≤ Need(P1)=(1,2,2)?  ✓
  Request(1,0,2) ≤ Available(3,3,2)?   ✓

试探分配:
  Available = (3,3,2) - (1,0,2) = (2, 3, 0)
  Allocation(P1) = (2,0,0) + (1,0,2) = (3, 0, 2)
  Need(P1) = (1,2,2) - (1,0,2) = (0, 2, 0)

重新安全性检查 → 若安全则真正分配
```

## 三、同类练习题

> **题目**：系统资源 A(10), B(5), C(7)。某时刻状态如下：
>
> | 进程 | Allocation | Need |
> |:----:|:----------:|:----:|
> | P0 | 0,1,0 | 7,4,3 |
> | P1 | 2,0,0 | 1,2,2 |
> | P2 | 3,0,2 | 6,0,0 |
> | P3 | 2,1,1 | 0,1,1 |
> | P4 | 0,0,2 | 4,3,1 |
>
> 当前 Available = (3, 3, 2)。问：（1）系统安全吗？找出安全序列。（2）若 P1 请求 (1,0,2)，能否分配？

**解析**：

**（1）安全性检查**：

```
Work = (3,3,2)

P1: Need(1,2,2) ≤ (3,3,2) ✓ → Work=(3,3,2)+(2,0,0)=(5,3,2)
P3: Need(0,1,1) ≤ (5,3,2) ✓ → Work=(5,3,2)+(2,1,1)=(7,4,3)
P0: Need(7,4,3) ≤ (7,4,3) ✓ → Work=(7,4,3)+(0,1,0)=(7,5,3)
P2: Need(6,0,0) ≤ (7,5,3) ✓ → Work=(7,5,3)+(3,0,2)=(10,5,5)
P4: Need(4,3,1) ≤ (10,5,5) ✓ → 全部完成

安全序列: P1→P3→P0→P2→P4 ✓ 系统安全
```

**（2）P1 请求 (1,0,2)**：

```
Request ≤ Need?  (1,0,2) ≤ (1,2,2) ✓
Request ≤ Available? (1,0,2) ≤ (3,3,2) ✓

试探分配:
  Available = (3,3,2) − (1,0,2) = (2,3,0)
  Allocation(P1) = (3,0,2)
  Need(P1) = (0,2,0)

重新安全性检查(Work=(2,3,0)):
  P1: (0,2,0) ≤ (2,3,0) ✓ → Work=(5,3,2)
  P3: (0,1,1) ≤ (5,3,2) ✓ → Work=(7,4,3)
  P0: (7,4,3) ≤ (7,4,3) ✓ → Work=(7,5,3)
  P2: (6,0,0) ≤ (7,5,3) ✓ → Work=(10,5,5)
  P4: (4,3,1) ≤ (10,5,5) ✓ → 全部完成

安全序列仍然存在 → 可以分配 ✓
```

> **银行家算法得分要点**
> 1. **Need = Max − Allocation**，先算对
> 2. **Available = 总量 − 已分配之和**，逐资源维度计算
> 3. 安全性检查的**迭代过程**必须写全（不能跳过）
> 4. 请求判断三步：Request ≤ Need？Request ≤ Available？试探分配后安全吗？
> 5. 安全序列可能不唯一，找到一个即可
