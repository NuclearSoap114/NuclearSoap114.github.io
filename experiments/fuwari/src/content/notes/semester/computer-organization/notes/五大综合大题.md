## 大题一：存储系统设计与连接

**题目**：

CPU 有 16 根地址线 (A₁₅~A₀)，8 根数据线 (D₇~D₀)。控制信号 MREQ（低有效），R/W（高电平读、低电平写）。现有 ROM（1K×8 位到 32K×8 位）、RAM（1K×4 位到 8K×8 位）芯片，配合一片 74LS138 译码器。

系统程序区（ROM）：地址范围 **0000H ~ 1FFFH**

用户程序区（RAM）：地址范围 **2000H ~ 7FFFH**

要求：选择合适的 ROM 和 RAM 芯片，完成 CPU 与存储芯片的连接设计。画出连接图（示意），分析译码器逻辑，核算系统总存储容量和地址空间利用率。

**这类题怎么做**：

> **步骤**：
> 1. **算容量**：结束地址 − 起始地址 + 1，转十进制。十六进制转十进制 = 每位×16ⁿ
> 2. **看地址线**：低 N 位（变化的位）→ 片内寻址；高 M 位→ 片选，接译码器
> 3. **选芯片**：容量匹配（几 KB）+ 位宽匹配（8 根数据线 = 选 8 位宽芯片）
> 4. **连译码器**：高位地址 → 138 的 A/B/C → Y₀~Y₇ → 各芯片 CS
> 5. **总容量** = ROM + RAM。利用率 = 已用/最大可寻址

**解答**：

**① 容量计算**

ROM 区：1FFFH − 0000H + 1 = 2000H = 2×16³ = 8192 字节 = **8KB**

RAM 区：7FFFH − 2000H + 1 = 6000H = 6×16³ = 24576 字节 = **24KB**

总存储容量 = 8KB + 24KB = **32KB**。
CPU 共 16 根地址线，最大寻址 2¹⁶ = 64KB。低 32KB(0000H~7FFFH) 已用，高 32KB(8000H~FFFFH) 空闲。空间利用率 = 50%。

**② 芯片选择（容量匹配+位宽匹配+最少数量）**

系统程序区 8KB → 选 **1 片 8K×8 位 ROM**。8K×8 容量完全匹配，不需多片并联。

用户程序区 24KB → 选 **3 片 8K×8 位 RAM**。3 × 8K = 24KB，刚好匹配。

所有芯片均为 8 位数据宽度，与 CPU 8 根数据线一致。

**③ 地址线分配**

8KB = 2¹³，需要 13 根地址线做片内寻址 → A₁₂ ~ A₀（低 13 位）接所有芯片的地址输入端。

高 3 位 A₁₅ ~ A₁₃ 接 74LS138 译码器的输入端（C, B, A），用于片选。

**④ 74LS138 译码连接**

MREQ（低有效）接译码器使能端。译码器输出 Y₀~Y₇ 低电平有效，接各芯片片选端 CS。

| A₁₅(C) | A₁₄(B) | A₁₃(A) | 译码输出 | 选中芯片 | 地址范围 |
|:---:|:---:|:---:|:---:|------|------|
| 0 | 0 | 0 | Y₀=0 | ROM | 0000H~1FFFH |
| 0 | 0 | 1 | Y₁=0 | RAM₁ | 2000H~3FFFH |
| 0 | 1 | 0 | Y₂=0 | RAM₂ | 4000H~5FFFH |
| 0 | 1 | 1 | Y₃=0 | RAM₃ | 6000H~7FFFH |

ROM 只读，不接 R/W 控制。三片 RAM 的 R/W 接 CPU 的 R/W 端。

## 大题二：指令系统与寻址方式分析

**题目**：

某机主存容量为 **4M×16 位**，存储字长等于指令字长。指令系统可完成 **108 种操作**，操作码位数固定，且支持**直接、间接、变址、基址、相对、立即**等六种寻址方式。

（1）设计一地址指令的完整格式（明确操作码、寻址特征位及形式地址码字段的位数）。

（2）计算直接寻址方式下可访问的主存最大地址范围。

（3）计算一次间接寻址和多次间接寻址的寻址范围。

（4）说明立即寻址方式下，立即数的取值范围（假定形式地址码字段用补码表示）。

（5）计算相对寻址方式下，位移量的最大正向和负向偏移范围。

**这类题怎么做**：

> **指令格式设计三步**：
> 1. OP 位数 = ⌈log₂(操作种类数)⌉
> 2. MOD 位数 = ⌈log₂(寻址方式种类数)⌉
> 3. A（形式地址）位数 = 指令字长 − OP − MOD
>
> **寻址范围规律**：
> - 直接寻址：看 A 的位数 → 2^(A 的位数)
> - 间接寻址：看存储字长 → 2^(存储字长)。无论几次间接都一样，因为有效地址的位数由存储字长决定
> - 立即数（补码）：n 位补码范围 [−2ⁿ⁻¹, 2ⁿ⁻¹−1]
> - 相对寻址位移量（补码）：同立即数

**解答**：

**（1）指令格式设计**

指令字长 = 存储字长 = 16 位。

操作码：⌈log₂(108)⌉ = 7 位（2⁷=128 ≥ 108）

寻址特征：⌈log₂(6)⌉ = 3 位（2³=8 ≥ 6）

形式地址 A：16 − 7 − 3 = 6 位

```
┌─────────┬────────┬──────────┐
│ OP(7位) │MOD(3位)│  A(6位)  │
└─────────┴────────┴──────────┘
```

**（2）直接寻址范围**

EA = A。A 为 6 位 → 2⁶ = **64 个地址单元**（0 ~ 63）。

**（3）间接寻址范围**

一次间接：先访存取出 EA，EA 长度 = 存储字长 = 16 位 → 2¹⁶ = **64K**。

多次间接：有效地址仍为 16 位 → 仍然是 **64K**。无论几次间接，范围都不变。

**（4）立即数取值范围（补码）**

A 为 6 位补码，n=6。范围：[−2⁵, 2⁵−1] = **−32 ~ +31**。

**（5）相对寻址位移量范围（补码）**

位移量 = A 字段的 6 位补码。范围：**−32 ~ +31**（以当前 PC 为基准）。

**寻址方式速度对比（按访存次数排）**：

| 寻址方式 | EA 公式 | 访存次数 | 速度 |
|------|------|:---:|:---:|
| 立即寻址 | 操作数 = A | 0 | 🥇最快 |
| 寄存器寻址 | 操作数 = (R) | 0 | 🥇最快 |
| 直接寻址 | EA = A | 1 | 🥈 |
| 变址寻址 | EA = (IX) + A | 1 | 🥈 |
| 基址寻址 | EA = (BR) + A | 1 | 🥈 |
| 相对寻址 | EA = (PC) + A | 1 | 🥈 |
| 间接寻址 | EA = (A) | ≥2 | 🥉最慢 |

> 关联：[课堂补充题解析](/notes/semester/computer-organization/notes/%E8%AF%BE%E5%A0%82%E8%A1%A5%E5%85%85%E9%A2%98%E8%A7%A3%E6%9E%90/#section-6)

## 大题三：单总线 CPU 指令执行分析

**题目**：

基于经典单总线结构 CPU，集成运算器（ALU/ACC/X）、控制器（CU/IR/PC）与总线接口（MAR/MDR）。定长 16 位指令设计：前 6 位为操作码，后 10 位为地址码。存储器按字节编址，单总线分时复用。

初始状态：PC = **0100H**，ACC = **0005H**。

指令区（0100H ~ 0104H）：

| 地址 | 机器码 | 指令含义 |
|------|------|------|
| 0100H | A020 | ADD 0200H |
| 0102H | 1C00 | SHL（算术左移一位） |
| 0104H | 2B01 | SUB 0201H |

数据区（0200H ~ 0201H）：

| 地址 | 数据 |
|------|------|
| 0200H | 0003H |
| 0201H | 0002H |

各指令功能说明：
- **ADD addr**：将累加器 ACC 中的值与主存 addr 地址单元中的数据相加，结果送回 ACC。即 (ACC) + (addr) → ACC。
- **SHL**（算术左移）：将累加器 ACC 内容算术左移一位。即 (ACC) << 1 → ACC。
- **SUB addr**：将累加器 ACC 中的值减去主存 addr 地址单元中的数据，结果送回 ACC。即 (ACC) − (addr) → ACC。

要求：
1. 写出取指周期的公共微操作序列（每条指令开始前均需执行）。
2. 分别写出 ADD 0200H、SHL、SUB 0201H 三条指令的执行周期微操作序列，并给出每条指令执行后 ACC 的值。
3. 分析整个过程中程序计数器 PC 的变化，给出最终 PC 的值并说明理由。

**这类题怎么做**：

> **取指周期（4 步，必默写，顺序不能错）**：
> ```
> ① PC → MAR        将程序计数器的内容送到地址寄存器
> ② M(MAR) → MDR    从存储器读指令字，经数据总线送入 MDR
> ③ MDR → IR        指令从 MDR 送到指令寄存器，控制器译码
> ④ PC + 2 → PC     程序计数器自增，指向下一条（16 位指令 = 2 字节）
> ```
>
> **执行周期模式（访存/运算指令统一模式）**：
> ```
> IR地址码 → MAR  →  读MEM → MDR  →  MDR → X  →  ALU运算  →  结果 → ACC
> ```
> - 加法：(X) + (ACC) → ACC
> - 减法：(ACC) − (X) → ACC
> - 移位：ACC → X → 移位器 → ACC
>
> **PC 变化**：取指时 +2（16 位=2 字节），执行时不变（除非转移指令）。

**解答**：

**1. 取指周期公共微操作（每条指令执行前执行）**

| 步 | 微操作 | 说明 |
|:---:|------|------|
| ① | PC → MAR | 程序计数器内容通过内部总线送入 MAR |
| ② | 读存储器，M(MAR) → MDR | 控制总线发"读"命令，读出指令字经数据总线送入 MDR |
| ③ | MDR → IR | 指令送入指令寄存器，由控制器译码 |
| ④ | PC + 2 → PC | PC 自增 2（指令 16 位=2 字节，按字节编址） |

**2. 三条指令执行**

**ADD 0200H**（初始 ACC = 0005H，地址码 = 0200H）：

| 步 | 微操作 | 说明 |
|:---:|------|------|
| ① | IR地址码(0200H) → MAR | 指令中的地址字段送入 MAR |
| ② | 读存储器 | 从地址 0200H 读出数据 0003H 经 DB → MDR |
| ③ | MDR → X | 操作数通过内部总线送入 ALU 的 X 输入 |
| ④ | ALU：X+ACC，结果→总线 | ALU 将 X 与 ACC 相加，结果输出到内部总线 |
| ⑤ | 总线 → ACC | ALU 运算结果写回 ACC |

结果：0005H + 0003H = **0008H**

**SHL 算术左移**（当前 ACC = 0008H）：

| 步 | 微操作 | 说明 |
|:---:|------|------|
| ① | ACC → X | 将 ACC 内容通过总线送入 X 寄存器（或直接入移位器） |
| ② | ALU 执行逻辑左移，结果→总线 | X 内容左移一位（最低位补 0），结果输出到总线 |
| ③ | 总线 → ACC | 移位结果写回 ACC |

结果：0008H << 1 = **0010H**
（0008H = 0000 0000 0000 1000₂，左移得 0000 0000 0001 0000₂ = 0010H）

**SUB 0201H**（当前 ACC = 0010H，地址码 = 0201H）：

| 步 | 微操作 | 说明 |
|:---:|------|------|
| ① | IR地址码(0201H) → MAR | 地址 0201H 送入 MAR |
| ② | 读存储器 | 从地址 0201H 读出数据 0002H → MDR |
| ③ | MDR → X | 操作数通过总线送入 X 寄存器 |
| ④ | ALU：ACC−X，结果→总线 | ALU 执行减法（ACC 减 X），结果输出到总线 |
| ⑤ | 总线 → ACC | 结果写回 ACC |

结果：0010H − 0002H = **000EH**

**3. PC 变化**

初始 PC = 0100H。

- 取 ADD 指令后，PC = 0100H + 2 = **0102H**
- 取 SHL 指令后，PC = 0102H + 2 = **0104H**
- 取 SUB 指令后，PC = 0104H + 2 = **0106H**

执行周期不改变 PC（本例无转移指令）。

最终 PC = **0106H**。

## 大题四：计算机系统概述与 DMA 分析

**题目**：

（1）简述计算机五大功能部件的基本功能，画出它们之间的连接框图（示意数据流与控制流），并说明你认为哪一个部件最重要，说明理由。

（2）选择一种 I/O 方式（建议选择 DMA 方式或中断方式），画出该方式的工作流程示意图，并依据图示详细阐述该方式的工作过程，最后分析它对 CPU 执行效率的影响（优点与局限性）。

**这类题怎么做**：

> **五大部件（必背）**：运算器（ALU，数据加工）、控制器（CU，神经中枢）、存储器（存程序数据）、输入设备（外部信息→二进制）、输出设备（结果→外部）。
>
> **最重要部件**：控制器（CPU 整体）。核心理由：计算机本质是"存储程序控制"，控制器按顺序取指、译码、发信号，协调所有部件。没有控制器，各部件各自为政。
>
> **DMA 四阶段（必默写）**：
> ```
> 初始化(CPU配置DMA参数) → 请求与响应(DREQ→HRQ→HLDA) → 直接传输(DMA控制总线,外设↔内存) → 结束恢复(计数=0,中断通知CPU,收回总线)
> ```
>
> **DMA 效率分析套路**：优点（解放CPU、降低中断次数、高速）∩ 局限（硬件成本、总线争用、小块不适用）。

**解答**：

**一、五大部件功能**

| 部件 | 核心功能 |
|------|------|
| **运算器（ALU）** | 算术运算（+−×÷）和逻辑运算（AND/OR/NOT），数据加工的场所 |
| **控制器（CU）** | 从存储器取指令、译码分析、产生微操作控制信号，计算机的"神经中枢" |
| **存储器** | 存放程序和数据。主存（CPU 可直接访问）+ 辅存（长期保存） |
| **输入设备** | 将外部信息（键盘、鼠标等）转换为计算机能识别的二进制数据 |
| **输出设备** | 将计算机处理结果从二进制转换为人类可读形式（显示器、打印机等） |

连接关系：五大部件通过**总线**（数据总线、地址总线、控制总线）互联。

最重要部件：**控制器（若将运算器与控制器合称 CPU，则为 CPU 整体）**。理由：
1. 统率全局——"存储程序控制"的本质就是控制器逐条取指、解释、执行
2. 协调各部件——中断、DMA、总线仲裁等都需要控制器发出正确时序
3. 体现"组成"核心——控制器决定指令集实现和微操作效率

**二、DMA 方式工作原理与效率分析**

**DMA（Direct Memory Access，直接存储器存取）**：由 DMA 控制器接管系统总线，在不经过 CPU 干预的情况下，直接实现外设与内存之间的高速数据传输。

**工作流程（4 阶段）**：

```
阶段① 初始化：CPU 设置 DMA 控制器的参数（内存起始地址、传输字节数、传输方向）
    ↓
阶段② 请求与响应：外设发 DREQ → DMA 控制器发 HRQ 请求总线 → CPU 执行完当前总线周期后
                    发 HLDA 应答，释放总线控制权
    ↓
阶段③ 直接传输：DMA 控制器操控总线，外设 ←→ 内存 高速批量传送
                 每传一个字：地址计数器+1，字数计数器−1，重复至字数=0
                 （整个阶段无需 CPU 干预）
    ↓
阶段④ 结束恢复：计数=0 → DMA 撤销 HRQ，向 CPU 发中断 → CPU 响应中断处理后续工作，
                 收回总线控制权
```

**对 CPU 效率的影响**：

| 优点 | 局限性 |
|------|------|
| **解放 CPU**：传输期间 CPU 可并行执行其他任务（只要不访问被 DMA 占用的总线），大块数据 CPU 效率可提升数倍至数十倍 | **硬件成本增加**：需额外 DMA 控制器芯片，复杂系统还可能有多个 DMA 通道 |
| **降低中断开销**：整块数据传输仅产生一次中断，而非每个字节都中断 CPU | **总线争用**：DMA 占用总线时，CPU 无法访问主存，可能导致等待 |
| **传输速率高**：DMA 控制器硬件实现地址生成和计数，速率接近总线带宽，远高于软件控制的逐字传输 | **小块传输不适用**：DMA 初始化的编程开销对极少量数据（几个字节）得不偿失，中断方式可能更合适 |

> 关联：[课堂补充题解析](/notes/semester/computer-organization/notes/%E8%AF%BE%E5%A0%82%E8%A1%A5%E5%85%85%E9%A2%98%E8%A7%A3%E6%9E%90/#section-2)

## 大题五：总线性能计算

**题目**：

现有一个系统，总线时钟频率为 **100 MHz**，每个总线周期固定占用 **4 个时钟周期**（每个阶段占用 1 个时钟周期）。数据总线宽度为 **16 位**。CPU（主设备）需要从某从设备连续读取 **200 个 32 位数据**。从设备的访问延迟（从收到地址到第一个数据可用的时间）为 **10 ns**，且每个 32 位数据必须分两次（每次 16 位）进行传输，每次传输都需要一个完整的总线周期（即每个 16 位传输独立经历四个阶段）。忽略地址递增的额外延迟，但每次传输的地址阶段均需重新发送地址。

请回答下列问题：

（1）（概念部分）什么叫总线？按照传输信息的不同，总线可分为哪三类？总线上连接的主设备和从设备是如何区分的？什么叫总线周期？它可分为哪四个阶段？请简要描述这四个阶段的具体过程。

（2）（计算部分）计算完成全部 200 个 32 位数据读取所需的总时间（单位：μs），并求该过程中总线的实际平均数据传输率（单位：Mbps）。要求写出详细计算步骤。

**这类题怎么做**：

> **概念部分（必背）**：
> - 总线 = 连接计算机系统中各部件的**一组公共信号线**
> - 三类 = **数据总线（DB）**传数据、**地址总线（AB）**传地址、**控制总线（CB）**传控制信号
> - 主设备 = 能**主动发起**总线请求并获得总线控制权的设备（如 CPU）
> - 从设备 = 只能**被动响应**主设备命令的设备（如内存）
> - 总线周期 = 一次完整总线操作的时间，四阶段：**申请分配 → 寻址 → 传数 → 结束**
>
> **计算部分**：
> 1. T_clk = 1/f
> 2. T_cycle = 周期内时钟数 × T_clk（访问延迟已包含在时钟周期内，不额外加）
> 3. 总传输次数 = 数据个数 × (每个数据的位宽 / 总线位宽)
> 4. 总时间 = 总次数 × T_cycle
> 5. 传输率 = 总 bit 数 / 总时间

**解答**：

**（1）概念部分**

**总线**：计算机系统中连接各部件（CPU、内存、I/O 设备等）的一组公共信号线，用于在各部件之间传输信息。

**按传输信息分三类**：
- **数据总线（DB）**：传输数据信息，双向
- **地址总线（AB）**：传输地址信息，单向（CPU→设备）
- **控制总线（CB）**：传输控制信号（读/写、中断、时钟等），每根线方向固定

**主设备与从设备**：
- **主设备**：能主动发起总线请求并获得总线控制权的设备（如 CPU），负责启动总线操作
- **从设备**：只能响应主设备命令、被动进行数据交换的设备（如内存），不能主动占用总线

**总线周期**：一次完整的总线操作（如一次读或写操作）所占用的时间。四个阶段：

| 阶段 | 名称 | 具体过程 |
|:---:|------|------|
| ① | 申请分配 | 主设备申请总线使用权，仲裁器决定将总线分配给哪个主设备 |
| ② | 寻址 | 获得控制权的主设备将地址信息放到地址总线上，并发出相应的控制信号 |
| ③ | 传数 | 从设备根据地址将数据放到数据总线上（读操作），或主设备将数据放到数据总线上（写操作） |
| ④ | 结束 | 主设备撤销控制信号，释放总线 |

**（2）计算部分**

**已知条件**：
- 时钟频率 f = 100 MHz
- 总线周期 = 4 个时钟周期
- 数据总线宽度 = 16 位
- 读取 200 个 32 位数据，每个 32 位数据分 2 次 16 位传输
- 访问延迟 10 ns ≤ 时钟周期 10 ns，已包含在寻址阶段的时钟周期内，不额外累加

**步骤 1：时钟周期与总线周期**

T_clk = 1/100MHz = **10 ns**

T_cycle = 4 × 10ns = **40 ns**

**步骤 2：总传输次数**

每个 32 位数据需 2 次传输（每次 16 位）

N = 200 × 2 = **400 次**

**步骤 3：总时间**

T_total = N × T_cycle = 400 × 40ns = 16000ns = **16 μs**

**步骤 4：总线实际平均数据传输率**

总数据量 = 200 × 32bit = 6400 bit

平均传输率 = 6400bit / 16μs = 400 × 10⁶ bps = **400 Mbps**

> 也可直接用公式验证：理论最大带宽 = 总线宽度/总线周期 = 16bit/40ns = 400Mbps ✓
