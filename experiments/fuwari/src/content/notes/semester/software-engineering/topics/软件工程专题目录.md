## 三、每个文件具体怎么复习

<div id="section-6" class="note-anchor"></div>

### 1. [软件工程概述与软件过程模型](/notes/semester/software-engineering/topics/%E8%BD%AF%E4%BB%B6%E5%B7%A5%E7%A8%8B%E6%A6%82%E8%BF%B0%E4%B8%8E%E8%BD%AF%E4%BB%B6%E8%BF%87%E7%A8%8B%E6%A8%A1%E5%9E%8B/)

<div id="section-7" class="note-anchor"></div>

#### 复习优先级：P1

<div id="section-8" class="note-anchor"></div>

#### 必背内容

1. 软件是逻辑产品。
2. 软件 = 程序 + 数据 + 文档。
3. 软件工程三要素 = 方法 + 工具 + 过程。
4. 软件危机表现和原因。
5. 软件生命周期七阶段。
6. 瀑布模型、原型模型、增量模型、螺旋模型、敏捷模型的特点和适用场景。
7. Scrum 三个角色。
8. RUP 三个核心特点、6个最佳实践、9个核心工作流。
9. CMM五级。

<div id="section-9" class="note-anchor"></div>

#### 最可能考法

1. 选择题：软件工程三要素不包括什么。
2. 判断题：软件测试是否只在编码后进行。
3. 简答题：软件危机原因。
4. 比较题：瀑布模型、原型模型、增量模型、螺旋模型区别。
5. 场景题：根据题干选择过程模型。

<div id="section-10" class="note-anchor"></div>

#### 速背口诀

```text
需求明确用瀑布
需求不清用原型
分批交付用增量
风险很高用螺旋
变化很快用敏捷
构件复用用构件
用例架构迭代是RUP
```

### 2. [需求工程与需求管理](/notes/semester/software-engineering/topics/%E9%9C%80%E6%B1%82%E5%B7%A5%E7%A8%8B%E4%B8%8E%E9%9C%80%E6%B1%82%E7%AE%A1%E7%90%86/)

<div id="section-12" class="note-anchor"></div>

#### 复习优先级：P0

<div id="section-13" class="note-anchor"></div>

#### 必背内容

1. 需求分析解决“做什么”，不是“怎么做”。
2. 需求分类：业务需求、用户需求、功能需求、非功能需求。
3. 需求工程 = 需求开发 + 需求管理。
4. 需求开发 = 获取、分析、规格说明、验证。
5. 需求管理 = 变更控制、版本控制、状态跟踪。
6. 需求获取方法：问卷、访谈、观察、原型、数据分析等。
7. 代码审查不是需求获取方法。
8. SRS作用：沟通、设计、编码、测试、验收依据。
9. 糟糕需求原因：沟通障碍、用户参与不足、描述不清、程序员镀金等。
10. 敏捷需求获取：用户故事 + 迭代计划。

<div id="section-14" class="note-anchor"></div>

#### 最可能考法

1. 选择题：需求获取目的是什么。
2. 多选题：哪些属于需求获取方法。
3. 简答题：需求工程主要活动。
4. 案例题：区分功能需求和非功能需求。
5. 综合题：根据题干提取需求。

<div id="section-15" class="note-anchor"></div>

#### 速背口诀

```text
需求分类：业务、用户、功能、非功能
需求开发：获取、分析、规格、验证
需求管理：变更、版本、跟踪
```

### 3. [面向过程与面向对象思想](/notes/semester/software-engineering/topics/%E9%9D%A2%E5%90%91%E8%BF%87%E7%A8%8B%E4%B8%8E%E9%9D%A2%E5%90%91%E5%AF%B9%E8%B1%A1%E6%80%9D%E6%83%B3/)

<div id="section-17" class="note-anchor"></div>

#### 复习优先级：P1

<div id="section-18" class="note-anchor"></div>

#### 必背内容

1. 面向过程关注步骤、函数、流程。
2. 面向对象关注对象、类、消息协作。
3. 类是对象的抽象，对象是类的实例。
4. 类中封装属性和方法。
5. 面向对象三大特征：封装、继承、多态。
6. 封装：隐藏内部实现，对外提供接口。
7. 继承：代码复用，表达一般与特殊关系。
8. 多态：同一操作，不同对象，不同结果。
9. 从案例中找类：名词找类，特征找属性，动作找方法。

<div id="section-19" class="note-anchor"></div>

#### 最可能考法

1. 简答题：类和对象的关系。
2. 简答题：封装、继承、多态。
3. 对比题：面向过程和面向对象区别。
4. 案例题：从系统中识别类、属性、方法。
5. 类图前置题：哪些是类，哪些是属性。

<div id="section-20" class="note-anchor"></div>

#### 速背口诀

```text
面向过程看步骤
面向对象看对象
类是模板，对象是实例
封装保安全，继承促复用，多态增灵活
```

### 4. [UML 建模与常考图说明](/notes/semester/software-engineering/topics/uml-%E5%BB%BA%E6%A8%A1%E4%B8%8E%E5%B8%B8%E8%80%83%E5%9B%BE%E8%AF%B4%E6%98%8E/)

<div id="section-22" class="note-anchor"></div>

#### 复习优先级：P0

<div id="section-23" class="note-anchor"></div>

#### 必背内容

1. UML = 统一建模语言，不是一张图，而是一套图。
2. 用例图：谁使用系统，系统有什么功能。
3. 类图：系统有哪些类、属性、方法、关系。
4. 时序图：对象之间按时间顺序传递消息。
5. 活动图：业务流程怎么走。
6. 状态图：对象状态如何变化。
7. 协作图：对象如何协作。
8. DFD：数据从哪来，到哪去，怎么处理。
9. ER图：实体、属性、关系。
10. DFD和ER图严格来说不是UML图。

<div id="section-24" class="note-anchor"></div>

#### 图题核心表

| 图 | 回答的问题 | 高频关键词 |
|---|---|---|
| 用例图 | 谁用系统，系统有什么功能 | 参与者、用例、系统边界、include、extend |
| 类图 | 有哪些类、属性、方法、关系 | 关联、依赖、继承、聚合、组合 |
| 时序图 | 对象如何按时间发消息 | 对象、生命线、消息、激活期 |
| 活动图 | 流程怎么走 | 开始、活动、判断、结束 |
| 状态图 | 状态怎么变 | 状态、事件、转移 |
| DFD | 数据怎么流动 | 外部实体、处理、数据流、数据存储 |
| ER图 | 数据对象有什么关系 | 实体、属性、联系 |

<div id="section-25" class="note-anchor"></div>

#### 最可能考法

1. 选择题：参与者与用例之间是什么关系。
2. 判断题：DFD是不是UML。
3. 简答题：UML建模对程序员的好处。
4. 简答题：用例图、类图、时序图作用。
5. 综合题：给案例判断应该用什么图。
6. 画图题：用例图、类图、时序图最优先。

<div id="section-26" class="note-anchor"></div>

#### 速背口诀

```text
用户功能用用例
类和关系用类图
消息顺序用时序
业务流程用活动
状态变化用状态
数据流动用DFD
实体关系用ER
```

### 5. [界面设计](/notes/semester/software-engineering/topics/%E7%95%8C%E9%9D%A2%E8%AE%BE%E8%AE%A1/)

<div id="section-28" class="note-anchor"></div>

#### 复习优先级：P2

<div id="section-29" class="note-anchor"></div>

#### 必背内容

1. 界面设计核心：以用户为中心。
2. 界面设计不是只追求好看，更重要是方便用户完成任务。

4. 界面优化：易学性、易用性、交互性、健壮性。

2. 简答题：界面设计过程。
3. 案例改错题：指出界面存在的问题。
4. 判断题：界面设计是否只是美观。

入口、主界面、表单、操作、响应

### 6. [软件测试基础与黑盒测试](/notes/semester/software-engineering/topics/%E8%BD%AF%E4%BB%B6%E6%B5%8B%E8%AF%95%E5%9F%BA%E7%A1%80%E4%B8%8E%E9%BB%91%E7%9B%92%E6%B5%8B%E8%AF%95/)

<div id="section-33" class="note-anchor"></div>

#### 复习优先级：P0

<div id="section-34" class="note-anchor"></div>

#### 必背内容

1. 软件测试目的：发现错误，验证是否满足需求，找实际输出与预期输出差异。
2. 软件测试不能证明软件完全没有错误。
3. 软件测试以需求为中心。
4. 用户可以参与验收测试，但不能替代开发方完整测试。
5. 测试种类：人工动态测试、人工静态测试、自动化测试。
6. 测试流程：计划、设计、实施、评估。
7. 黑盒测试：不看代码，只看输入输出。
8. 黑盒测试原理：程序是输入域到输出域的映射。
9. 测试方法评价标准：覆盖高、数量少、冗余低、定位高、复杂度低。

<div id="section-35" class="note-anchor"></div>

#### 最可能考法

1. 简答题：软件测试目的。
2. 判断题：软件测试是否能证明没有错误。
3. 简答题：为什么测试不能完全交给用户。
4. 简答题：测试流程。
5. 简答题：黑盒测试定义和优势。
6. 案例题：根据需求说明黑盒测试思路。

<div id="section-36" class="note-anchor"></div>

#### 速背口诀

```text
测试目的：找错、验需求、比差异
测试流程：计划、设计、实施、评估
黑盒测试：只看输入输出，不看内部结构
```

### 7. [边界值分析方法](/notes/semester/software-engineering/topics/%E8%BE%B9%E7%95%8C%E5%80%BC%E5%88%86%E6%9E%90%E6%96%B9%E6%B3%95/)

#### 复习优先级：P0

<div id="section-39" class="note-anchor"></div>

#### 必背内容

1. 边界值分析属于黑盒测试。
2. 边界值分析重点测边界和边界附近。
3. 缺陷常出现在最大、最小、第一、最后、刚好越界处。
4. 边界点：可能导致系统内部处理机制变化的点。
5. 典型取值：min-、min、min+、nom、max-、max、max+。
6. 单缺陷边界值测试公式：6n+1。
7. 一般最坏情况测试公式：5^n。
8. 健壮性最坏情况测试公式：7^n。
9. δ不固定，整数常取1，金额可取0.01，日期可取1天。

<div id="section-40" class="note-anchor"></div>

#### 最可能考法

1. 简答题：为什么采用边界值方法。
2. 概念题：什么是边界点。
3. 计算题：6n+1、5^n、7^n。
4. 案例题：给范围选测试数据。
5. 比较题：单缺陷和多缺陷边界值测试。

<div id="section-41" class="note-anchor"></div>

#### 公式速背

```text
单缺陷边界值测试：6n+1
一般最坏情况测试：5^n
健壮性最坏情况测试：7^n
```

<div id="section-42" class="note-anchor"></div>

#### 数据速背

```text
整数范围 18～60：
17、18、19、正常值、59、60、61
```

<div id="section-43" class="note-anchor"></div>

### 8. [需求规格说明书与综合实战](/notes/semester/software-engineering/topics/%E9%9C%80%E6%B1%82%E8%A7%84%E6%A0%BC%E8%AF%B4%E6%98%8E%E4%B9%A6%E4%B8%8E%E7%BB%BC%E5%90%88%E5%AE%9E%E6%88%98/)

<div id="section-44" class="note-anchor"></div>

#### 复习优先级：P0

<div id="section-45" class="note-anchor"></div>

#### 必背内容

1. SRS = Software Requirements Specification。
2. SRS写系统“做什么”，不是写“怎么做”。
3. SRS主要包含功能需求和非功能需求。
4. SRS是沟通、设计、编码、测试、验收和维护依据。
5. 功能需求句式：系统应支持……
6. 非功能需求要量化。
7. 综合题步骤：找角色、找功能、找非功能、找数据、写验收标准。
8. SRS可以转用例图、类图、时序图和测试用例。

<div id="section-46" class="note-anchor"></div>

#### 最可能考法

1. 简答题：SRS作用。
2. 简答题：功能需求和非功能需求区别。
3. 案例题：提取用户角色、功能需求、非功能需求。
4. 综合题：写需求规格说明书片段。
5. 延伸题：根据SRS画用例图或设计测试用例。

<div id="section-47" class="note-anchor"></div>

#### 速背口诀

```text
读题干 → 找角色 → 找动词功能 → 找质量要求 → 找数据对象 → 写成SRS格式
```

## 八、我的补充建议

<div id="section-79" class="note-anchor"></div>

### 1. 不要平均用力

这门课最容易出现的问题是：知识点很多，但考试真正高频的是“模型、需求、UML、测试”。

所以优先级要这样放：

```text
UML / 需求 / 测试 / 边界值 / SRS > 过程模型 > 面向对象 > 界面设计
```

---

<div id="section-80" class="note-anchor"></div>

### 2. 大题优先背模板，不要死背长段

比如“SRS作用”这种题，你不需要逐字背。

只要背核心词：

```text
沟通、设计、编码、测试、验收、维护
```

然后考试时扩成完整句子。

---

<div id="section-81" class="note-anchor"></div>

### 3. 案例题一定要按结构写

不要一整段乱写。

推荐结构：

```text
用户角色：
1.
2.

功能需求：
1.
2.

非功能需求：
1.
2.

数据需求：
1.
2.

验收标准：
1.
2.
```

结构清楚，比内容散乱更容易得分。

---

<div id="section-82" class="note-anchor"></div>

### 4. 图题先拿“元素分”

就算不会画得很完美，也要保证基本元素正确：

1. 用例图：参与者、用例、系统边界、关联线。
2. 类图：类名、属性、方法、关系。
3. 时序图：对象、生命线、消息、激活期。

老师一般不会只看美观，会看你有没有抓住关键元素。

---

<div id="section-83" class="note-anchor"></div>

### 5. 边界值题先写公式，再代入

例如题目说3个变量，单缺陷边界值：

```text
n = 3
6n + 1 = 6 × 3 + 1 = 19
```

不要只写答案，过程写出来更稳。

---

<div id="section-84" class="note-anchor"></div>

### 6. 判断题遇到绝对词要小心

看到这些词要谨慎：

```text
一定、只能、完全、不需要、必须全部、永远、绝不
```

例如：

```text
软件测试可以证明软件完全没有错误。
```

错。

```text
一个用例只能对应一个参与者。
```

错。

```text
用户可以完全替代开发方完成测试。
```

错。

---

<div id="section-85" class="note-anchor"></div>

### 7. 最后检查清单

考前问自己：

1. 我能不能说出5种过程模型适用场景？
2. 我能不能区分功能需求和非功能需求？
3. 我能不能从案例中找角色和功能？
4. 我能不能解释用例图、类图、时序图？
5. 我能不能背出测试流程？
6. 我能不能解释黑盒测试？
7. 我能不能算6n+1、5^n、7^n？
8. 我能不能写一个SRS片段？

如果这8个都能答，基本大题不会空。
