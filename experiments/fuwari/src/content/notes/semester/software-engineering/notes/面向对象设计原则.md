> 设计原则是**设计模式**的理论基础。SOLID 五大原则经常出现在选择题和简答题中。

<div id="section-1" class="note-anchor"></div>

## 一、三大核心设计策略（老师课件）

| 策略 | 说明 |
|------|------|
| **设计接口** | 通过公共接口耦合，不依赖具体实现 |
| **发现变化并封装** | 隔离可能变化的部分，变化时不影响其他部分 |
| **先考虑聚合，后考虑继承** | 组合/聚合（has-a）优于继承（is-a） |

<div id="section-2" class="note-anchor"></div>

## 二、SOLID 五大原则（必考）

| 字母 | 原则 | 全称 | 一句话解释 |
|------|------|------|------------|
| **S** | 单一职责原则 | Single Responsibility Principle | 一个类**只负责一件事**，只有一个修改的理由 |
| **O** | 开闭原则 | Open-Closed Principle | **对扩展开放，对修改关闭** — 新增功能不修改原有代码 |
| **L** | 里氏替换原则 | Liskov Substitution Principle | 子类必须能**完全替换**父类而不影响程序正确性 |
| **I** | 接口隔离原则 | Interface Segregation Principle | 多个**专用接口**优于一个大而全的接口 |
| **D** | 依赖倒置原则 | Dependency Inversion Principle | 依赖**抽象**（接口），而非**具体实现** |

<div id="section-3" class="note-anchor"></div>

### 各原则详解

<div id="section-4" class="note-anchor"></div>

#### S — 单一职责（与"高内聚"直接对应）

```java
// ❌ 违反 SRP：一个类做两件事
class Employee {
    void calculatePay() { ... }    // 算工资
    void saveToDatabase() { ... }  // 存数据库
}

// ✅ 符合 SRP：各自独立
class PayCalculator { void calculatePay(Employee e) { ... } }
class EmployeeRepository { void save(Employee e) { ... } }
```

<div id="section-5" class="note-anchor"></div>

#### O — 开闭原则

```java
// ❌ 违反 OCP：每种形状都要改 if-else
double area(Shape s) {
    if (s.type == "circle") return π*r*r;
    else if (s.type == "rect") return w*h;
}

// ✅ 符合 OCP：新增形状只需新增子类，不修改原有代码
interface Shape { double area(); }
class Circle implements Shape { double area() { return π*r*r; } }
class Rectangle implements Shape { double area() { return w*h; } }
```

<div id="section-6" class="note-anchor"></div>

#### L — 里氏替换（继承的正确使用标准）

> 违反 LSP 的经典例子：正方形是矩形的子类 — `Square extends Rectangle`。
> 当设置 `width` 时，正方形也会改变 `height`，这与矩形行为不同，替换后会出错。

```
判断 LSP 是否满足：父类引用指向子类对象时，行为是否符合预期？
```

<div id="section-7" class="note-anchor"></div>

#### I — 接口隔离

```java
// ❌ 违反 ISP：胖接口
interface Worker { void work(); void eat(); void sleep(); }
class Robot implements Worker {
    void eat() { /* ??? 机器人不需要吃饭 */ }
}

// ✅ 符合 ISP：拆分为专用接口
interface Workable { void work(); }
interface Eatable { void eat(); }
class Robot implements Workable { void work() { ... } }
```

<div id="section-8" class="note-anchor"></div>

#### D — 依赖倒置

```java
// ❌ 违反 DIP：高层依赖低层具体类
class NotificationService {
    private EmailSender sender = new EmailSender();  // 紧耦合
}

// ✅ 符合 DIP：依赖抽象接口
interface MessageSender { void send(String msg); }
class NotificationService {
    private MessageSender sender;  // 可注入 EmailSender 或 SmsSender
}
```

## 三、其他重要设计原则

| 原则 | 说明 |
|------|------|
| **迪米特法则（LoD）** | "最少知识原则" — 一个对象应尽可能少地了解其他对象。只与直接朋友通信，不和"朋友的朋友"打交道。 |
| **组合/聚合优先原则** | "优先使用 has-a（组合/聚合），而不是 is-a（继承）"。组合更加灵活、松耦合。 |
| **封装变化原则** | 找出应用中可能变化之处，把它们独立出来，与固定不变的代码分离。 |

## 四、可重用性（Reusability）

> 老师课件中强调的设计目标。

| 策略 | 说明 |
|------|------|
| **使用已有的类** | 充分利用环境类库 + 相似业务类 |
| **设计可重用的类** | 创建新类时考虑通用性，使其可被其他项目复用 |
| **框架（Framework）** | 一组可用于不同应用的类的集合（如 Java API、Spring Framework） |

> **重用的成本效益**：设计可重用软件的前期成本高于普通软件，但随着重用次数增加，分摊成本持续降低。

<div id="section-11" class="note-anchor"></div>

### 框架的使用方式

| 方式 | 说明 |
|------|------|
| 通过**继承**关联使用 | 继承框架基类 |
| 通过**聚合**关联使用 | 持有框架对象作为成员 |

## 期末考试常见考点

<div id="section-13" class="note-anchor"></div>

### 简答题

> **Q：简述面向对象设计的 SOLID 原则。**
>
> **答题要点**：
> 1. S（单一职责）：一个类只负责一件事
> 2. O（开闭原则）：对扩展开放，对修改关闭
> 3. L（里氏替换）：子类必须能完全替换父类
> 4. I（接口隔离）：多个专用接口优于一个胖接口
> 5. D（依赖倒置）：依赖抽象而非具体实现

<div id="section-14" class="note-anchor"></div>

### 选择题

> 以下哪个原则体现了"对扩展开放，对修改关闭"？
> A. 单一职责 | B. 开闭原则 | C. 接口隔离 | D. 依赖倒置
>
> **答案：B** — 开闭原则（OCP）
