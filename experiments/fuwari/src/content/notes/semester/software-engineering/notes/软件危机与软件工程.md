## 一、软件危机

<div id="section-2" class="note-anchor"></div>

### 定义

> 软件危机（Software Crisis）是指计算机软件开发和维护过程中遇到的一系列严重问题，导致项目费用超支、进度失控、质量低劣、维护困难。

<div id="section-3" class="note-anchor"></div>

### 典型表现

| 表现 | 说明 |
|------|------|
| 成本超支 | 项目实际费用远超预算 |
| 进度失控 | 无法按计划时间交付 |
| 质量不可靠 | 软件频繁出错、崩溃 |
| 需求不符 | 交付的软件与用户真实需求不一致 |
| 维护困难 | 代码难以理解、修改，维护成本极高 |
| 缺乏文档 | 开发过程缺少必要的文档记录 |
| 生产率低 | 开发效率跟不上硬件发展速度 |

<div id="section-4" class="note-anchor"></div>

### 产生原因

| 主观原因 | 客观原因 |
|----------|----------|
| 忽视需求分析（急于编码） | 软件是逻辑实体，缺乏可见性 |
| 忽视软件维护（只重开发） | 软件规模与复杂性呈指数增长 |
| 缺乏工程化方法（手工作坊式） | 需求频繁变更 |
| 轻视文档作用 | 开发工具与方法落后 |

<div id="section-5" class="note-anchor"></div>

### 解决途径

> 引入**软件工程**的系统化、工程化方法，将软件开发从"手工作坊"提升为"工程化生产"。

## 二、软件工程

<div id="section-7" class="note-anchor"></div>

### 定义

> 软件工程（Software Engineering）是运用系统的、规范的、可量化的方法，来开发、运行和维护软件的工程学科。

**Fritz Bauer 定义（NATO 会议，1968）**：软件工程是为了经济地获得可靠的且能在实际机器上高效运行的软件，而建立和使用的好的工程原则。

**IEEE 定义**：将系统化的、规范的、可量化的方法应用于软件的开发、运行和维护，即工程化应用到软件上。

<div id="section-8" class="note-anchor"></div>

### 软件工程的本质

- 将**工程化思想**引入软件开发全流程
- 研究的核心问题是**质量**、**成本**和**进度**三者的平衡

<div id="section-9" class="note-anchor"></div>

### 软件工程的三个要素

| 要素 | 说明 |
|------|------|
| **过程（Process）** | 软件开发的活动序列（生命周期模型） |
| **方法（Method）** | 完成各阶段任务的技术手段（需求分析、设计、测试方法） |
| **工具（Tool）** | 支持方法和过程的自动化/半自动化工具（IDE、测试工具、版本管理） |

## 三、软件的定义与特性

<div id="section-11" class="note-anchor"></div>

### 软件 = 程序 + 数据 + 文档

| 组成部分 | 说明 |
|----------|------|
| 程序 | 可执行的代码指令 |
| 数据 | 程序运行时所需的数据结构及初始数据 |
| 文档 | 开发、使用和维护过程中的图文资料 |

<div id="section-12" class="note-anchor"></div>

### 软件的特性（与硬件对比）

| 特性 | 说明 |
|------|------|
| 逻辑性 | 软件是逻辑实体，不是物理实体 |
| 无磨损性 | 软件不会像硬件一样老化磨损，但会退化（维护引入缺陷） |
| 可复制性 | 边际复制成本几乎为零 |
| 定制性 | 大多数软件是定制的，而非由标准组件组装 |
| 复杂性 | 状态空间巨大，难以穷尽测试 |

## 四、软件工程的 7 个基本原则（了解）

| 原则 | 说明 |
|------|------|
| 1. 分阶段的生命周期计划 | 按阶段进行严格计划管理 |
| 2. 坚持阶段评审 | 每个阶段结束必须进行严格评审 |
| 3. 实行严格的产品控制 | 基线化 + 变更控制 |
| 4. 采用现代程序设计技术 | 面向对象、设计模式等 |
| 5. 结果应当能清楚地审查 | 可度量、可验证的交付物 |
| 6. 开发小组小而精 | 人员素质 > 人员数量 |
| 7. 承认不断改进软件工程实践的必要性 | CMM 持续改进 |

## 期末考试常见考点

<div id="section-15" class="note-anchor"></div>

### 简答题

> **Q1：什么是软件危机？它有哪些表现？产生的原因是什么？**
>
> **答题要点**：
> 1. 定义：软件开发和维护中遇到的严重问题
> 2. 表现（答 3-4 点）：成本超支、进度失控、质量不保、需求不符、维护困难
> 3. 原因：主观——忽视需求分析和维护、缺乏工程化方法、轻视文档；客观——软件是逻辑实体缺乏可见性、规模复杂度高
> 4. 解决：引入软件工程的系统化方法

> **Q2：什么是软件工程？它包含哪三个基本要素？**
>
> **答题要点**：
> 1. 定义：运用系统化、规范化、可量化的方法开发、运行和维护软件
> 2. 三要素：**过程**（活动序列/生命周期）、**方法**（技术手段）、**工具**（自动化支持）
