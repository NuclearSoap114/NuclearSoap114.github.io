## 软件工程基础

| 术语 | 英文 | 定义 |
|------|------|------|
| **软件** | Software | 程序 + 数据 + 文档的完整集合 |
| **软件工程** | Software Engineering | 运用系统化、规范化、可量化的方法来开发、运行和维护软件 |
| **软件危机** | Software Crisis | 软件开发和维护中遇到的成本、进度、质量方面的严重问题 |
| **软件生命周期** | Software Life Cycle | 软件从定义→开发→运行维护→退役的全过程，包含 7 个阶段 |
| **CMM** | Capability Maturity Model | 软件能力成熟度模型，分为 5 个等级（初始→可重复→已定义→量化管理→优化） |

## 开发模型

| 术语 | 英文 | 定义 |
|------|------|------|
| **瀑布模型** | Waterfall Model | 线性顺序开发模型，阶段间不能回溯，文档驱动 |
| **V 模型** | V-Model | 强调每个开发阶段对应一个测试阶段的模型 |
| **原型模型** | Prototype Model | 快速构建样机以澄清需求，用户试用以获取反馈 |
| **增量模型** | Incremental Model | 将系统划分为多个增量，每次交付一个可工作的子集 |
| **螺旋模型** | Spiral Model | 每轮包含"风险分析—工程实施—评审—规划"四象限的迭代模型 |
| **敏捷开发** | Agile Development | 以迭代增量为核心，强调个人交互、工作软件、客户协作、响应变化 |
| **Scrum** | Scrum | 敏捷开发的主流框架，包含 Sprint、站会、回顾等活动 |
| **RUP** | Rational Unified Process | IBM 的统一过程框架，用例驱动、以架构为中心、迭代增量 |
| **XP** | eXtreme Programming | 极限编程，强调结对编程、TDD、持续集成等工程最佳实践 |

## 需求工程

| 术语 | 英文 | 定义 |
|------|------|------|
| **功能需求** | Functional Requirement | 系统必须提供的具体功能或行为 |
| **非功能需求** | Non-functional Requirement | 系统的性能、安全、可用性等质量约束 |
| **SRS** | Software Requirements Specification | 软件需求规格说明书，描述系统"做什么"的正式文档 |
| **需求获取** | Requirements Elicitation | 通过访谈、问卷、观摩等方式从干系人处收集需求 |
| **需求跟踪矩阵** | Requirements Traceability Matrix (RTM) | 建立需求与设计、编码、测试之间的双向追踪关系 |
| **用例** | Use Case | 从用户角度描述系统功能的一个场景/单元 |
| **参与者** | Actor | 与系统交互的外部实体（人或外部系统） |

## 面向对象

| 术语 | 英文 | 定义 |
|------|------|------|
| **类** | Class | 一组具有相同属性和操作的对象的抽象描述/模板 |
| **对象** | Object | 类的实例，真实存在的具体实体 |
| **封装** | Encapsulation | 将数据与操作封装在类中，隐藏内部实现细节 |
| **继承** | Inheritance | 子类继承父类属性和方法（is-a 关系） |
| **多态** | Polymorphism | 同一操作在不同对象上表现为不同行为 |
| **消息** | Message | 对象间通信的方式 |

## UML 图

| 术语 | 英文 | 定义 |
|------|------|------|
| **UML** | Unified Modeling Language | 统一建模语言，面向对象系统建模的标准可视化工具 |
| **用例图** | Use Case Diagram | 从用户视角描述系统功能的图（参与者+用例） |
| **类图** | Class Diagram | 描述类及其之间关系的静态结构图 |
| **顺序图** | Sequence Diagram | 按时间顺序描述对象间消息交互的动态图 |
| **状态图** | State Machine Diagram | 描述一个对象生命周期中状态及其转移的动态图 |
| **活动图** | Activity Diagram | 描述业务流程或算法控制流的动态图 |
| **泛化** | Generalization | 类之间的一般-特殊关系（is-a），即继承 |
| **聚合** | Aggregation | 弱整体-部分关系（空心菱形），部分可独立存在 |
| **组合** | Composition | 强整体-部分关系（实心菱形），部分不可独立存在 |
| **依赖** | Dependency | 一个类临时使用另一个类的关系（最弱的关系） |

## 软件设计

| 术语 | 英文 | 定义 |
|------|------|------|
| **耦合** | Coupling | 模块间相互依赖的程度，越低越好 |
| **内聚** | Cohesion | 模块内部各元素相互关联的紧密程度，越高越好 |
| **数据耦合** | Data Coupling | 仅通过传递简单参数交换数据（最好的耦合） |
| **功能内聚** | Functional Cohesion | 模块内所有元素共同完成且只完成单一功能（最好的内聚） |
| **SOLID** | SOLID Principles | 面向对象设计的 5 大基本原则（SRP/OCP/LSP/ISP/DIP） |
| **设计模式** | Design Pattern | 被反复使用的、经过验证的面向对象设计经验的总结 |
| **Singleton** | Singleton Pattern | 确保一个类只有一个实例的设计模式 |
| **重构** | Refactoring | 在不改变外部行为的前提下，改善代码内部结构 |

## 软件测试

| 术语 | 英文 | 定义 |
|------|------|------|
| **白盒测试** | White-box Testing | 了解程序内部结构，基于代码进行测试 |
| **黑盒测试** | Black-box Testing | 不了解内部结构，只基于输入/输出进行测试 |
| **等价类划分** | Equivalence Partitioning | 将输入域划分为等价类，每类取代表值进行测试 |
| **边界值分析** | Boundary Value Analysis | 重点测试输入域边界及边界附近的数据 |
| **语句覆盖** | Statement Coverage | 每条可执行语句至少执行一次（最弱的覆盖标准） |
| **判定覆盖** | Branch Coverage | 每个判定的真/假分支各执行一次 |
| **条件覆盖** | Condition Coverage | 每个条件的真/假各取一次 |
| **路径覆盖** | Path Coverage | 程序中每条可能的路径至少执行一次（最强） |
| **环形复杂度** | Cyclomatic Complexity | 度量程序独立路径数量，V(G)=E-N+2=P+1 |
| **单元测试** | Unit Testing | 对单个函数/模块进行测试 |
| **集成测试** | Integration Testing | 对模块间接口进行测试 |
| **系统测试** | System Testing | 对整个系统进行端到端测试 |
| **验收测试** | Acceptance Testing | 用户参与，确认系统满足需求的测试 |
| **回归测试** | Regression Testing | 修改后重新运行已有测试，确保没有引入新缺陷 |

## 软件维护

| 术语 | 英文 | 定义 |
|------|------|------|
| **改正性维护** | Corrective Maintenance | 修复发现的缺陷和错误 |
| **适应性维护** | Adaptive Maintenance | 为适应外部环境变化（OS/硬件/法规）而修改 |
| **完善性维护** | Perfective Maintenance | 增加新功能、改进性能（占比最大，约 50%） |
| **预防性维护** | Preventive Maintenance | 主动修改以预防未来可能的故障 |
| **逆向工程** | Reverse Engineering | 从已有代码中提取设计信息 |
| **再工程** | Re-engineering | 逆向工程 + 重新设计 + 重新实现 |
