## 一、类的基本表示

```
 ┌──────────────────┐
 │    类名          │  ← 抽象类名用斜体
 │  （ClassName）    │
 ├──────────────────┤
 │ - privateAttr    │  ← 属性（可见性 + 名称 : 类型）
 │ # protectedAttr  │
 │ + publicAttr     │
 ├──────────────────┤
 │ + method1()      │  ← 方法（可见性 + 名称(参数) : 返回类型）
 │ - method2()      │
 └──────────────────┘
```

<div id="section-2" class="note-anchor"></div>

### 可见性符号

| 符号 | 可见性 | 说明 |
|------|--------|------|
| `+` | public | 所有类均可访问 |
| `-` | private | 仅本类内部可访问 |
| `#` | protected | 本类 + 子类可访问 |
| `~` | package | 同包内的类可访问（不常考） |

> 🔑 **抽象类**：类名用*斜体*表示；**接口**：类名上方标注 `<<interface>>`

## 二、六种关系（必考排序 + 辨析）

> 按**关系强度**从强到弱排列

| 强度 | 关系 | UML 符号 | 说明 | 经典例子 |
|------|------|----------|------|----------|
| 最强 | **泛化**（Generalization） | 实线 + 空心三角 ▶ → 指向父类 | is-a 关系 | 狗 → 动物 |
| 强 | **实现**（Realization） | 虚线 + 空心三角 ▶ → 指向接口 | 类实现接口 | ArrayList → List |
| 强 | **组合**（Composition） | 实心菱形 ◆—— → 指向整体 | 强整体-部分，部分不能独立存在 | 手 → 人 |
| 中 | **聚合**（Aggregation） | 空心菱形 ◇—— → 指向整体 | 弱整体-部分，部分可独立存在 | 球队 → 球员 |
| 弱 | **关联**（Association） | 实线 —— | 平级的"使用/拥有"关系 | 司机 → 汽车 |
| 最弱 | **依赖**（Dependency） | 虚线 + 开放箭头 - - -▷ → | 临时使用，作为参数/局部变量 | 方法内 new 临时对象 |

<div id="section-4" class="note-anchor"></div>

### 聚合 vs 组合（最高频辨析题 ）

| 维度 | 组合（Composition） | 聚合（Aggregation） |
|------|---------------------|---------------------|
| **符号** | 实心菱形 ◆ | 空心菱形 ◇ |
| **整体-部分强度** | 强（同生共死） | 弱（可分离） |
| **部分能否独立存在** | ❌ 不能（整体删除，部分也删除） | ✅ 可以 |
| **部分能否被共享** | ❌ 不能被多个整体共享 | ✅ 可以属于多个整体 |
| **经典例子** | House → Room（房子拆了房间也没了） | University → Department（大学解散了院系仍存在） |
| **类图代码** | 部分在整体构造函数中创建 | 部分通过 setter 或外部注入 |

> 🧠 **记忆**：空心 = "空" = 可分 = 聚合；实心 = "实" = 不可分 = 组合

## 三、多重性（基数）

| 表示 | 含义 |
|------|------|
| `1` | 恰好 1 个 |
| `0..1` | 0 或 1 个 |
| `*` 或 `0..*` | 0 或多 |
| `1..*` | 至少 1 个 |
| `n` | 恰好 n 个 |
| `n..m` | n 到 m 个 |

### 分析阶段的三种类（MVC 思想的源头）

| 类型 | 英文 | 说明 | 示例 |
|------|------|------|------|
| **实体类** | Entity Class | 存储和管理系统核心数据 | User、Order、Product |

### 画图题

> **Q：画出"学生-课程-教师"系统的类图。**
> - 学生有学号、姓名，可以选课
> - 教师有工号、姓名，可以授课
> - 课程有课程号、课程名、学分
> - 学生和课程是多对多关系
> - 教师和课程是一对多关系

**📝 参考答案（文字描述类图结构，考试时在纸上画）**：

```
┌──────────────┐           ┌──────────────┐           ┌──────────────┐
│    Student   │           │    Course    │           │   Teacher    │
├──────────────┤           ├──────────────┤           ├──────────────┤
│ - id: String │   *   *   │ - cid: String│  1  1..* │ - tid: String│
│ - name: Str  │←─────────→│ - name: Str  │←─────────→│ - name: Str  │
├──────────────┤           │ - credit:Int │           ├──────────────┤
│ + enroll()   │           ├──────────────┤           │ + teach()    │
└──────────────┘           │ + addStudent │           └──────────────┘
                           │ + assignTchr │
                           └──────────────┘
```

**关系分析**：
| 关系 | 类A — 类B | 多重性 | UML 符号 | 说明 |
|------|-----------|--------|----------|------|
| 关联 | Student — Course | `* —— *` | 实线 | 学生可选多门课，一门课可被多个学生选 |
| 关联 | Teacher — Course | `1 —— 1..*` | 实线 | 一个教师教多门课，一门课只能由一个教师教 |
| 这个例子中**没有**聚合/组合关系 | — | — | — | Course 不是 Student 的"部分"，只是"被选" |

### 再来一题：网上购物系统

> **Q**：画出"订单-顾客-订单项-商品"的关系类图。
> - Customer 有 id, name, address
> - Order 有 id, date, total
> - OrderItem 有 quantity, subtotal
> - Product 有 id, name, price
> - 一个 Customer 可以有多个 Order
> - 一个 Order 包含多个 OrderItem
> - 一个 OrderItem 对应一个 Product
> - **关键**：OrderItem 是 Order 的一部分，Order 删除时 OrderItem 也应删除

**📝 参考答案**：

```
┌──────────┐   1   *   ┌──────────┐   1   *   ┌───────────┐   *   1  ┌──────────┐
│ Customer │←──────────│  Order   │◆──────────│ OrderItem │─────────→│ Product  │
├──────────┤           ├──────────┤           ├───────────┤          ├──────────┤
│ - id     │           │ - id     │           │ - quantity│          │ - id     │
│ - name   │           │ - date   │           │ - subtotal│          │ - name   │
│ - address│           │ - total  │           └───────────┘          │ - price  │
└──────────┘           └──────────┘                                 └──────────┘
                                                          
  关联（实线）         组合（实心菱形◆）                 关联（实线）
```

**关系辨析【本题精华】**：
| 关系 | 符号 | 为什么不用别的？ |
|------|------|-----------------|
| Customer — Order：**关联** | 实线 `1 —— *` | Order 可以独立于 Customer 存在吗？可以（如历史订单保存），所以不是组合 |
| Order — OrderItem：**组合** | 实心菱形 `◆—— 1 —— *` | OrderItem 离开了 Order 就没意义（不可能是"漂浮的订单项"），订单取消则订单项也删除 → 强整体-部分 |
| OrderItem — Product：**关联** | 实线 `* —— 1` | Product 不是 OrderItem 的"部分"，只是引用关系

### 简答题

> **Q：面向对象类图中的"聚合"和"组合"有什么区别？各举一个例子。**
>
> **答题要点**：
> 1. 组合（实心菱形）：强整体-部分，部分不可独立存在，不可被多个整体共享。例：人——手（手离开人就失去意义）。
> 2. 聚合（空心菱形）：弱整体-部分，部分可独立存在。例：大学——院系（院系可以从一个大学转移到另一个）。
> 3. 符号区分：组合是实心菱形，聚合是空心菱形。
