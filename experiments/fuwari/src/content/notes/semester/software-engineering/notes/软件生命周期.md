## 一、软件生命周期的 7 个阶段

> 软件生命周期（Software Life Cycle）是指软件从**定义**到**开发**再到**运行维护**直到最终**退役**的全过程。

| 阶段 | 英文 | 核心任务 | 输出产物 |
|------|------|----------|----------|
| 1. 可行性研究 | Feasibility Study | 分析项目是否值得做、是否可行 | 可行性分析报告 |
| 2. 需求分析 | Requirements Analysis | 明确系统"做什么" | 需求规格说明书（SRS） |
| 3. 总体设计 | Preliminary Design | 系统架构、模块划分 | 概要设计说明书 |
| 4. 详细设计 | Detailed Design | 模块内部算法、数据结构 | 详细设计说明书 |
| 5. 编码实现 | Coding | 将设计翻译为程序代码 | 源程序 |
| 6. 测试 | Testing | 发现和修复缺陷 | 测试报告 |
| 7. 维护 | Maintenance | 修改完善、适应变化 | 维护记录 |

> **记忆口诀**：可 → 需 → 概 → 详 → 编 → 测 → 维

## 二、各阶段成本占比（了解）

| 阶段 | 占总成本约 |
|------|-----------|
| 需求分析 + 设计 | ~40% |
| 编码 | ~20% |
| 测试 | ~40% |
| **维护**（交付后） | **占总生命周期的 50%-70%** |

> 🔑 **高频考点**：软件维护是软件生命周期中**持续时间最长、成本最高**的阶段。

## 三、CMM 能力成熟度模型

> CMM（Capability Maturity Model），由卡内基·梅隆大学 SEI 提出，用于评估软件组织的过程能力水平。

| 等级 | 名称 | 特征 | 关键词 |
|------|------|------|--------|
| **Level 1** | 初始级（Initial） | 过程无序，成功依赖个人英雄主义 | 混乱、不可预测 |
| **Level 2** | 可重复级（Repeatable） | 有基本的项目管理过程，可跟踪成本/进度 | 项目级管理 |
| **Level 3** | 已定义级（Defined） | 过程已标准化、文档化，形成组织标准 | 组织级标准过程 |
| **Level 4** | 量化管理级（Managed） | 过程有量化度量与控制 | 度量、统计控制 |
| **Level 5** | 优化级（Optimizing） | 持续改进，预防缺陷 | 持续优化、新技术引入 |

> **记忆**：1 乱 → 2 管 → 3 定 → 4 量 → 5 优

<div id="section-4" class="note-anchor"></div>

### 各级行为特征辨析（常考选择题）

| 问题 | 对应等级 |
|------|----------|
| 项目成功靠某个程序员个人能力 | Level 1（初始级） |
| 有能力控制项目进度和成本 | Level 2（可重复级） |
| 整个组织使用统一的开发流程 | Level 3（已定义级） |
| 能度量代码缺陷密度、量化控制质量 | Level 4（量化管理级） |
| 自动化的缺陷预防、持续引进新技术 | Level 5（优化级） |

## 期末考试常见考点

<div id="section-6" class="note-anchor"></div>

### 简答题

> **Q：简述软件生命周期各阶段及其主要任务。**
>
> **答题要点**：按顺序列出 7 个阶段：
> 1. 可行性研究 → 分析是否可行
> 2. 需求分析 → 明确定义"做什么"
> 3. 总体设计 → 系统架构、模块划分
> 4. 详细设计 → 模块内部算法与数据结构
> 5. 编码实现 → 将设计翻译为代码
> 6. 测试 → 发现和修复缺陷
> 7. 维护 → 交付后的持续修改完善
>
> 并指出：维护阶段持续时间最长、成本最高。

### 填空题

> CMM 的五个等级从低到高依次是：\_\_\_\_ → \_\_\_\_ → \_\_\_\_ → \_\_\_\_ → \_\_\_\_
>
> **答案**：初始级 → 可重复级 → 已定义级 → 量化管理级 → 优化级
