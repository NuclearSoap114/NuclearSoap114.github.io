> 设计模式（Design Pattern）是**被反复使用的、经过验证的**面向对象设计经验的总结。

---

<div id="section-1" class="note-anchor"></div>

## 一、设计模式分类

> GoF（Gang of Four）提出了 23 种经典设计模式，分为三类。

| 分类 | 说明 | 常见模式 |
|------|------|----------|
| **创建型**（Creational） | 封装对象创建过程 | Singleton、Factory Method、Abstract Factory、Builder、Prototype |
| **结构型**（Structural） | 处理类/对象的组合 | Adapter、Decorator、Proxy、Facade、Bridge、Composite、Flyweight |
| **行为型**（Behavioral） | 描述类/对象之间的交互 | Observer、Strategy、Template Method、Command、Iterator、State、Chain of Responsibility |

## 二、五大高频模式（期末考试重点）

<div id="section-3" class="note-anchor"></div>

### 2.1 Singleton（单例模式）— 创建型

> **确保一个类只有一个实例**，并提供一个全局访问点。

| 要素 | 说明 |
|------|------|
| 构造方法 | `private`（防止外部 new） |
| 静态实例 | `private static` 持有唯一实例 |
| 获取方法 | `public static getInstance()` |

```java
class Singleton {
    private static Singleton instance;
    private Singleton() {}
    public static Singleton getInstance() {
        if (instance == null) instance = new Singleton();
        return instance;
    }
}
```

| 典型应用 |
|----------|
| 日志管理器、配置管理器、数据库连接池 |
| Java 标准库案例：`java.lang.Runtime.getRuntime()` |

---

<div id="section-4" class="note-anchor"></div>

### 2.2 Factory Method（工厂方法）— 创建型

> **将对象创建逻辑封装**起来，客户端不直接 `new`，而是调用工厂方法。

| 关键点 | 说明 |
|--------|------|
| 目的 | 解耦对象创建与使用 |
| 方式 | 定义创建对象的接口，让子类决定实例化哪个类 |

```java
interface Product { void use(); }
class ConcreteProductA implements Product { ... }
class ConcreteProductB implements Product { ... }

class Factory {
    Product create(String type) {
        if ("A".equals(type)) return new ConcreteProductA();
        if ("B".equals(type)) return new ConcreteProductB();
    }
}
```

| 典型应用 |
|----------|
| 支付处理器选择（支付宝/微信/银行卡） |
| 跨平台 UI 组件创建 |

---

<div id="section-5" class="note-anchor"></div>

### 2.3 Observer（观察者模式）— 行为型

> **一对多依赖关系**。当一个对象（Subject）状态变化时，所有依赖它的对象（Observer）都**自动收到通知并更新**。

| 角色 | 职责 |
|------|------|
| Subject（主题） | 维护观察者列表，状态变化时通知所有观察者 |
| Observer（观察者） | 定义更新接口，收到通知后更新自身 |

```java
interface Observer { void update(String message); }
class Subject {
    List<Observer> observers = new ArrayList<>();
    void attach(Observer o) { observers.add(o); }
    void notifyAll(String msg) {
        for (Observer o : observers) o.update(msg);
    }
}
```

| 典型应用 |
|----------|
| 股票行情实时推送、消息订阅/推送、UI 事件处理（Listener） |

---

<div id="section-6" class="note-anchor"></div>

### 2.4 Strategy（策略模式）— 行为型

> 定义一组**可互换的算法**，让客户端**运行时动态选择**使用哪个算法。

> 🔑 消除了冗长的 `if-else`/`switch` 链，符合**开闭原则**。

```java
interface SortStrategy { void sort(int[] data); }
class QuickSort implements SortStrategy { ... }
class MergeSort implements SortStrategy { ... }

class Context {
    SortStrategy strategy;
    void setStrategy(SortStrategy s) { this.strategy = s; }
    void execute(int[] data) { strategy.sort(data); }
}
```

| 典型应用 |
|----------|
| 支付方式切换（支付宝/微信/银行卡） |
| 运费计算（不同快递公司不同算法） |
| 排序算法动态选择 |

---

<div id="section-7" class="note-anchor"></div>

### 2.5 Decorator（装饰器模式）— 结构型

> **动态地**给对象添加额外职责，**不修改原有类**。比生成子类更灵活。

```java
interface Coffee { double cost(); }
class SimpleCoffee implements Coffee { public double cost() { return 10; } }

// 装饰器
class MilkDecorator implements Coffee {
    Coffee coffee;
    MilkDecorator(Coffee c) { this.coffee = c; }
    public double cost() { return coffee.cost() + 5; }  // + 牛奶价
}

// 使用
Coffee c = new SimpleCoffee();
c = new MilkDecorator(c);   // 加牛奶
c = new SugarDecorator(c);  // 再加糖，嵌套装饰
```

| 典型应用 |
|----------|
| Java I/O 流：`new BufferedInputStream(new DataInputStream(new FileInputStream("a.txt")))` |
| 文本格式化（加粗+斜体+下划线...可任意组合） |

## 三、模式关系总结表

| 模式 | 分类 | 一句话 | 什么时候用 |
|------|------|--------|------------|
| Singleton | 创建型 | 只能有一个实例 | 配置管理、日志、连接池 |
| Factory | 创建型 | 隐藏 new 的细节 | 根据类型创建不同对象 |
| Observer | 行为型 | 状态变化自动通知 | 消息推送、事件处理 |
| Strategy | 行为型 | 运行时换算法 | 多种支付、多种计费 |
| Decorator | 结构型 | 不断给对象加功能 | Java I/O、图层叠加 |

---

<div id="section-9" class="note-anchor"></div>

## 四、设计模式与设计原则的关系

| 设计模式 | 体现的原则 |
|----------|------------|
| Strategy | **开闭原则**（对扩展算法开放，不修改 Context） |
| Decorator | **开闭原则**（扩展功能不修改原类）+ **组合优先** |
| Observer | **依赖倒置**（依赖于抽象的 Observer 接口） |
| Factory | **依赖倒置**（依赖抽象产品接口而非具体类） |
| Singleton | **单一职责**（只负责管理自身实例） |

## 期末考试常见考点

<div id="section-11" class="note-anchor"></div>

### 简答题

> **Q：简述观察者模式（Observer）的核心思想及应用场景。**
>
> **答题要点**：
> 1. 定义对象间一对多的依赖关系。当一个对象（Subject）状态改变时，所有依赖它的观察者自动收到通知并更新。
> 2. 角色：Subject（维护观察者列表、通知）、Observer（更新接口）
> 3. 应用：股票通知、消息订阅、UI 事件处理

<div id="section-12" class="note-anchor"></div>

### 选择题

> Java I/O 库中的 `BufferedInputStream` 和 `DataInputStream` 使用了哪种设计模式？
> A. Singleton | B. Strategy | C. Decorator | D. Observer
>
> **答案：C — 装饰器模式**。通过嵌套包装来动态添加功能。

> 以下哪个模式属于创建型模式？
> A. Observer | B. Singleton | C. Strategy | D. Decorator
>
> **答案：B** — Singleton（单例）属于创建型模式。
