## 一、状态图（State Machine Diagram）

<div id="section-2" class="note-anchor"></div>

### 定义

> 描述一个特定**对象**在其生命周期中**所有可能的状态**，以及因**事件**触发的**状态间转移**。

> ⚠️ **不**是每个类都需要画状态图！只有那些**在不同状态下行为显著不同**的类才需要。如：订单、图书、ATM 会话。

<div id="section-3" class="note-anchor"></div>

### 核心元素

| 元素 | 符号 | 说明 |
|------|------|------|
| **状态** | 圆角矩形 | 对象生命周期中的一个条件/情况 |
| **初始状态** | 实心圆 ● | 状态机的起点 |
| **终态** | ○ 内含 ● | 状态机的终点 |
| **转移** | 带箭头实线 → | 从一个状态到另一个状态的变化 |
| **事件** | 标注在转移线上 | 引起状态变化的原因 |
| **条件（守卫）** | `[条件]` | 转移发生需要满足的条件 |
| **动作** | `/动作` | 转移发生时执行的操作 |

```
● → [空闲] ──借出事件──→ [借出]
         ←──归还事件──
         [超时]/发送提醒
            ↓
           ◎
```

<div id="section-4" class="note-anchor"></div>

### 转移语法

```
事件(参数) [守卫条件] / 动作
```

示例：`cancel [balance > 0] / refund()`

<div id="section-5" class="note-anchor"></div>

### 状态类型

| 类型 | 说明 | 示例 |
|------|------|------|
| **初始状态** | 对象的起始点 | ● |
| **中间状态** | 生命周期中的正常状态 | 空闲、借出、逾期 |
| **终态** | 对象的结束点 | ◎ |
| **组合状态** | 包含子状态的状态 | "借出"状态包含子状态"正常借出"和"逾期借出" |
| **并发状态** | 多个并行子状态同时进行 | 一个对象同时处于"在校"和"在职" |

<div id="section-6" class="note-anchor"></div>

### 事件类型

| 类型 | 语法 | 说明 |
|------|------|------|
| **调用事件** | 方法名 | 接收到方法调用 |
| **变化事件** | `when(条件)` | 条件变为真时触发 |
| **时间事件** | `after(时长)` 或 `when(绝对时间)` | 时间到达时触发 |

<div id="section-7" class="note-anchor"></div>

### 转移类型

| 类型 | 说明 |
|------|------|
| **自转移** | 状态不变，只是执行动作后回到自身 |
| **自动转移** | 无事件触发，当前状态动作完成后自动转移 |
| **条件转移** | 需要守卫条件满足才转移 |

## 二、活动图（Activity Diagram）

<div id="section-9" class="note-anchor"></div>

### 定义

> 描述**业务流程或算法**中活动到活动的**控制流**。

<div id="section-10" class="note-anchor"></div>

### 核心元素

| 元素 | 符号 | 说明 |
|------|------|------|
| **起始节点** | 实心圆 ● | 流程起点 |
| **活动节点** | 圆角长方形（两端弧线） | 一个原子操作/步骤 |
| **活动流** | 带箭头实线 → | 活动间的流转 |
| **判定节点** | 菱形 ◇ | 条件分支 |
| **分叉** | 粗横线 — | 并发开始，一个流分成多个并行流 |
| **汇合** | 粗横线 — | 并发结束，多个并行流合并为一个 |
| **泳道** | 纵向/横向分区 | 划分不同角色的职责区域 |
| **终节点** | ○ 内含 ● | 流程终点 |
| **对象流** | → | 表示对象在活动间的传递 |

```
● → [填写订单] → ◇ → [审核] ─┬→ [发货] → [验收] → ◎
                    对       对
                    ↓        ↓
               [驳回修改]    [退款]
```

<div id="section-11" class="note-anchor"></div>

### 分叉（Fork）与汇合（Join）

```
              ┌→ [活动A] ─┐
[活动1] → ─┬─┤           ├─ → ─ → [活动3]
              └→ [活动B] ─┘
             分叉          汇合
```

> 分叉后 A 和 B **并行执行**；汇合处必须**所有并行分支都到达**才能继续。

## 三、状态图 vs 活动图（必考辨析）

| 维度 | 状态图 | 活动图 |
|------|--------|--------|
| **描述对象** | **一个对象**的状态变化 | **多个对象/角色**间的活动流程 |
| **核心要素** | 状态、事件、转移 | 活动、控制流、分叉/汇合 |
| **关注点** | **对象如何响应事件**而改变状态 | **业务流程**如何一步步执行 |
| **典型应用** | 订单生命周期、图书状态 | 审批流程、算法流程、工作流 |
| **泳道** | 无 | 有（划分不同角色职责） |
| **并发** | 并发状态 | 分叉/汇合 |

> 🧠 **一句话区别**：状态图 = "一个对象的一生"；活动图 = "一件事的全流程"

## 四、程序流程图（补充：结构化的表达方式）

> 老师第 9 周课件内容，不是 UML 的一部分，但考试中可能出现。

| 结构 | 说明 |
|------|------|
| **顺序** | 从上到下依次执行 |
| **选择** | 条件判断（if/else），菱形框表示 |
| **循环** | while-do（先判断后执行）或 do-while（先执行后判断） |

<div id="section-14" class="note-anchor"></div>

### 流程图基本符号

| 符号 | 含义 |
|------|------|
| 椭圆形 | 开始/结束 |
| 矩形 | 处理/操作 |
| 菱形 | 判断 |
| 箭头 | 流向 |

## 期末考试常见考点

<div id="section-16" class="note-anchor"></div>

### 简答题

> **Q：UML 中状态图和活动图有什么区别？**
>
> **答题要点**：
> 1. 状态图描述**一个对象**生命周期中的状态及因事件引起的状态转移。重点关注"对象如何响应事件"。
> 2. 活动图描述**业务流程**中活动到活动的控制流。关注"流程如何一步步进行"。
> 3. 状态图无泳道，活动图有泳道。
> 4. 典型例子：状态图 → 订单状态（待支付 → 已支付 → 已发货 → 已完成）；活动图 → 审批流程（员工提交 → 经理审批 → 财务审核 → 归档）。

<div id="section-17" class="note-anchor"></div>

### 画图题

> **Q：画出"图书借阅管理"中 Book 对象的状态图。**
> - 状态：可借、已借出、逾期、预约、下架
> - 事件：借出、归还、逾期（超时条件）、预约、取消预约、下架
>
> **要点**：正确标注初始状态、转移事件、守卫条件（如超时 → 逾期）
