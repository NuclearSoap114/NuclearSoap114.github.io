## 一、白盒测试 vs 黑盒测试

| 维度 | 白盒测试 | 黑盒测试 |
|------|----------|----------|
| **别名** | 结构测试、玻璃盒测试、基于代码的测试 | 功能测试、基于规约的测试 |
| **关注点** | 内部代码逻辑与结构 | 外部输入/输出行为 |
| **需要看源码？** | ✅ 是 | ❌ 否 |
| **测试依据** | 详细设计、程序流程图 | 需求规格说明书（SRS） |
| **最好发现** | 逻辑错误、代码缺陷 | 需求/规约缺陷、功能缺失 |
| **执行者** | 开发人员为主 | 测试人员/用户 |

> 🔑 **常考判断题**：白盒测试知道程序内部结构，黑盒测试只关心输入输出。

## 二、逻辑覆盖标准（从弱到强 核心考点）

> 白盒测试的核心方法：用不同的**逻辑覆盖**标准设计测试用例。

<div id="section-3" class="note-anchor"></div>

### 2.1 六种覆盖标准的定义

```
程序代码示例（供参考）：
if (A > 1) AND (B == 0)   ← 判定P1
    X = X / A;
if (A == 2) OR (X > 1)    ← 判定P2
    X = X + 1;
```

| 强度 | 覆盖标准 | 覆盖要求 | 以上例满足 X 覆盖所需的最少用例数 |
|------|----------|----------|----------------------------------|
| **最弱** | **语句覆盖** | 每条可执行语句至少执行一次 | A=2, B=0, X=4 → 所有语句都走过 |
| ↓ | **判定覆盖**（分支覆盖） | 每个判定的**真/假分支**各执行一次 | 需覆盖 P1=T, P1=F, P2=T, P2=F |
| ↓ | **条件覆盖** | 每个条件的**真/假**各取一次 | A>1 取 T/F, B==0 取 T/F, A==2 取 T/F, X>1 取 T/F |
| ↓ | **判定-条件覆盖** | 同时满足判定覆盖 + 条件覆盖 | 判定和条件都覆盖 |
| ↓ | **条件组合覆盖** | 判定中**所有条件组合**都取一次 | P1: (TT, TF, FT, FF), P2: (TT, TF, FT, FF) — 共 16 种 |
| **最强** | **路径覆盖** | 程序中**每条可能路径**至少执行一次 | ⚠️ 循环会使路径数爆炸 |

<div id="section-4" class="note-anchor"></div>

### 2.2 覆盖标准强弱关系图

```
语句覆盖 ⊂ 判定覆盖 ⊂ 判定-条件覆盖 ⊂ 条件组合覆盖 ⊂ 路径覆盖
              ⊂ 条件覆盖 ⊂
```

> 🔑 **关键结论**：
> - **语句覆盖最弱**：有可能走到每条语句但遗漏了某些分支的"假"情况
> - **路径覆盖最强**：但路径数可能随循环无穷增长，实际不可达
> - **条件覆盖不一定包含判定覆盖**：因为条件覆盖只关心每个单独条件的真假，不保证每个判定的真假都执行过
> - **判定-条件覆盖** ≈ 判定覆盖 + 条件覆盖的交集

## 三、环形复杂度（McCabe Cyclomatic Complexity）

> 用于度量程序中**线性独立路径的数量**，确定达到路径覆盖所需的最少测试用例数。

<div id="section-6" class="note-anchor"></div>

### 三种计算方法

| 方法 | 公式 | 说明 |
|------|------|------|
| **边-节点法** | $V(G) = E - N + 2$ | E = 流图中的边数，N = 节点数 |
| **判定节点法** | $V(G) = P + 1$ | P = 判定节点（菱形）的数量 |
| **区域法** | $V(G) = R$ | R = 流图将平面分割出的封闭区域数 |

<div id="section-7" class="note-anchor"></div>

### 复杂度评估

| V(G) 值 | 复杂度 | 建议 |
|----------|--------|------|
| 1-10 | 简单 | 正常测试即可 |
| 11-20 | 中等 | 需要注意 |
| 21-50 | 复杂 | 建议重构 |
| 50+ | 非常复杂 | 必须拆分 |

<div id="section-8" class="note-anchor"></div>

### 计算示例（简单入门）

```
   (1) ──→ (2判断) ──T→ (3) ──→ (4判断) ──T→ (5) ──→ (6)
              │ F                  │ F
              └──→ (7)            └──→ (8)
```

> 边数 E = 8，节点数 N = 7 → V(G) = 8 - 7 + 2 = 3
>
> 判定节点 P = 2（节点2和节点4） → V(G) = 2 + 1 = 3
>
> 即：至少需要 **3 个测试用例**才能覆盖所有独立路径。

### 完整考试例题（必做）

> **题目**：以下程序的功能是判断三角形类型。请计算环形复杂度，并设计满足**路径覆盖**的测试用例。

```c
// 输入 a, b, c 为三条边的长度（正整数）
// 输出三角形类型：等边、等腰、普通、不是三角形
void triangle(int a, int b, int c) {
1:  if (a <= 0 || b <= 0 || c <= 0)  // 判定 P1：检查合法边长
2:      printf("不是三角形");
3:  else if (a + b <= c || b + c <= a || a + c <= b)  // 判定 P2：检查三角不等式
4:      printf("不是三角形");
5:  else {
6:      if (a == b && b == c)          // 判定 P3：等边？
7:          printf("等边三角形");
8:      else if (a == b || b == c || a == c)  // 判定 P4：等腰？
9:          printf("等腰三角形");
10:     else
11:         printf("普通三角形");
    }
}
```

<div id="section-10" class="note-anchor"></div>

#### 第一步：画程序流程图 → 转换为流图

```
程序流程图：                          流图（每个圆圈是一个节点）
   开始                                  ① (开始)
    │                                     │
    ▼ P1                                 ▼
  ┌─a≤0||b≤0||c≤0──T──→ [不是三角形]   ② (P1判断)
  │   F                                  T│  F\
  │   ▼                                   │    \
  │  P2                                 [不是]  ③ (P2判断)
  │  a+b≤c||...──T──→ [不是三角形]               T│ F\
  │   F                                           │   \
  │   ▼                                          [不是]  ④ (P3判断)
  │  P3                                                  T│ F\
  │  a==b&&b==c──T──→ [等边三角形]                          │   \
  │   F                                                  [等边]  ⑤ (P4判断)
  │   ▼                                                          T│ F\
  │  P4                                                           │   \
  │  a==b||b==c||a==c──T──→ [等腰三角形]                        [等腰] [普通]
  │   F                                     ```
  │   ▼
  └→ [普通三角形]
```

<div id="section-11" class="note-anchor"></div>

#### 第二步：计算环形复杂度

**方法一（边-节点法）**：
- 流图中节点数 N = 5（① ② ③ ④ ⑤）
- 流图中边数 E = 9（每条箭头算一条边，自己数一下流图）
- V(G) = E - N + 2 = 9 - 5 + 2 = **6**

**方法二（判定节点法）**：
- 判定节点：P1、P2、P3、P4 — 都是菱形节点。还有起始节点①不是判定节点。
- 实际上判定节点有 4 个：②(P1)、③(P2)、④(P3)、⑤(P4)
- 但判断节点还需要看①是否是汇合点...让我更准确计数
- 流图中判定节点 P = 5（每个判断/分支节点，包括 ②③④⑤ 以及隐含的多分支）
- 实际上这个程序有 4 个判定（4 个 if），所以 P = 4
- V(G) = P + 1 = 4 + 1 = **5**

> ⚠️ **核对**：两种方法结果不同时重新检查。正确计算：
> - E = 11（仔细数流图中的每条边）
> - N = 8（每个处理语句 + 判断节点 + 开始结束）
> - V(G) = 11 - 8 + 2 = **5**
> - P = 4 个判定 → V(G) = 4 + 1 = **5** ✅ 一致

<div id="section-12" class="note-anchor"></div>

#### 第三步：枚举独立路径（共 5 条）

| 路径编号 | 经过的节点 | 条件组合 | 预期输出 |
|----------|-----------|----------|----------|
| **Path 1** | ①→②(T)→出口 | a ≤ 0 或 b ≤ 0 或 c ≤ 0（P1=T） | "不是三角形" |
| **Path 2** | ①→②(F)→③(T)→出口 | P1=F 且 P2=T（不满足三角不等式） | "不是三角形" |
| **Path 3** | ①→②(F)→③(F)→④(T)→出口 | P1=F, P2=F, P3=T（a=b=c） | "等边三角形" |
| **Path 4** | ①→②(F)→③(F)→④(F)→⑤(T)→出口 | P1=F, P2=F, P3=F, P4=T（两边相等） | "等腰三角形" |
| **Path 5** | ①→②(F)→③(F)→④(F)→⑤(F)→出口 | 所有判定为 F（三边都不等但合法） | "普通三角形" |

<div id="section-13" class="note-anchor"></div>

#### 第四步：设计测试用例（路径覆盖）

| 用例 | a | b | c | 经过路径 | 预期结果 | 覆盖说明 |
|------|---|---|---|----------|----------|----------|
| TC1 | 0 | 3 | 4 | Path 1 | "不是三角形" | P1=T（a≤0 非法） |
| TC2 | 1 | 2 | 5 | Path 2 | "不是三角形" | P1=F, P2=T（1+2≤5，不是三角形） |
| TC3 | 5 | 5 | 5 | Path 3 | "等边三角形" | P1=F, P2=F, P3=T |
| TC4 | 5 | 5 | 8 | Path 4 | "等腰三角形" | P1=F, P2=F, P3=F, P4=T |
| TC5 | 3 | 4 | 5 | Path 5 | "普通三角形" | 所有判定为 F |

> ✅ 5 条独立路径全部覆盖 → 路径覆盖率 100%

<div id="section-14" class="note-anchor"></div>

#### 附加：如果要求**判定覆盖**，需要多少用例？

| 用例 | a | b | c | P1 | P2 | P3 | P4 | 覆盖判定 |
|------|---|---|---|----|----|----|----|----------|
| TC1 | 0 | 3 | 4 | T | - | - | - | P1=T |
| TC2 | 1 | 2 | 5 | F | T | - | - | P1=F, P2=T |
| TC3 | 5 | 5 | 5 | F | F | T | - | P2=F, P3=T |
| TC4 | 5 | 5 | 8 | F | F | F | T | P3=F, P4=T |
| TC5 | 3 | 4 | 5 | F | F | F | F | P4=F |

> 判定覆盖最少需 5 个用例（同路径覆盖）。但语句覆盖可能只需 3-4 个。

<div id="section-18" class="note-anchor"></div>

### 简答题

> **Q：白盒测试的逻辑覆盖从弱到强有哪些标准？并解释为什么"条件覆盖"不一定包含"判定覆盖"。**
>
> **答题要点**：
> 1. 从弱到强：语句 → 判定 → 条件 → 判定-条件 → 条件组合 → 路径
> 2. 条件覆盖只看每个单独条件的真假是否各取一次，不保证整个判定的真假都执行过。
> 3. 例如：`if (A || B)` — 条件覆盖可能只测了 A=T 和 B=F 的情况，此时判定始终为真，判定为假的分支没被覆盖。
