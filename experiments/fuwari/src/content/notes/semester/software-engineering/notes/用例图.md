## 一、核心元素

| 元素 | 符号 | 说明 |
|------|------|------|
| **参与者（Actor）** | 火柴人 👤 | 与系统交互的外部实体（用户或其他系统） |
| **用例（Use Case）** | 椭圆 | 系统提供的一个完整功能单元 |
| **系统边界** | 矩形框 | 表示系统的范围，用例在框内，参与者在框外 |
| **关联** | 实线 ——— | 表示参与者与用例之间有交互 |

```
        ┌── 系统 ─────────────┐
        │   ╭──────╮         │
 👤 ────┼───│ 登录  │         │
  用户  │   ╰──────╯         │
        │   ╭──────╮         │
 👤 ────┼───│ 下单  │         │
  管理员 │   ╰──────╯         │
        └────────────────────┘
```

## 二、用例之间的关系（核心考点）

| 关系 | 符号 | 语义 | 示例 |
|------|------|------|------|
| **泛化** | 实线 + 空心三角 →（指向父用例） | 子用例是父用例的特殊形式 | "支付"可泛化为"支付宝支付"和"微信支付" |
| **包含 `<<include>>`** | 虚线 + 箭头 `<<include>>` → | **必须执行**：基用例必然调用被包含用例 | "下单"必然包含"验证登录" |
| **扩展 `<<extend>>`** | 虚线 + 箭头 `<<extend>>` → | **可选执行**：满足条件时才扩展 | "下单"可能扩展"使用优惠券"（如果用户有券） |

<div id="section-3" class="note-anchor"></div>

### `<<include>>` vs `<<extend>>` 对比（高频辨析）

| 维度 | `<<include>>` | `<<extend>>` |
|------|---------------|--------------|
| **是否必须** | ✅ 必须执行 | ❌ 可选，有条件 |
| **基用例是否完整** | 基用例不完整，依赖被包含用例 | 基用例独立完整 |
| **箭头方向** | 基用例 → 被包含用例 | 扩展用例 → 基用例 |
| **典型场景** | 多个用例共享的公共步骤（如"登录验证"） | 特殊/异常情况的补充（如"使用优惠券"、"密码错误处理"） |

> 🧠 **记忆技巧**：include = 必须"包含"才完整；extend = 在基本功能上"扩展"可选功能。箭头方向：include 是从基指向被包含的，extend 是从扩展指向基（反直觉！）。

## 四、用例描述文档

> 用例图只展示功能的"骨架"，详细的行为逻辑需要通过**用例描述文档**表达。

<div id="section-6" class="note-anchor"></div>

### 用例描述模板（必知的字段）

| 字段 | 说明 |
|------|------|
| 用例编号 | 唯一标识（如 UC-001） |
| 用例名称 | 简洁的动宾短语（如"登录系统"） |
| 参与者 | 主要参与者 + 次要参与者 |
| 简要说明 | 一句话描述用例目的 |
| **前置条件** | 用例开始前必须为真的条件 |
| **后置条件** | 用例结束后系统所处的状态 |
| **基本事件流** | 正常的"阳光大道"流程（最重要的部分） |
| **备选事件流** | 异常/分支处理（如"密码错误"、"余额不足"） |

<div id="section-7" class="note-anchor"></div>

### 示例：ATM 取款用例描述

| 字段 | 内容 |
|------|------|
| 用例名称 | ATM 取款 |
| 参与者 | 持卡人（主），银行系统（次） |
| 前置条件 | 已插入有效银行卡，已通过密码验证 |
| 后置条件 | 钞票已吐出，账户余额已更新 |
| 基本流 | 1. 选择"取款" → 2. 输入金额 → 3. 系统验证余额 → 4. 吐钞 → 5. 打印凭条 → 6. 退卡 |
| 备选流A | 3a. 余额不足 → 提示并重新输入 → 返回基本流步骤2 |
| 备选流B | 4a. ATM 钞票不足 → 提示"无法提供服务" → 退卡 |

## 期末考试常见考点

<div id="section-9" class="note-anchor"></div>

### 画图题

> **Q：画出图书馆管理系统中"借书"的用例图。参与者包括读者和管理员，功能包括借书、还书、查询图书、续借（需先查询）。**

**📝 参考答案（文字描述，考试时你需要画出来）**：

```
                            ┌────── 图书馆管理系统 ──────────────┐
                            │                                    │
    👤 读者 ────────────────┤  ○ 借书 ──<<include>>──→ ○ 查询图书│
         │                  │         ←──<<extend>>── ○ 续借     │
         │  (泛化)          │                                    │
         ↓                  │  ○ 还书                           │
    👤 管理员 ──────────────┤  ○ 管理图书信息                    │
                            │  ○ 管理读者信息                    │
                            └────────────────────────────────────┘
```

**关系说明**：
| 关系 | 方向 | 理由 |
|------|------|------|
| 借书 `<<include>>→` 查询图书 | 基→被包含 | 借书**必须**先查到书（必须有书才能借） |
| 续借 `<<extend>>→` 查询图书 | 扩展→基 | 续借**可选**地依赖查询（有时读者直接拿书来续不需要查） |
| 读者→管理员（泛化） | 子→父 | 管理员也是读者，继承了读者的所有用例 |

> ⚠️ **易错**：`extend` 箭头是**扩展用例指向基用例**（续借→查询），和 `include` 方向相反！

<div id="section-10" class="note-anchor"></div>

### 简答题

> **Q：用例图中 `<<include>>` 和 `<<extend>>` 的区别是什么？**
>
> **答题要点**：
> 1. include：必须执行的关系。基用例不完整，必须依赖被包含用例。多个用例共享的公共行为使用 include。
> 2. extend：可选执行的关系。基用例独立完整，仅在特定条件下才扩展。特殊/异常情况使用 extend。
> 3. 箭头方向：include = 基 → 被包含；extend = 扩展 → 基
