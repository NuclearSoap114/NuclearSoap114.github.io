## 一、面向对象的核心思想

> 软件系统由多个**对象**组成，对象间通过**消息**相互通信、共同协作，完成整个系统的功能。

<div id="section-2" class="note-anchor"></div>

### 面向过程 vs 面向对象

| 维度 | 面向过程（POP） | 面向对象（OOP） |
|------|-----------------|-----------------|
| **核心关注** | 功能 / 过程 | 对象 / 数据 |
| **思维方式** | 自顶向下、逐层分解 | 自底向上、对象协作 |
| **基本单位** | 函数 / 模块 | 类 / 对象 |
| **设计方法** | 结构化分析 + 结构化设计 | 面向对象分析 + 面向对象设计 |
| **建模工具** | 数据流图（DFD）、流程图 | UML（用例图、类图、顺序图等） |
| **复用性** | 差（函数级复用） | 强（类级/框架级复用） |
| **可维护性** | 低（数据与操作分离） | 高（数据与操作封装在一起） |
| **适用场景** | 需求稳定、功能简单 | 需求多变、大型复杂系统 |

## 二、面向对象三大基本特性（必考）

<div id="section-4" class="note-anchor"></div>

### 2.1 封装（Encapsulation）

> 将**数据**（属性）和**操作**（方法）封装到类中，**隐藏内部实现细节**，只暴露公共接口。

```
┌───────────────────┐
│   public 接口     │  ← 外部只能通过公开接口访问
│  ┌─────────────┐  │
│  │ private 内部 │  │  ← 内部数据/实现对外不可见
│  │ 属性 + 方法  │  │
│  └─────────────┘  │
└───────────────────┘
```

| 关键点 | 说明 |
|--------|------|
| 目的 | 信息隐藏、降低耦合 |
| 方式 | 通过 private/protected/public 访问修饰符控制 |
| 好处 | 内部修改不影响外部调用者（只要接口不变） |

---

<div id="section-5" class="note-anchor"></div>

### 2.2 继承（Inheritance）

> 子类**继承**父类的属性和方法，使子类拥有父类的特征和行为。

| 关键点 | 说明 |
|--------|------|
| 关系 | "is-a" 关系（子类 is-a 父类） |
| 目的 | **代码复用**、建立类层次结构 |
| 语法 | `class Dog extends Animal {}` |
| 局限 | 破坏封装（子类了解父类实现细节）、强耦合 |
| 替代 | **组合/聚合优于继承**原则（has-a 而非 is-a） |

```
        Animal（父类）
        ├── 属性：name, age
        ├── 方法：eat(), sleep()
           ↓ 继承
   ┌─────┴─────┐
  Dog          Cat
  + bark()     + meow()
```

---

<div id="section-6" class="note-anchor"></div>

### 2.3 多态（Polymorphism）

> 同一操作作用于不同对象上，可以有不同的解释，产生不同的执行结果。

| 多态类型 | 说明 | 实现方式 |
|----------|------|----------|
| **编译时多态** | 方法重载（Overloading） | 同一方法名、不同参数列表 |
| **运行时多态** | 方法重写（Overriding） | 子类重写父类方法 + 父类引用指向子类对象 |

```
Animal a = new Dog();  // 父类引用 → 子类对象
a.makeSound();          // 调用的是 Dog 的 makeSound()，而非 Animal 的
```

| 关键点 | 说明 |
|--------|------|
| 目的 | 提高可扩展性、符合开闭原则 |
| 核心机制 | 动态绑定（运行时确定调用哪个方法） |

> 🧠 **记忆技巧**：封装 = 打包隐藏；继承 = 拿来就用；多态 = 同一接口不同表现

## 三、类与对象的关系

| 概念 | 定义 | 比喻 |
|------|------|------|
| **类（Class）** | 对一组具有相同属性和操作的对象的**抽象描述/模板** | 模具、图纸 |
| **对象（Object）** | 类的**实例**，真实存在的具体实体 | 用模具生产出的零件 |
| **关系** | 类是对象的抽象，对象是类的实例 | `new 类名()` 产生对象 |

<div id="section-8" class="note-anchor"></div>

### 类中封装的内容

```
class Student {
    // 属性（数据）
    private String name;
    private int age;

    // 方法（操作）
    public void study() { ... }
    public int getAge() { ... }
}
```

## 四、面向对象需求分析的三种模型

> 老师 XMind 中标注：面向对象建模分为数据模型、功能模型、行为模型。

| 模型类型 | UML 图 | 说明 |
|----------|--------|------|
| **数据模型**（静态） | 类图、类的关系图 | 描述系统中的类及其相互关系 |
| **功能模型**（静态） | 用例图 | 描述系统的功能需求（从用户视角） |
| **行为模型**（动态） | 顺序图、活动图、状态图、协作图 | 描述对象间的交互和状态变化 |

## 期末考试常见考点

<div id="section-11" class="note-anchor"></div>

### 简答题

> **Q：简述面向对象的三大特性。**
>
> **答题要点**：
> 1. **封装**：将数据与操作封装在类中，隐藏内部实现，只暴露公共接口。目的：信息隐藏、降低耦合。
> 2. **继承**：子类继承父类的属性和方法（is-a 关系）。目的：代码复用。注意：组合/聚合优先于继承。
> 3. **多态**：同一操作在不同对象上表现不同。方法重载（编译时多态）+ 方法重写（运行时多态）。目的：提高可扩展性。

> **Q：结构化开发方法与面向对象开发方法的主要区别是什么？**
>
> **答题要点**：
> 1. 结构化方法以**功能/过程**为中心，自顶向下逐层分解；面向对象方法以**对象/数据**为中心，自底向上找对象协作。
> 2. 结构化方法数据与操作分离，维护困难；面向对象方法将数据与操作封装在一起，维护性好。
> 3. 结构化方法适用需求稳定的小型系统；面向对象方法适用需求多变的大型复杂系统。
