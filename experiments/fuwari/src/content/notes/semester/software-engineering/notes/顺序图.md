> 顺序图是最常用的**动态行为图**之一，描述**对象间消息传递的时间顺序**。

---

<div id="section-1" class="note-anchor"></div>

## 一、核心元素

```
  参与者A           对象B             对象C
    │                │                 │
    ├──消息1(sync)──→│                 │
    │                │────消息2────→   │
    │                │  ┌─激活期─┐     │
    │                │  │  do()  │     │
    │                │  └────────┘     │
    │                │←───返回消息────  │
    │←──返回────────┤                 │
    │                │                 │
    ↓                ↓                 ↓
 生命线            生命线             生命线
```

| 元素 | 符号 | 说明 |
|------|------|------|
| **对象/生命线** | 矩形 + 垂直虚线 | 对象存在的时间线，从上到下表示时间推进 |
| **激活期（Activation）** | 生命线上的细长矩形 | 对象正在执行操作的时段 |
| **消息** | 带箭头的横线 | 对象间的通信 |
| **X 标记** | 生命线末端的 X | 对象被销毁（destroy） |

<div id="section-2" class="note-anchor"></div>

### 对象的创建与销毁

| 情况 | 表示方式 |
|------|----------|
| **交互开始前已存在** | 对象在图的顶部 |
| **交互过程中创建** | 对象在图中部出现（有 create 消息指向它） |
| **对象销毁** | 生命线末端加 **X**，或发送 `<<destroy>>` 消息 |

<div id="section-3" class="note-anchor"></div>

## 二、五种消息类型（重要）

| 消息类型 | 符号 | 说明 |
|----------|------|------|
| **同步消息** | 实线 + 实心箭头 → | 调用者等待被调用者返回（最常见） |
| **异步消息** | 实线 + 开放箭头 → | 调用者发完即走，不等待返回 |
| **返回消息** | 虚线 + 开放箭头 - - -▷ | 从被调用者返回给调用者（可选，可省略） |
| **自调用/返身消息** | 绕回自身 | 对象调用自身的方法 |
| **创建消息** | 虚线 + 开放箭头 → 目标 | `<<create>>` 构造新对象 |

> 🔑 **同步 vs 异步**：同步 = 等待返回（打电话），异步 = 不等待（发短信）

## 三、组合片段（Combined Fragments）

> 用方框标记，左上角标注操作符，用于表达条件、循环、并行等复杂逻辑。

| 操作符 | 含义 | 使用场景 |
|--------|------|----------|
| **alt** | 多选一（if/else） | "登录成功" vs "登录失败" |
| **opt** | 可选（if） | "如果有优惠券则应用" |
| **loop** | 循环 | "重复输入密码，最多 3 次" |
| **par** | 并行 | "同时发送邮件和短信通知" |
| **ref** | 引用另一个顺序图 | 将复杂流程拆分为子图 |
| **break** | 异常退出 | "余额不足，直接结束" |

```
┌─ alt ─────────────────────────────┐
│  [登录成功]                        │
│    ...正常流程...                   │
│  ──────────────────────────────────│
│  [登录失败]                        │
│    ...提示重新输入...               │
└───────────────────────────────────┘
```

## 四、顺序图的绘制原则

> 老师 PPT 强调的规则：

| 原则 | 说明 |
|------|------|
| 对象从左到右排列 | 把最重要的对象放在最左边 |
| 消息自上而下 | 按时间顺序从上到下排列 |
| 设置激活期 | 对象正在执行操作时画出激活矩形 |
| 消息名标注 | 同步/异步消息标注方法名，返回消息可标注返回值 |

<div id="section-6" class="note-anchor"></div>

## 五、顺序图 vs 协作图/通信图

| 维度 | 顺序图 | 协作图（通信图） |
|------|--------|-----------------|
| 强调重点 | **时间顺序** | **对象间的结构关系** |
| 布局 | 从上到下按时间排列 | 任意布局，用编号表示顺序 |
| 编号 | 无需编号（时间即顺序） | 必须用数字编号（1, 2, 3...）表示顺序 |
| 适用场景 | 描述单个用例的事件流 | 展示对象间的静态连接关系 |

> 🔑 **常考判断**："顺序图强调时间顺序，协作图强调对象间结构关系。"

## 期末考试常见考点

<div id="section-8" class="note-anchor"></div>

### 画图题

> **Q：画出"ATM 取款"的顺序图。参与者：持卡人，对象：ATM 界面、账户系统、钞票机。**
> - 持卡人输入密码 → ATM 验证
> - ATM 向账户系统查询余额
> - 余额足够 → ATM 指令钞票机吐钞
> - 钞票机返回吐钞结果
> - ATM 显示取款成功
>
> **要点**：
> - 4 条生命线：持卡人、ATM 界面、账户系统、钞票机
> - 同步消息：验证密码、查询余额、吐钞指令
> - 返回消息：查询结果、吐钞结果、显示成功
> - 考虑平衡不足的 alt 片段

<div id="section-9" class="note-anchor"></div>

### 简答题

> **Q：顺序图中的同步消息和异步消息有什么区别？**
>
> **答题要点**：
> 1. 同步消息（实心箭头）：调用者发送消息后**阻塞等待**被调用者返回结果。如：方法调用。
> 2. 异步消息（开放箭头）：调用者发送消息后**立即继续执行**，不等待返回。如：发送通知。
> 3. 在 UML 中的表示：同步用实心三角箭头，异步用开放箭头。
