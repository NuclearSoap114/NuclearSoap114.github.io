> 软件维护是软件生命周期中**持续时间最长、成本最高**的阶段（占总成本的 50%-70%）。

---

<div id="section-1" class="note-anchor"></div>

## 一、四种维护类型（必考排序）

| 类型 | 英文 | 说明 | 占总维护比例 |
|------|------|------|-------------|
| **完善性维护** | Perfective Maintenance | 增加新功能、改进性能、提升用户体验 | **~50%**（最多） |
| **适应性维护** | Adaptive Maintenance | 为适应外部环境变化（OS 升级、硬件更换、法规变更） | ~25% |
| **改正性维护** | Corrective Maintenance | 修复发现的缺陷和错误 | ~21% |
| **预防性维护** | Preventive Maintenance | 主动修改以预防未来可能的故障 | ~4%（最少） |

> 🔑 **高频考点**：占比最大的是**完善性维护**（约一半），不是改正性维护！预防性维护占比最小。

---

<div id="section-2" class="note-anchor"></div>

## 二、各类型辨析表

| 类型 | 触发条件 | 例 |
|------|----------|-----|
| **改正性** | 用户报告 bug | 修复登录失败 bug |
| **适应性** | 外部环境变化 | 系统从 Windows 7 迁移到 Windows 11 |
| **完善性** | 用户提出新需求 | 增加"导出报表"功能 |
| **预防性** | 开发者主动预防 | 重构代码以减少未来的维护成本 |

<div id="section-3" class="note-anchor"></div>

## 三、维护的困难

| 问题 | 说明 |
|------|------|
| **理解他人代码困难** | 软件是逻辑产品，读懂别人的代码远比写自己的难 |
| **文档缺失或过时** | 长期维护后文档往往与实际代码不一致 |
| **副作用风险** | 修改一处可能引发连锁故障 |
| **人员流失** | 原开发人员离开，新人不了解系统 |

---

<div id="section-4" class="note-anchor"></div>

## 四、逆向工程与再工程

| 概念 | 说明 |
|------|------|
| **逆向工程（Reverse Engineering）** | 从已有代码中提取设计信息，恢复系统的结构和规约 |
| **再工程（Re-engineering）** | 逆向工程 + 正向工程的组合：理解旧系统 → 重新设计 → 重新实现 |

<div id="section-5" class="note-anchor"></div>

### 再工程的过程

```
现有系统 → 逆向工程（理解、提取设计） → 重新设计与优化 → 新系统
```

<div id="section-6" class="note-anchor"></div>

## 五、软件维护过程

| 步骤 | 内容 |
|------|------|
| 1. 建立维护组织 | 确定维护责任人 |
| 2. 维护申请与分类 | 判断是改正/适应/完善/预防哪种类型 |
| 3. 影响分析 | 评估修改对系统其他部分的影响 |
| 4. 实施修改 | 编码、测试、审查 |
| 5. 回归测试 | 保证修改没有引入新缺陷 |
| 6. 文档更新 | 使文档与代码保持一致 |
| 7. 发布新版本 | 交付给用户 |

---

<div id="section-7" class="note-anchor"></div>

## 六、遗留系统（Legacy System）的演进策略

| 策略 | 说明 | 适用情况 |
|------|------|----------|
| **继续维护** | 照常进行维护活动 | 系统仍能基本满足业务需要 |
| **再工程** | 逆向+重构+正向重建 | 系统有价值但技术过时 |
| **替换** | 开发新系统替代 | 系统价值低、维护成本过高 |
| **废弃** | 停止使用 | 不再有业务需求 |

<div id="section-8" class="note-anchor"></div>

## 期末考试常见考点

<div id="section-9" class="note-anchor"></div>

### 简答题

> **Q：软件维护有哪四种类型？哪种类型占比最大？**
>
> **答题要点**：
> 1. 改正性维护（修 bug）、适应性维护（适应环境变化）、完善性维护（增加功能）、预防性维护（主动预防）
> 2. **完善性维护**占比最大，约 50% 以上
> 3. 预防性维护占比最小

<div id="section-10" class="note-anchor"></div>

### 判断题

> "软件维护中改正性维护占比最大" — **❌ 错误**。完善性维护占比最大。

> "软件维护就是改正软件中的错误" — **❌ 错误**。维护包括四种类型，改正性只是其中之一。
