## 一、总原则

> **模块独立性**是衡量软件设计质量的核心标准。好的设计追求：**高内聚（模块内部）、低耦合（模块之间）**。

---

<div id="section-2" class="note-anchor"></div>

## 二、耦合（Coupling）—— 模块间的关联程度

> 耦合是模块之间相互依赖的度量。**耦合越低越好**。

| 等级 | 耦合类型 | 说明 | 典型代码 |
|------|----------|------|----------|
| **最低** | 无直接耦合 | 两个模块之间没有任何直接关系 | 独立模块 |
| **低** | **数据耦合** | 仅通过简单参数传递数据（值传递） | `void print(String name)` |
| **中** | **标记耦合** | 传递复合数据结构，但被调用方只用其中部分字段 | 传整个 User 对象，但只需要 user.getName() |
| **较高** | **控制耦合** | 传递控制 flag，影响另一模块的执行路径 | `void process(boolean isAdmin)` — 内部根据 flag 走不同分支 |
| **高** | **公共耦合** | 多个模块共享全局数据 | 多个模块读写同一个全局变量 `public static int count` |
| **最高** | **内容耦合** | 一个模块直接访问/修改另一模块的内部数据或代码 | 直接操作别的类的 private 字段；goto 跳到别的模块 |

<div id="section-3" class="note-anchor"></div>

### 耦合从弱到强排序（填空题高频）

```
数据耦合 < 标记耦合 < 控制耦合 < 公共耦合 < 内容耦合
（想要低耦合 → 尽量只用数据耦合）
```

<div id="section-4" class="note-anchor"></div>

### 控制耦合 vs 数据耦合辨析

| 场景 | 耦合类型 |
|------|----------|
| `calculate(a, b)` — 传入两个数值 | **数据耦合**（✅ 好的） |
| `calculate(a, b, "add")` — 传入操作类型 flag | **控制耦合**（❌ 避免） |
| 更好的做法：`add(a, b)` + `subtract(a, b)` 各自独立 | 消除控制耦合 |

<div id="section-5" class="note-anchor"></div>

## 三、内聚（Cohesion）—— 模块内部的紧密程度

> 内聚是模块内部各成分之间相关联的度量。**内聚越高越好**。

| 等级 | 内聚类型 | 说明 | 典型场景 |
|------|----------|------|----------|
| **最低** | **偶然内聚** | 模块内各部分毫无逻辑关系，碰巧放在一起 | "杂项工具类" `MiscUtils` 放了一堆不相关函数 |
| **低** | **逻辑内聚** | 若干逻辑相关功能放在一起，由调用方通过参数选择 | 一个类里有 `printPDF()` 和 `printExcel()`，通过参数选 |
| **较低** | **时间内聚** | 必须在同一时间执行的任务放在一起 | 初始化模块（一次性执行所有初始化操作） |
| **中** | **过程内聚** | 按特定顺序执行的任务放在一个模块中 | 先读文件 → 再解析 → 再写入数据库（流水线） |
| **中** | **通信内聚** | 操作同一数据集的若干功能 | 对同一张数据库表的所有增删改查操作 |
| **较高** | **顺序内聚** | 前一处理的输出正好是后一处理的输入（数据流连接） | 读文件 → 解析数据 → 格式化输出（流水线且数据流连贯） |
| **最高** | **功能内聚** | 模块内所有元素共同完成且**只完成一个单一功能** | `validateEmail()`、`calculateTax()` — 单一职责 |

<div id="section-6" class="note-anchor"></div>

### 内聚从弱到强排序

```
偶然 < 逻辑 < 时间 < 过程 < 通信 < 顺序 < 功能
（想要高内聚 → 追求功能内聚）
```

<div id="section-7" class="note-anchor"></div>

### 各内聚类型速记

| 类型 | 一句话 | 标志词 |
|------|--------|--------|
| 偶然 | 毫无关系，硬塞在一起 | "杂项"、"工具集" |
| 逻辑 | 用 if/switch 分流不同逻辑 | "根据类型不同处理" |
| 时间 | 同时发生，顺便放一起 | "初始化"、"清理" |
| 过程 | 按特定顺序执行 | "步骤1→步骤2→步骤3" |
| 通信 | 操作同一份数据 | "同一张表的所有操作" |
| 顺序 | 前一步输出 = 后一步输入 | "数据管道" |
| 功能 | 只做一件事，做好它 | 单一职责 |

<div id="section-8" class="note-anchor"></div>

## 四、模块独立性的判定公式（理解即可）

> 模块独立性 ∝ 内聚 / 耦合

- 内聚越高 → 独立性越强
- 耦合越低 → 独立性越强
- 最佳组合：**功能内聚 + 数据耦合**

## 期末考试常见考点

<div id="section-10" class="note-anchor"></div>

### 简答题

> **Q：什么是模块独立性？如何衡量它？**
>
> **答题要点**：
> 1. 模块独立性是指软件系统中每个模块只完成独立的功能，与其他模块的联系尽可能简单。
> 2. 衡量标准：**内聚**（模块内部紧密程度）和**耦合**（模块间依赖程度）。
> 3. 设计目标：**高内聚**（追求功能内聚）、**低耦合**（追求数据耦合）。

<div id="section-11" class="note-anchor"></div>

### 填空题

> 耦合类型从弱到强排列：\_\_\_\_ < \_\_\_\_ < \_\_\_\_ < \_\_\_\_ < \_\_\_\_
>
> **答案**：数据耦合 < 标记耦合 < 控制耦合 < 公共耦合 < 内容耦合

> 内聚类型从弱到强排列：\_\_\_\_ < \_\_\_\_ < \_\_\_\_ < \_\_\_\_ < \_\_\_\_ < \_\_\_\_ < \_\_\_\_
>
> **答案**：偶然 < 逻辑 < 时间 < 过程 < 通信 < 顺序 < 功能

<div id="section-12" class="note-anchor"></div>

### 选择题

> 两个模块通过传递简单参数交换数据，属于哪种耦合？
> A. 控制耦合 | B. 数据耦合 | C. 标记耦合 | D. 公共耦合
>
> **答案：B** — 传递简单参数 = 数据耦合。
