你的两个总结方向是对的，但我建议把表述再精确一点：

1. **“将中位数/阈值数转化为确切的数字/上下界”**  
    更准确地说是：
    
    > **把“统计量的判定条件”转化为“元素数量的不等式”。**  
    > 比如 `median <= k` 并不需要真的求中位数，只需要知道 `<=k` 的元素是否至少占一半。
    
2. **“将互斥条件转化为 1 和 -1 的贡献”**  
    “互斥条件”范围有点太大，更准确是：
    
    > **把二分类元素编码成 `+1/-1`，将两类元素的数量比较转化为区间和的正负。**  
    > `good = +1, bad = -1` 后，`good >= bad` 就变成 `sum >= 0`。
    

我觉得第二条尤其值得单独形成一种条件反射。下面这篇我按“思维复盘”来写，而不是单纯复盘 2103C。

## 判定条件数值化：从 Median 到 ±1 前缀和

> **核心思想**
> 很多题目表面上要求处理一个复杂的统计量，例如：
>
> - 中位数
> - 多数元素
> - 至少一半满足条件
> - 某个值是否不超过阈值
>
> 但如果题目只问这个统计量是否满足某个**阈值条件**，往往根本不需要求出统计量本身。
>
> 可以尝试：
>
> 1. 把统计量条件改写成**元素数量关系**
> 2. 再把数量关系编码成 `+1/-1`
> 3. 最终转化为一个普通的**区间和 / 前缀和问题**

---

<div id="section-2" class="note-anchor"></div>

### 1. 第一个思维：不要急着计算统计量本身

看到：

```text
median <= k
````

第一反应很容易是：

```
怎么快速求区间中位数？
```

于是想到：

- 排序
- multiset
- 平衡树
- 主席树
- 二分答案

但这些可能全都想复杂了。

因为题目并没有问：

> 中位数具体是多少？

它只问：

> 中位数是否 `<= k`？

这是一个**判定问题**。

对于判定问题，我们通常可以丢掉大量不必要的信息。

---

# 2. Median ≤ k 的真正含义

假设一个区间长度为 `len`。

题目采用的中位数是排序后第：

\[ \left\lceil\frac{len}{2}\right\rceil \]

小的元素。

那么：

\[ median\le k \]

等价于：

> 区间中至少有

\[ \left\lceil\frac{len}{2}\right\rceil \]

个元素满足：

\[ a_i\le k \]

也就是说：

\[ \boxed{ \#(a_i\le k)\ge \#(a_i>k) } \]

至此，中位数已经完全消失了。

我们不再关心：

```
1, 3, 7, 100, 1000
```

这些具体值是多少。

只关心每个元素属于哪一类：

```
<= k
> k
```

这就是一次非常重要的**信息降维**。

---

> [!important] 思维 1：统计量判定 → 数量不等式
> 
> 当题目问：
> 
> ```
> 某个复杂统计量 是否 <= / >= 某个阈值
> ```
> 
> 不要立刻研究如何维护统计量。
> 
> 先问：
> 
> **这个判定条件本身，能不能用“有多少个元素满足某性质”来描述？**

---

# 3. 第二个思维：数量比较 → ±1

现在问题已经变成：

\[ \#good\ge\#bad \]

其中：

```
good : a[i] <= k
bad  : a[i] > k
```

这种“两类元素数量比较”有一个非常经典的编码：

```
a[i] <= k  -> +1
a[i] >  k  -> -1
```

定义：

\[ b_i= \begin{cases} +1,&a_i\le k\\ -1,&a_i>k \end{cases} \]

那么一个区间的和：

\[ \sum b_i \]

实际上就是：

\[ \#good-\#bad \]

所以：

\[ \#good\ge\#bad \]

直接变成：

\[ \boxed{\sum b_i\ge0} \]

于是：

\[ \boxed{ median\le k \iff 区间和\ge0 } \]

一个原本看起来像“中位数数据结构”的问题，突然变成了普通前缀和。

---

# 4. 为什么 ±1 编码这么强

因为它把：

```
两个数量之间的关系
```

压缩成了：

```
一个数字的正负
```

例如：

\[ A=\#good \]\[ B=\#bad \]

如果想判断：

\[ A\ge B \]

直接看：

\[ A-B\ge0 \]

于是自然令：

```
good -> +1
bad  -> -1
```

这不是某一道题的技巧，而是一种非常通用的建模方式。

---

> [!important] 思维 2：二分类 → ±1
> 
> 当元素天然分成两类，而条件只关心：
> 
> ```
> 第一类是否比第二类多
> 第一类是否至少占一半
> 第一类数量 - 第二类数量
> ```
> 
> 优先考虑：
> 
> ```
> 第一类 -> +1
> 第二类 -> -1
> ```
> 
> 把“计数比较”变成“区间和符号”。

---

# 5. 一个非常重要的识别信号：至少一半

以后看到：

```
至少一半
超过一半
多数
majority
median <= x
median >= x
```

都应该对 `+1/-1` 非常敏感。

例如：

## 至少一半满足 P

```
满足 P     -> +1
不满足 P   -> -1
```

那么：

\[ 满足P的数量\ge不满足P的数量 \]

等价于：

\[ sum\ge0 \]

---

## 超过一半满足 P

则变成：

\[ sum>0 \]

---

## 至少一半元素 ≤ x

正是：

\[ median\le x \]

所以：

```
median 判定
```

本质上经常就是一个：

```
majority 判定
```

---

# 6. 第三个隐含思维：复杂数值可以被阈值二值化

假设原数组：

```
2 100 7 1 30 9
```

如果当前只关心：

```
<= 10 ?
```

那么：

```
2   -> good
100 -> bad
7   -> good
1   -> good
30  -> bad
9   -> good
```

具体数值全部可以扔掉：

```
+1 -1 +1 +1 -1 +1
```

所以有时：

```
值域很大
```

并不意味着你真的需要处理这些值。

题目只要给了一个阈值 `k`，就应该思考：

> **能不能把每个值压缩成“在阈值左边还是右边”？**

即：

\[ a_i\longrightarrow [a_i\le k] \]

这是一种非常重要的**阈值二值化**。

---

# 7. 为什么二值化以后常常会接前缀和

因为：

```
单个元素 -> ±1
```

之后，区间性质自然变成：

```
区间 ±1 的总和
```

而区间和最自然的数据结构就是：

\[ prefix \]

定义：

\[ P_i=\sum_{j=1}^{i}b_j \]

那么：

\[ sum(l,r)=P_r-P_{l-1} \]

于是：

```
一个复杂的区间统计量条件
```

可能一路变成：

```
两个前缀和之间的大小关系
```

---

# 8. CF 2103C 中完整的降维过程

这道题是一个很好的例子。

原问题表面上是：

```
把数组分成三段

求每段 median

再对三个 median 求 median

判断最终结果 <= k
```

看起来有两层 median，非常复杂。

但第一层：

```
三个数的 median <= k
```

等价于：

```
至少两个数 <= k
```

所以只需要：

> 三个区间中至少两个区间的 median `<= k`。

第二层：

```
区间 median <= k
```

等价于：

```
区间中 <=k 的元素至少一半
```

然后：

```
<=k -> +1
>k  -> -1
```

得到：

```
区间 median <= k
        ⇕
区间和 >= 0
```

最终原问题彻底变成：

> 把一个 `±1` 数组切成三段，使至少两段的和 `>=0`。

这时候已经完全没有 median 了。

---

# 9. 再进一步：区间条件 → 前缀和不等式

假设切点：

\[ l<r \]

三段：

```
[1 ... l]

[l+1 ... r]

[r+1 ... n]
```

前缀和为：

\[ P_i \]

那么三段分别：

\[ A=P_l \]\[ B=P_r-P_l \]\[ C=P_n-P_r \]

所以：

```
第一段好
```

就是：

\[ P_l\ge0 \]

第二段好：

\[ P_r-P_l\ge0 \]

即：

\[ P_l\le P_r \]

第三段好：

\[ P_n-P_r\ge0 \]

即：

\[ P_r\le P_n \]

于是一个：

```
median + 分段
```

问题，最后变成几个普通不等式：

\[ P_l\ge0 \]\[ P_l\le P_r \]\[ P_r\le P_n \]

然后只需要维护前缀最小值。

这就是典型的：

```
复杂定义
    ↓
判定化
    ↓
计数化
    ↓
±1 数值化
    ↓
前缀和化
    ↓
不等式化
```

# 10. 一个非常值得训练的提问顺序

以后碰到类似题目，可以按下面顺序问自己。

> [!question] ① 题目真的需要我算出这个值吗？
> 
> 还是只需要判断：
> 
> ```
> value <= k ?
> value >= k ?
> ```

如果只是判定，就继续降维。

---

> [!question] ② 这个统计量的阈值条件能不能变成计数？
> 
> 比如：
> 
> ```
> median <= k
> ```
> 
> 能否变成：
> 
> ```
> <=k 的元素至少多少个？
> ```

---

> [!question] ③ 元素是不是可以只分成两类？
> 
> 例如：
> 
> ```
> <= k
> > k
> ```
> 
> 如果可以，原始值可能已经没有用了。

---

> [!question] ④ 条件是不是在比较两类元素数量？
> 
> 如果出现：
> 
> ```
> cntA >= cntB
> ```
> 
> 尝试：
> 
> ```
> A -> +1
> B -> -1
> ```

---

> [!question] ⑤ 最终是不是变成区间和条件？
> 
> 如果是：
> 
> ```
> sum(l,r) >= 0
> ```
> 
> 那么继续想到：
> 
> ```
> 前缀和
> ```

# 11. 这套思想不仅能处理 Median

## Majority

判断某种颜色是否占多数：

```
目标颜色 -> +1
其他颜色 -> -1
```

然后看：

\[ sum>0 \]

---

## 两种事件数量比较

例如要求：

```
区间中 A 的数量 >= B 的数量
```

直接：

```
A -> +1
B -> -1
其他 -> 0
```

然后：

\[ sum\ge0 \]

---

## 括号序列

经典：

```
( -> +1
) -> -1
```

前缀和表示括号平衡程度。

它本质上也是：

> 两种相反贡献的数值化。

---

## 投票 / 优势关系

例如：

```
支持方案 A -> +1
支持方案 B -> -1
```

区间和：

```
>0 : A 占优
=0 : 平衡
<0 : B 占优
```

---

## 阈值类子数组问题

例如：

> 某个子数组内至少一半元素 `>= x`

可以：

```
>=x -> +1
<x  -> -1
```

于是变成：

\[ 区间和\ge0 \]

---

# 12. `+1/-1` 并不是固定写法

真正的思想不是一定要写：

```
1
-1
```

而是：

> **为不同类别赋贡献，使原来的数量关系变成一个代数条件。**

例如：

如果条件是：

\[ 2\#A\ge\#B \]

那么可以考虑：

```
A -> +2
B -> -1
```

于是条件直接变成：

\[ sum\ge0 \]

所以更一般地说：

\[ \boxed{ \text{计数约束} \rightarrow \text{贡献赋权} \rightarrow \text{和的约束} } \]

这比单纯记：

```
二分类就 ±1
```

更加泛用。

---

# 13. 更一般的“贡献赋权”

如果条件：

\[ cnt_A\ge cnt_B \]

那么：

```
A : +1
B : -1
```

如果：

\[ cnt_A\ge2cnt_B \]

可以：

```
A : +1
B : -2
```

如果：

\[ 3cnt_A+2cnt_B\ge cnt_C \]

可以尝试：

```
A : +3
B : +2
C : -1
```

最后统一变成：

\[ sum\ge0 \]

这就是：

> **把组合计数关系线性化。**

---

# 14. 为什么这种转化很有价值

原问题：

```
区间内分别统计 A、B
然后比较
```

可能需要维护多个计数。

转化以后：

```
只维护一个 sum
```

于是大量成熟工具都能直接使用：

- 前缀和
- 最小/最大前缀
- 哈希
- 单调结构
- 线段树
- 树状数组
- DP

所以：

> 数值化不仅仅让表达更简单，它还把问题接到了我们熟悉的算法工具上。

# 15. 我这次真正应该记住的东西

> [!summary] 认知一：不要过度计算
> 
> 如果题目只问：
> 
> ```
> median <= k
> ```
> 
> 不需要知道 median 本身。
> 
> 应该寻找：
> 
> ```
> median <= k
> ```
> 
> 与某个更简单条件之间的等价关系。

---

> [!summary] 认知二：阈值可以让数值失去意义
> 
> 如果只关心：
> 
> ```
> a[i] <= k ?
> ```
> 
> 那么原本的具体数值可能全部可以丢掉，只保留：
> 
> ```
> good / bad
> ```

---

> [!summary] 认知三：数量关系可以赋贡献
> 
> 如果条件是：
> 
> ```
> good >= bad
> ```
> 
> 令：
> 
> ```
> good = +1
> bad  = -1
> ```
> 
> 就得到：
> 
> ```
> sum >= 0
> ```

---

> [!summary] 认知四：复杂定义要不断“翻译”
> 
> 一道题的原始描述可能完全不是最终应该处理的形式。
> 
> 例如：
> 
> ```
> median
> ↓
> 数量
> ↓
> ±1
> ↓
> 区间和
> ↓
> 前缀和
> ↓
> 大小关系
> ```
>

# 16. 最值得形成的条件反射

以后看到：

```
median / majority / 至少一半 / 多数 / 阈值
```

先问：

```
能不能只看元素位于阈值哪一侧？
```

如果能：

```
二分类
```

再问：

```
条件是不是两类数量的比较？
```

如果是：

```
赋 ±1
```

再问：

```
是不是变成了区间和条件？
```

如果是：

```
前缀和
```

因此可以形成这一条思维链：

\[ \boxed{ \text{统计量判定} \rightarrow \text{计数条件} \rightarrow \text{贡献编码} \rightarrow \text{区间和} \rightarrow \text{前缀和} } \]

## 17. 一句话总结

> **> **不要执着于计算题目给出的复杂对象本身。****
> 
> 如果最终只需要判断它与某个阈值的关系，就尝试把这个关系翻译成更简单的计数条件。
> 
> 当条件进一步变成“两类元素数量的比较”时，再通过贡献赋权把它压缩成一个数值和。
> 
> 很多看起来需要高级数据结构的问题，会因此退化成最基础的前缀和与不等式。
