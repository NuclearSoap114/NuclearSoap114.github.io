## 树上最小支配集｜子树向父节点传递“未完成要求”

> **存放建议  **
> **等级：** A 类·核心突破题  
> **理由：** 关键突破不是简单记录“当前节点选不选”，而是进一步区分“不选但已经被儿子覆盖”和“不选且等待父亲覆盖”。

<div id="section-2" class="note-anchor"></div>

### 抽象题目

给定一棵 $n$ 个节点的无根树，可以选择若干节点放置塔。

一个塔能够覆盖它所在的节点以及所有相邻节点。要求树中的每个节点都被覆盖，求最少需要选择多少个节点。

---

<div id="section-3" class="note-anchor"></div>

### 一句话本质

处理完一棵子树后，不仅要知道选了多少个节点，还要告诉父节点：

> 当前子树的根是否放塔、是否已经被覆盖，以及是否仍需要父节点提供覆盖。

---

<div id="section-4" class="note-anchor"></div>

### 从朴素思路到关键转折

最直接的方法是枚举每个节点是否放塔，一共有 $2^n$ 种方案，再逐个检查所有节点是否被覆盖。

当 $n=10^4$ 时显然不可行。

树的关键性质是：

- 任选一个节点作为根后，不同儿子子树之间互不相交；
- 儿子子树之间只通过当前节点产生联系；
- 父节点只能直接影响当前节点，不能直接影响更深的后代。

因此，每棵子树不需要向父节点汇报内部具体选了哪些点，只需要汇报根节点当前的状态。

一开始只记录：

```text
u 选 / u 不选
```

仍然不够。

因为 `u` 不选时有两种本质不同的情况：

1. `u` 已经被某个儿子覆盖，不需要父亲帮助；
2. `u` 在子树内没有被覆盖，必须等待父亲放塔。

这两种状态对父节点提出的要求不同，必须拆开。

---

<div id="section-5" class="note-anchor"></div>

### 状态设计

定义：

```text
dp[u][1][1]：u 放塔，u 子树已经合法处理
dp[u][0][1]：u 不放塔，但 u 已经被某个儿子覆盖
dp[u][0][0]：u 不放塔，u 尚未被覆盖，等待父亲覆盖
```

`dp[u][1][0]` 不可能存在，因为只要 `u` 放塔，它就一定能够覆盖自己。

特别注意：

> 在 `dp[u][0][0]` 中，只有节点 `u` 可以暂时未覆盖，u 的所有后代都必须已经被合法覆盖。

为了简化推导，记：

```text
A：u 放塔
B：u 不放塔，但已经被儿子覆盖
C：u 不放塔且未覆盖，等待父亲
```

---

<div id="section-6" class="note-anchor"></div>

### 核心推导

<div id="section-7" class="note-anchor"></div>

#### 1. 初始化当前节点

在还没有合并任何儿子时：

```text
A = 1
B = INF
C = 0
```

原因：

- `A=1`：选择当前节点，需要一座塔；
- `B=INF`：还没有儿子，不可能被儿子覆盖；
- `C=0`：可以暂时不选当前节点，等待父亲覆盖。

对于叶子，这三个值就是它的最终状态。

---

<div id="section-8" class="note-anchor"></div>

#### 2. 合并一个儿子

设当前处理儿子 `v`，它的三种状态为：

```text
A_v = dp[v][1][1]
B_v = dp[v][0][1]
C_v = dp[v][0][0]
```

合并的本质是：

> 根据 `u` 是否放塔，判断儿子的哪些状态能够合法接到当前状态后面。

---

<div id="section-9" class="note-anchor"></div>

#### 3. `u` 放塔

如果 `u` 放塔，儿子的三种状态都可以：

- `v` 自己放塔；
- `v` 不放塔，但已经被自己的儿子覆盖；
- `v` 没被覆盖，等待父亲，而此时 `u` 正好可以覆盖它。

所以：


$$
A'=A+\min(A_v,B_v,C_v)
$$


---

<div id="section-10" class="note-anchor"></div>

#### 4. `u` 不放塔，并且仍未被覆盖

要让 `u` 合并完当前儿子后仍处于 `C`：

- `v` 不能放塔，否则 `v` 会覆盖 `u`；
- `v` 不能处于 `C_v`，因为 `v` 等待父亲 `u` 覆盖，但 `u` 没放塔；
- `v` 只能处于 `B_v`。

所以：


$$
C'=C+B_v
$$


---

<div id="section-11" class="note-anchor"></div>

#### 5. `u` 不放塔，但最终已经被覆盖

要得到状态 `B'`，有两种来源。

<div id="section-12" class="note-anchor"></div>

##### 原来已经被其他儿子覆盖

当前儿子可以选择：

- `A_v`：儿子放塔；
- `B_v`：儿子不放塔但已经覆盖。

不能选择 `C_v`，因为 `u` 没有塔，无法覆盖儿子。

代价为：


$$
B+\min(A_v,B_v)
$$


<div id="section-13" class="note-anchor"></div>

##### 原来还没有被覆盖

那么当前儿子必须放塔，才能第一次覆盖 `u`：


$$
C+A_v
$$


所以：


$$
B'=\min(B+\min(A_v,B_v),C+A_v)
$$


---

<div id="section-14" class="note-anchor"></div>

### 为什么必须使用新状态

合并儿子时，`A'、B'、C'` 都必须由合并前的旧状态推出。

不能先修改 `A`，再用修改后的状态计算其他值，否则当前儿子的贡献可能被使用多次。

正确的阶段关系是：

```cpp
int na = ...;
int nb = ...;
int nc = ...;

a = na;
b = nb;
c = nc;
```

旧状态表示：

> 已经处理完前面的儿子。

新状态表示：

> 在此基础上又处理完当前儿子。

---

<div id="section-15" class="note-anchor"></div>

### 根节点为什么特殊

原树没有指定根，可以任意选择节点 `1` 作为根。

选哪个根只会改变父子关系，不会改变原问题的最优答案。

但是根节点没有父亲，因此不能处于：

```text
不放塔、没有被覆盖、等待父亲
```

所以最终答案只能是：


$$
\min(dp[root][1][1],dp[root][0][1])
$$


不能选择 `dp[root][0][0]`。

---

<div id="section-16" class="note-anchor"></div>

### 为什么正确

<div id="section-17" class="note-anchor"></div>

#### 状态覆盖了全部情况

对于节点 `u`：

- 如果 `u` 放塔，它属于 `A`；
- 如果 `u` 不放塔且已经被儿子覆盖，它属于 `B`；
- 如果 `u` 不放塔且准备由父亲覆盖，它属于 `C`。

不存在其他有效情况，因此没有遗漏。

<div id="section-18" class="note-anchor"></div>

#### 转移只保留合法组合

父子之间的覆盖关系只有三种可能：

- 父亲放塔，可以覆盖儿子；
- 儿子放塔，可以覆盖父亲；
- 父子都不放塔时，双方不能互相补救。

每个转移都严格按照这些关系筛选儿子状态，因此不会产生非法方案。

<div id="section-19" class="note-anchor"></div>

#### 局部信息足够

父节点只能直接覆盖 `u`，不能越过 `u` 覆盖更深的后代。

所以在一棵子树处理结束时，所有后代必须已经完全合法，最多只允许子树根 `u` 等待父亲覆盖。

因此三个状态已经包含了父节点后续决策所需的全部信息。

---

<div id="section-20" class="note-anchor"></div>

### 复杂度

DFS 遍历整棵树，每条边只作为父子边处理一次。

合并一个儿子只进行常数次计算，因此：

- 时间复杂度：$O(n)$；
- 空间复杂度：$O(n)$，用于邻接表、DP 数组和递归栈。

相比枚举所有 $2^n$ 种选择，树形 DP 利用子树独立性，把每棵子树压缩成三个状态。

---

<div id="section-21" class="note-anchor"></div>

### 识别信号

遇到以下结构时，可以考虑类似状态：

- 需要让每个节点被自己或相邻节点满足；
- 父节点的选择能够补救当前节点；
- 当前节点“不选”时存在不同的完成程度；
- 子树处理完后，仍可能给父节点留下一个未完成要求；
- 不同儿子子树彼此独立，只通过父节点发生联系；
- 根节点不能保留“等待父亲处理”的状态。

设计状态时应主动询问：

> 当前子树处理完成后，父节点还需要知道什么？

---

<div id="section-22" class="note-anchor"></div>

### 适用边界

<div id="section-23" class="note-anchor"></div>

#### 每个节点建塔费用不同

如果在节点 `u` 建塔的费用为 $w_u$，只需要把初始化：


$$
A=1
$$


改为：


$$
A=w_u
$$


其余状态结构不变。

<div id="section-24" class="note-anchor"></div>

#### 塔能覆盖距离不超过 2 的节点

原状态不再足够。

因为祖父节点可能跨过父节点覆盖当前节点，需要记录当前节点距离最近的塔有多远，或者还需要上方多少距离的帮助。

<div id="section-25" class="note-anchor"></div>

#### 图不是树

一般图中存在环，不同“子树”之间可能通过其他边再次相连，无法独立合并，因此不能直接使用这套树形 DP。

<div id="section-26" class="note-anchor"></div>

#### 树退化成链

状态和转移仍然成立。

此时每个节点最多只有一个儿子，“合并多个儿子”退化成普通的线性状态转移。

---

<div id="section-27" class="note-anchor"></div>

### 本题暴露的问题

<div id="section-28" class="note-anchor"></div>

#### 1. 需要区分不同的“覆盖问题”

之前讨论过：

- 最小点覆盖：覆盖所有边；
- 最小路径覆盖：用路径覆盖所有点；
- 本题最小支配集：让每个点被自己或相邻点覆盖。

它们都包含“覆盖”二字，但研究对象不同，不能只凭名称套同一种算法。

<div id="section-29" class="note-anchor"></div>

#### 2. 状态不能只描述当前选择

已经想到：

```text
dp[u][选不选][有没有覆盖]
```

方向正确。

更关键的是理解：

> 状态不仅要描述子树内部发生了什么，还要描述这棵子树给父节点留下了什么要求。

`dp[u][0][0]` 本质上是在向父节点传递：

```text
我的后代已经处理完，但我自己还需要你覆盖。
```

<div id="section-30" class="note-anchor"></div>

#### 3. 特殊边界应该从状态含义推出

根节点不能选择 `dp[root][0][0]`，不是额外规定，而是因为根没有父亲，无法兑现“等待父亲覆盖”的要求。

---

<div id="section-31" class="note-anchor"></div>

### 实现时最容易错的地方

1. 无向树 DFS 时必须跳过父节点：

```cpp
if(v == fa)continue;
```

2. 合并儿子必须使用 `na、nb、nc`，不能原地更新。

3. `dp[u][0][0]` 中只能允许 `u` 未覆盖，不能让更深的节点也处于未覆盖状态。

4. 根节点最终不能取 `dp[root][0][0]`。

5. 题目只有一组数据，没有测试组数 `T`。

6. 当 $n=1$ 时，根没有儿子，答案为 `1`，不能输出等待父亲覆盖的状态。

---

<div id="section-32" class="note-anchor"></div>

### 复习时反问

1. 为什么只记录“当前节点选不选”不足以完成这道题？
2. 当 `u` 不放塔且仍未覆盖时，为什么儿子只能取 `B_v`，不能取 `A_v` 或 `C_v`？
3. 为什么父节点只需要知道当前节点的三个状态，不需要知道子树内部具体选择了哪些节点？
4. 如果塔能够覆盖距离不超过 $2$ 的节点，原状态缺少了什么信息？

---

<div id="section-33" class="note-anchor"></div>

### 完整代码

```cpp
#include <bits/stdc++.h>
using namespace std;
#define int long long
#define rep(i,l,r) for(int i=(l);i<=(r);i++)
const int inf = 1e18,N = 1e4 + 10;
int n;
int dp[N][2][2];
vector<int> G[N];

void dfs(int u,int fa){
    int a = 1;
    int b = inf;
    int c = 0;
    for(int v:G[u]){
        if(v == fa)continue;
        dfs(v,u);
        int va = dp[v][1][1];
        int vb = dp[v][0][1];
        int vc = dp[v][0][0];
        int na = a + min({va,vb,vc});
        int nb = min(b + min(va,vb),c + va);
        int nc = c + vb;
        a = na;
        b = nb;
        c = nc;
    }
    dp[u][1][1] = a;
    dp[u][0][1] = b;
    dp[u][0][0] = c;
    dp[u][1][0] = inf;
}

signed main(){
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    cin >> n;
    rep(i,1,n - 1){
        int u,v;
        cin >> u >> v;
        G[u].push_back(v);
        G[v].push_back(u);
    }
    dfs(1,0);
    cout << min(dp[1][1][1],dp[1][0][1]) << '\n';
    return 0;
}
```
