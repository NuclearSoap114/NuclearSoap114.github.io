## 二叉苹果树｜树形背包的 Pull 转移

> **存放建议  **
> **等级：** A 类·核心突破题  
> **理由：** 本题的关键增量是从“保留部分必须与根连通”推出“边数要在不同儿子子树之间分配”，并理解了树形背包的 Pull 转移。

<div id="section-2" class="note-anchor"></div>

### 抽象题目

给定一棵以节点 `1` 为根的带权树，每条边有一个非负权值。

要求保留恰好 $Q$ 条边，且保留下来的边仍然与根连通，求最大边权和。

---

<div id="section-3" class="note-anchor"></div>

### 一句话本质

每个儿子子树都提供一组“分配若干条边可以获得多少价值”的选择，当前节点要把有限的边数分配给各个儿子，因此需要逐个合并子树背包。

---

<div id="section-4" class="note-anchor"></div>

### 从朴素思路到关键转折

<div id="section-5" class="note-anchor"></div>

#### 错误的叶子贪心

最初考虑维护所有叶子边，每次删除权值最小的叶子边。

这个方法的问题是：

- 当前能删除的只有叶子边，不是所有边；
- 一条边是否成为叶子，取决于其下方子树是否已经删完；
- 边之间存在祖先依赖，不能独立按照权值比较。

但“贪心存在反例”只能证明贪心错误，不能直接推出树形背包。

<div id="section-6" class="note-anchor"></div>

#### 真正的推导起点

若保留一条较深的边，它到根路径上的所有边都必须保留，否则它会与根断开。

所以最终保留的部分一定是：

> 一棵包含根节点、拥有 $Q$ 条边的连通子树。

固定节点 `u` 后，保留的边只能分布在它的各个儿子子树中。不同儿子子树互不相交，只通过 `u` 联系，因此可以分别求最优，再分配总边数。

---

<div id="section-7" class="note-anchor"></div>

### 状态设计

为了配合简洁的零初始化代码，更准确地定义：


$$
dp[u][j]
$$


表示：

> 在 `u` 的子树中，保留**至多** $j$ 条边，并保证保留部分与 `u` 连通时，能够获得的最大价值。

为什么可以使用“至多”而不是“恰好”？

因为本题所有边权都非负。在 $Q$ 可行的前提下，一个不足 $Q$ 条边的含根连通子树可以继续向外添加边，直到恰好 $Q$ 条，价值不会减少。

因此：


$$
\text{至多 }Q\text{ 条的最大价值}=\text{恰好 }Q\text{ 条的最大价值}
$$


这也是全局 `dp` 数组直接初始化为 `0` 仍然能够成立的原因。

---

<div id="section-8" class="note-anchor"></div>

### 核心推导

<div id="section-9" class="note-anchor"></div>

#### 1. 先计算儿子

处理节点 `u` 的儿子 `v` 前，必须先执行：

```cpp
dfs(v,u);
```

这样才能得到：

```text
dp[v][0],dp[v][1],...,dp[v][q]
```

它们表示给 `v` 子树不同边数容量时，分别能够取得的最大价值。

---

<div id="section-10" class="note-anchor"></div>

#### 2. 把一个儿子看成一组选择

设 `v` 是 `u` 的儿子，连接边 `u-v` 的权值为 `w`。

若决定进入 `v` 分支，那么必须选择连接边 `u-v`。

假设在 `v` 子树内部最多使用 $x$ 条边，则整个分支：

- 消耗 $x+1$ 条边；
- 获得 $dp[v][x]+w$ 的价值。

所以一个儿子并不是一个固定物品，而是一组选择：

```text
不选择该分支：消耗 0，收益 0

选择该分支：
消耗 x+1 条边
收益 dp[v][x]+w
```

---

<div id="section-11" class="note-anchor"></div>

#### 3. Pull 转移

当前正在把儿子 `v` 合并到 `u`。

固定合并后的目标状态：

```text
dp[u][j]
```

表示合并后总容量为 $j$。

枚举之前已经处理的儿子使用容量 $k$，那么当前 `v` 子树内部还能使用：


$$
j-k-1
$$


其中减去的 `1` 是连接边 `u-v`。

于是：


$$
dp[u][j]=\max\left(dp[u][j],dp[u][k]+dp[v][j-k-1]+w\right)
$$


代码为：

```cpp
for(int j=q;j>=1;j--){
    for(int k=0;k<j;k++){
        dp[u][j] = max(dp[u][j],dp[u][k] + dp[v][j - k - 1] + w);
    }
}
```

各变量含义：

```text
j：合并当前儿子后的总容量
k：之前处理过的儿子使用的容量
j-k-1：v 子树内部使用的容量
1：连接边 u-v
w：连接边的权值
```

容量关系为：


$$
k+(j-k-1)+1=j
$$


---

<div id="section-12" class="note-anchor"></div>

#### 4. 为什么 `j` 必须倒序

转移右侧会读取：

```cpp
dp[u][k]
```

并且始终有：


$$
k<j
$$


如果 `j` 正序，较小的 `dp[u][k]` 可能已经在本轮加入了当前儿子 `v`，再用它转移就会重复选择同一个儿子。

倒序时，较小下标还没有被当前儿子更新，所以它仍然只包含此前处理过的儿子。

这和 01 背包倒序枚举容量的原因相同。

---

<div id="section-13" class="note-anchor"></div>

### 为什么正确

对任意一个以 `u` 为根的合法方案，考虑当前儿子 `v`：

- 要么完全不选择 `v` 分支，此时原来的 `dp[u][j]` 保持不变；
- 要么选择连接边 `u-v`，并在 `v` 子树中选择一部分与 `v` 连通的边。

第二种情况中，总容量一定能唯一拆成：

```text
之前儿子的容量 k
+
v 子树内部容量 j-k-1
+
连接边 1
```

转移枚举了所有 $0\le k<j$，因此没有遗漏任何分配方式。

固定容量分配后，不同儿子子树之间互不影响。若某个子树没有采用对应容量下的最优方案，可以直接替换为其 `dp` 最优值，使总容量不变、总价值不减。

因此每个儿子可以独立取最优，再逐个合并。

---

<div id="section-14" class="note-anchor"></div>

### 为什么不依赖二叉树

这份代码并不要求每个节点只有两个儿子。

```cpp
for(auto [v,w]:G[u])
```

会依次把 `u` 的所有儿子合并进 `dp[u]`。

所以：

- 二叉树：每个节点最多合并两个儿子；
- 普通树：每个节点合并更多儿子；
- 转移和状态完全不变。

二叉树只是让题目结构更直观，并不是算法成立的必要条件。

---

<div id="section-15" class="note-anchor"></div>

### 复杂度

每条父子边都会进行一次背包合并。

一次合并枚举：

- 目标容量 $j$；
- 之前儿子的容量 $k$。

所以：

- 时间复杂度：$O(NQ^2)$；
- 空间复杂度：$O(NQ+N)$。

相比枚举所有边的选择方案，DP 将每棵子树压缩成一张长度为 $Q$ 的“容量—最优价值表”。

---

<div id="section-16" class="note-anchor"></div>

### 识别信号

看到以下结构时，可以考虑树形背包：

- 要在树上选择固定数量或有限数量的边、点；
- 选择深层对象时必须同时选择通向根的路径；
- 最终方案必须与根或当前节点连通；
- 不同儿子子树彼此独立；
- 总数量需要在多个儿子子树之间分配；
- 子树可以概括成“给它 $k$ 个名额时的最优价值”。

核心问题是：

> 当前节点拥有 $j$ 个名额，应该怎样分配给各个儿子？

---

<div id="section-17" class="note-anchor"></div>

### 适用边界

<div id="section-18" class="note-anchor"></div>

#### 边权可能为负数

当前零初始化写法会失效。

因为“至多 $Q$ 条”和“恰好 $Q$ 条”的答案不再相同，继续添加负权边会让价值下降。

此时必须：

- 把不可达状态初始化为 `-inf`；
- 精确维护“恰好选择多少条边”。

<div id="section-19" class="note-anchor"></div>

#### 保留部分不要求与根连通

当前状态无法表示多个互不连通的保留部分，需要重新设计状态。

<div id="section-20" class="note-anchor"></div>

#### 原图存在环

不同子树不再独立，不能直接使用树形背包合并。

<div id="section-21" class="note-anchor"></div>

#### 统计节点数量

仍然可以使用类似思想，但容量的计算方式要从“连接边加一”改成相应的节点计数。

---

<div id="section-22" class="note-anchor"></div>

### 本题暴露的问题

<div id="section-23" class="note-anchor"></div>

#### 1. 贪心失败不是算法来源

最小叶子堆存在反例，只能说明贪心错误。

真正推出树形背包的逻辑是：

```text
保留部分必须与根连通
→ 深层边依赖祖先边
→ 总边数分配给不同儿子子树
→ 每棵子树汇报容量—价值表
→ 树形背包
```

<div id="section-24" class="note-anchor"></div>

#### 2. 最初的递归参数不适合状态复用

最初尝试使用：

```text
dfs(u,have)
```

并对 `have=0、1、2` 分情况。

但父节点需要的是儿子在所有容量下的答案，而不是某一个 `have`。因此一次 `dfs(u)` 应该把整张 `dp[u][0...q]` 算完。

<div id="section-25" class="note-anchor"></div>

#### 3. 转移必须同时考虑多个儿子

不能只比较：

```text
只选择左子树
只选择右子树
```

还要枚举总边数如何在不同儿子之间分配。

<div id="section-26" class="note-anchor"></div>

#### 4. 实现不应脱离题目条件过度复杂化

本题边权非负、规模很小，可以直接使用简洁的倒序 Pull 转移。

`sz`、`ndp`、大量不可达判断可以用于更通用的版本，但不是这道题最清晰的实现。

---

<div id="section-27" class="note-anchor"></div>

### 实现时最容易错的地方

1. 输入边没有规定父子方向，必须双向存边。

2. DFS 中必须跳过父节点：

```cpp
if(v == fa)continue;
```

3. `j-k-1` 中的 `1` 表示连接边 `u-v`，不能遗漏。

4. 外层容量 `j` 必须倒序，否则可能重复合并当前儿子。

5. 最终输出的是根节点的：

```cpp
dp[1][q]
```

6. 这份零初始化代码依赖边权非负；若允许负权，必须改成精确状态与 `-inf` 初始化。

---

<div id="section-28" class="note-anchor"></div>

### 复习时反问

1. 为什么保留一条深层边时，它到根路径上的边也必须全部保留？
2. 转移中的 `j-k-1` 分别减去了什么，为什么不是 `j-k`？
3. 为什么 `j` 倒序能够保证当前儿子只被合并一次？
4. 如果边权可能为负数，为什么这份零初始化代码不再能够表示“恰好保留 $Q$ 条边”？

---

<div id="section-29" class="note-anchor"></div>

### 完整代码

```cpp
#include <bits/stdc++.h>
using namespace std;
#define int long long
#define rep(i,l,r) for(int i=(l);i<=(r);i++)
const int inf = 1e18,N = 110;
int n,q;
int dp[N][N];
vector<pair<int,int>> G[N];

// dp[u][j]：u 子树中至多保留 j 条边，且与 u 连通时的最大价值
void dfs(int u,int fa){
    for(auto [v,w]:G[u]){
        if(v == fa)continue;
        dfs(v,u);

        // 固定合并后的容量 j，枚举之前的儿子使用了 k 条边
        for(int j=q;j>=1;j--){
            for(int k=0;k<j;k++){
                dp[u][j] = max(dp[u][j],dp[u][k] + dp[v][j - k - 1] + w);
            }
        }
    }
}

void O_o(){
    cin >> n >> q;
    rep(i,1,n - 1){
        int u,v,w;
        cin >> u >> v >> w;
        G[u].push_back({v,w});
        G[v].push_back({u,w});
    }

    dfs(1,0);

    cout << dp[1][q] << '\n';
}

signed main(){
    ios::sync_with_stdio(false);
    cin.tie(nullptr);
    O_o();
    return 0;
}
```
